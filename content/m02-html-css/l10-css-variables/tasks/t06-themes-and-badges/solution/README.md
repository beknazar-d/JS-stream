# Разбор

**Шаг 1. Компоненты читают токены.** В `.card`, `.button` и `.badge` значения заменены на `var()`. Светлая тема при этом не меняется: проверка, что рефакторинг ничего не сломал.

**Шаг 2. Темы.** `[data-theme="dark"]` и `[data-theme="sale"]` задают те же семь переменных. Компоненты их не знают: переключается только значение, и весь сайт перекрашивается.

Для sale цвета подбирались по контрасту:

- светло-розовый текст `#fff1f0` на тёмно-красном `#2b0a0a` читается;
- тёмный `#2b0a0a` на ярко-красной кнопке `#ff4d4f` читается;
- тёмный текст на жёлтом акценте `#ffd666` тоже.

**Шаг 3. Плашка.** `.badge` читает `--badge-bg` и запасное значение `var(--color-accent)`. Пока `--badge-bg` не задана, плашка следует теме. `.badge--hot` задаёт `--badge-bg` у себя: значение не зависит от темы и действует только на эту плашку. Тот же приём превращает любой компонент в настраиваемый: «если нужно, переопредели переменную, иначе возьми значение темы».

Почему `.badge--hot` не пишет `background` напрямую: тогда у плашки нет единого места для изменения, а другие варианты (`.badge--new`, `.badge--sale`) пришлось бы тоже перекрашивать свойствами. С переменной достаточно одной строки.
