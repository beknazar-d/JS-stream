## Зачем это в работе

Тикет от маркетинга «Домотеки»: «Фирменный зелёный меняется, нужно перекрасить весь сайт до пятницы». Разработчик ищет `#0b6e4f` по проекту и находит сорок мест. В трёх местах цвет записан чуть иначе, и они остаются зелёными по-старому.

Второй тикет: «Хотим тёмную тему». Если цвета разбросаны по сотне правил, это значит переписать сотню правил.

Переменные CSS решают обе задачи. Значение записывается один раз, а использовать его можно везде. Поменяли в одном месте, поменялось везде.

## Объяснение

Переменная CSS (по-английски custom property, «пользовательское свойство») — это значение, которому вы дали имя. Имя начинается с двух дефисов.

Представьте табличку с ценой на витрине. Вместо того чтобы писать цену на каждом ценнике, вы пишете «цена по табличке». Сменили табличку, и все ценники изменились.

Две операции.

1. **Объявление.** Пишется как обычное свойство, только с именем из двух дефисов.
2. **Использование.** Функция `var(--имя)` подставляет значение.

```css
:root {
  --color-brand: #0b6e4f;
  --space-md: 16px;
}

.button {
  background: var(--color-brand);
  padding: 8px var(--space-md);
}
```

Селектор `:root` — это корневой элемент `html`. Переменная, объявленная на нём, доступна на всей странице, потому что переменные наследуются от родителя к детям. Если объявить переменную на `.card`, её увидят карточка и всё внутри неё, но не соседи.

У `var()` есть второй аргумент: запасное значение (fallback). Оно используется, когда переменной нигде нет:

```css
.badge {
  color: var(--badge-color, #b42318);
}
```

Набор переменных с общей ролью называют дизайн-токенами (design tokens): цвета, отступы, размеры шрифта, радиусы. Токен называют по роли (`--color-surface`, `--color-brand`), а не по цвету (`--color-white`). Тогда при смене темы имя не теряет смысла.

Запустите модель поиска значения. Поменяйте, где объявлена `--color-brand`, и посмотрите, кто что увидит.

<Playground example="var-lookup" />

Теперь тот же приём для темы. Переменные одни и те же, значения разные:

```css
:root {
  --color-bg: #f7f8fa;
  --color-text: #1d2733;
}

[data-theme="dark"] {
  --color-bg: #12161c;
  --color-text: #e8edf2;
}

body {
  background: var(--color-bg);
  color: var(--color-text);
}
```

Правила `body` ничего не знают про темы. Достаточно поставить на `html` атрибут `data-theme="dark"`, и значения подменятся. Селектор `[data-theme="dark"]` перебивает `:root`: они одинаково весят как класс, но тёмный блок стоит ниже в файле.

Сравните два подхода.

<Wrong>

```css
.button   { background: #0b6e4f; }

.link:hover { color: #0b6e4f; }
```

</Wrong>

<Right>

```css
:root     { --color-brand: #0b6e4f; }
.button   { background: var(--color-brand); }
.header   { background: var(--color-brand); }

```

</Right>

## Как это работает

<Figure src="variable-tree.svg" alt="Дерево элементов. Вверху html с переменной color-brand зелёного цвета. Под ним секция promo, где color-brand переопределена в красный, и в ней кнопка, которая получает красный. Рядом подвал footer без своих переменных, он получает зелёный от html. Стрелки идут только сверху вниз." caption="Переменная идёт от родителя к детям. Ближайшее объявление побеждает. Соседи друг друга не видят." />

Правила, которые стоит помнить.

1. **Ближайшее объявление побеждает.** Кнопка в акции возьмёт красный из `section.promo`, а кнопка в подвале зелёный из `:root`. Так делают локальные варианты компонента: переопределили переменную у одного блока, не трогая остальные.
2. **Тема системы.** Операционная система может быть в тёмном режиме. Браузер сообщает об этом условием `prefers-color-scheme: dark`. Но выбор человека (кнопка на сайте) важнее настройки системы. Поэтому условие подключают так, чтобы оно не перебивало явный выбор:

```css
@media (prefers-color-scheme: dark) {
  :root:not([data-theme]) {
    --color-bg: #12161c;
    --color-text: #e8edf2;
  }
}
```

Часть `:not([data-theme])` читается: «только если атрибута `data-theme` нет».

3. **Контраст нужно считать.** Цвета тёмной темы подбирают так, чтобы текст читался. Минимум для обычного текста по стандарту доступности WCAG AA — 4,5 к 1. Запустите расчёт и увидите, что белый на светло-зелёном (1,8) не годится, а тёмный на нём (8,9) годится.

<Playground example="contrast" />

4. **Переменные нельзя использовать в условии медиазапроса.** `@media (min-width: var(--bp))` не работает. Контрольные точки пишут значением.

<Note>

Переменная, значение которой недействительно, не ломает страницу громко. Свойство просто сбрасывается: наследуемое (как `color`) берёт значение родителя, остальные (как `margin`) становятся начальными. Поэтому после рефакторинга сверяйте страницу глазами и в DevTools.

</Note>

## Типичные ошибки

У CSS нет консоли ошибок для таких случаев: браузер молча сбрасывает свойство. Результаты ниже получены запуском в Chromium.

**1. Единица после `var()`.** Подстановка — текстовая. `var(--gap)px` превращается в `16pxpx`, это недействительное значение, и отступ получился `0px`.

<Wrong>

```css
:root { --gap: 16px; }
.card { margin-bottom: var(--gap)px; }
```

</Wrong>

<Right>

```css
:root { --gap: 16px; }
.card { margin-bottom: var(--gap); }
```

</Right>

Если число хранится без единицы, умножайте на единицу: `calc(var(--n) * 1px)`. Значение `calc(var(--gap) * 2)` при `--gap: 16px` дало `32px`.

**2. Опечатка в имени.** Имени `--colour-x` не существует, значение недействительно, и `color` взял цвет родителя: `rgb(29, 39, 51)`, а не тот, что задумывали. Консоль молчит.

<Wrong>

```css
.price { color: var(--color-acent); }
```

</Wrong>

<Right>

```css
.price { color: var(--color-accent); }
```

</Right>

**3. Переменная объявлена слишком низко.** Подвал вне секции каталога не видит переменные, объявленные на секции. Общие значения объявляйте на `:root`.

<Wrong>

```css
.catalog-section { --gap: 16px; }
.site-footer { padding: var(--gap); }
```

</Wrong>

<Right>

```css
:root { --gap: 16px; }
.site-footer { padding: var(--gap); }
```

</Right>

**4. Переменная в медиазапросе.** Chromium оставил `display: none`, правило внутри `@media (min-width: var(--bp))` не применилось даже на экране 1024 px.

<Wrong>

```css
:root { --bp: 768px; }
@media (min-width: var(--bp)) { .menu { display: block; } }
```

</Wrong>

<Right>

```css
@media (min-width: 768px) { .menu { display: block; } }
```

</Right>

**5. Запасное значение с запятыми.** Всё после первой запятой — запасное значение целиком. `var(--missing, Arial, sans-serif)` в Chromium дало `Arial, sans-serif`. Это не ошибка, а удобство: запасным может быть список шрифтов.

## Итог

Что вы теперь умеете:

- объявлять переменные на `:root` и подставлять их через `var()`;
- задавать запасное значение и объяснять, когда оно срабатывает;
- понимать, откуда элемент берёт значение переменной;
- собирать дизайн-токены и делать тёмную тему блоком переопределений;
- уважать и настройку системы, и явный выбор человека;
- проверять контраст расчётом.

Переменные удобно сочетать с анимацией: например, плавно менять цвет при наведении. В следующем уроке мы научимся делать переходы и анимации так, чтобы они не тормозили страницу и не мешали тем, кому от движения плохо.
