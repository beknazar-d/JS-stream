# Разбор

**1. Меню обрывается.** `height: 100%` считается от высоты родителя, а у `.layout` она `auto`: процент превращается в `auto`, и меню равно высоте контента. Решение: убрать лишний процент и дать родителю `min-height: 100vh`. Меню как flex-элемент растянется на всю высоту ряда, а `min-height` (а не `height`) позволит странице расти при длинном контенте.

**2. Заголовок прилип.** У `.summary` нет ни рамки, ни padding, поэтому `margin-top` первого ребёнка схлопнулся с верхним краем родителя и ушёл наружу: блок сдвинулся вниз, а заголовок остался вплотную к его верху. `display: flow-root` создаёт отдельный контекст форматирования, и отступ остаётся внутри.

**3. Прокрутка вбок.** `.content` — гибкий элемент (`flex: 1`), его минимальная ширина равна самому длинному слову, то есть длинной ссылке. Решение из двух частей: `min-width: 0` у `.content` и `overflow-wrap: anywhere` у комментария.

**4. Активный пункт серый.** Правило `#nav a` весит `1,0,1`, а `.sidebar a.active` только `0,2,1`: идентификатор побеждает. Вместо `!important` понизили вес базового правила: `.sidebar a` (`0,1,1`). Теперь `.sidebar a.active` (`0,2,1`) побеждает честно.

Общий урок: каждая жалоба — одна из шести ловушек. Когда стиль «не работает», сначала смотрите в DevTools, какое правило победило и какой блок что считает.
