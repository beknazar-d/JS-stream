## Зачем это в работе

Тикет от менеджера «Домотеки»: «Заявки на установку кондиционера приходят мусором. В индексе четыре цифры, в количестве «пять», дата «когда-нибудь», а один покупатель вообще не понял, какое поле что значит, потому что подсказки в полях пропали, как только он начал печатать».

Все эти проблемы решает не JavaScript, а правильная разметка формы. Браузер умеет проверять почту, число и дату. Он умеет предлагать сохранённый адрес и показывать нужную клавиатуру. Но только если мы объяснили ему, что за поле перед ним.

Форма (form) — единственное место, где сайт получает данные от человека. Ошибка в разметке формы стоит магазину заказов.

## Объяснение

Форма состоит из четырёх видов частей:

- `form` — контейнер. У него есть `action` (куда отправить) и `method` (как: `post` или `get`).
- `label` — подпись поля. Видимый текст, который связан с полем.
- поля: `input`, `select`, `textarea`.
- `button` — кнопка. С типом `submit` она отправляет форму.

Представьте бумажный бланк на почте. У каждой клетки есть заголовок: «Фамилия», «Индекс». Если заголовок стёрся, клетку заполнят как попало. `label` — это постоянный заголовок клетки. `placeholder` — карандашная надпись внутри клетки: она стирается, как только начинаешь писать.

Тип поля (`type`) говорит браузеру, что внутри:

- `text` — обычный текст;
- `email` — почта: браузер проверяет, что есть `@`;
- `tel` — телефон: на смартфоне откроется цифровая клавиатура;
- `number` — число: можно задать границы `min` и `max`;
- `date` — дата: браузер покажет календарь;
- `checkbox` и `radio` — флажок и переключатель.

Отдельные теги: `select` с вложенными `option` — выпадающий список, `textarea` — многострочный текст.

Группы связанных полей оборачивают в `fieldset`, а название группы кладут в первый вложенный тег `legend`. Например: «Контакты», «Доставка», «Оплата».

Пара атрибутов `name` и `value` нужна для отправки: имя поля уходит на сервер вместе со значением. Поле без `name` не отправляется.

## Пример

Форма подписки на акции из «Домотеки». Сначала плохая.

<Wrong>

```html
<form>
  <input type="text" placeholder="Ваш email">
  <div class="btn">Подписаться</div>
</form>
```

</Wrong>

Здесь у поля нет подписи и имени, формат почты не проверяется, а «кнопка» — это `div`, она ничего не отправит.

Правильный вариант.

<Right>

```html
<form action="/subscribe" method="post">
  <label for="email">Ваш email</label>
  <input id="email" name="email" type="email" required autocomplete="email">
  <button type="submit">Подписаться</button>
</form>
```

</Right>

Что изменилось:

- `label for="email"` и `input id="email"` связаны одинаковым значением;
- `type="email"` включает проверку формата;
- `required` не даёт отправить пустое поле;
- `autocomplete="email"` позволяет браузеру подставить сохранённый адрес.

А теперь посмотрите, какого типа данные приходят из такой формы в JavaScript. Запустите пример и поменяйте `"3"` на `"abc"`.

## Как это работает

Главное в форме — связь между подписью и полем. Она держится на двух одинаковых значениях.

<Figure src="label-for-id.svg" alt="Схема: слева блок «label for равно email» с текстом «Ваш email», справа блок «input id равно email», между ними стрелка. Внизу два следствия: клик по подписи ставит курсор в поле, скринридер читает «Ваш email, поле ввода»." caption="Значение for у label совпадает с id у поля. Это связывает подпись с полем." />

Теперь правила.

**1. У каждого поля есть `label`.** Либо `for` и `id`, либо подпись оборачивает поле: `label` с вложенным `input`. `placeholder` не заменяет подпись. Он исчезает при вводе, у него обычно слабый контраст, и скринридеры не всегда его читают.

**2. Тип выбирают по данным.** Тип нужен не для красоты. Он включает проверку и подходящую клавиатуру.

<Playground example="input-types" />

**3. Проверку делает браузер.** Атрибуты задают правила:

- `required` — нельзя оставить пустым;
- `min` и `max` — границы для чисел и дат;
- `maxlength` — предел длины текста;
- `pattern` — шаблон, например `[0-9]{6}` для индекса из шести цифр.

Если правило нарушено, браузер не отправит форму и покажет подсказку. Запустите пример: он повторяет логику проверки числа.

<Playground example="check-field" />

В реальном браузере проверку можно запросить из JavaScript: у формы есть метод `checkValidity()`, он возвращает `true` или `false`. Это нам пригодится в модуле 3.

**4. Выбор из нескольких.** Для группы радиокнопок у всех один `name`, у каждой свой `value`. Группу оборачивают в `fieldset`, а вопрос кладут в `legend`. В выпадающем списке (`select`) первый `option` с пустым значением работает как подсказка: вместе с `required` он не даёт отправить форму, пока человек не выберет настоящий пункт.

**5. Автозаполнение.** Атрибут `autocomplete` подсказывает браузеру, что подставить: `name`, `email`, `tel`, `street-address`, `postal-code`. Заполнение формы доставки занимает одно касание.

<Note>

Проверка в браузере защищает от случайных ошибок, а не от злонамеренных. Человек может отправить запрос в обход формы. Поэтому сервер всё равно проверяет данные сам. Это тема модуля 7.

</Note>

## Типичные ошибки

Как и в прошлом уроке, браузер молчит о неправильной разметке. Поэтому проверяем в консоли. Результаты ниже получены в Chromium.

**1. Подпись не связана с полем.** В `label for` написан один идентификатор, в `input id` другой.

<Wrong>

```html
<label for="user-name">Имя</label>
<input id="name" name="name">
```

```js
console.log(document.querySelector("#name").labels.length);
```

```text
0
```

</Wrong>

Ноль подписей у поля. Клик по слову «Имя» ничего не делает.

<Right>

```html
<label for="name">Имя</label>
<input id="name" name="name">
```

```js
console.log(document.querySelector("#name").labels.length);
```

```text
1
```

</Right>

**2. Опечатка в типе.** Браузер не ругается, он молча считает поле текстовым.

```js
const field = document.createElement("input");
field.type = "emial";
console.log(field.type);
```

```text
text
```

Проверка почты не работает, а ошибка нигде не показана. Если проверка «не включается», сначала проверьте написание `type`.

**3. Число из поля — строка.** Даже у поля с типом `number` значение в JavaScript приходит строкой.

```js
const units = document.querySelector("#units");
units.value = "12";
console.log(typeof units.value);
```

```text
string
```

Складывать нужно после `Number(units.value)`, как в уроке 1.1.

**4. Поле без `name` не отправляется.** Поле видно на странице, а на сервер не доходит.

<Wrong>

```html
<form id="order">
  <input name="email" value="anna@example.ru">
  <input value="забытое поле">
</form>
```

</Wrong>

```js
console.log([...new FormData(document.querySelector("#order"))]);
```

```text
[ [ 'email', 'anna@example.ru' ] ]
```

В данных только `email`. Второе поле потерялось, ошибки нет.

**5. Пустая подсказка в списке без `required`.** Если у `select` нет `required`, пользователь может отправить форму с пустым значением. Тогда на сервер уйдёт пустая строка.

```js
const city = document.querySelector("select[name=city]");
console.log(JSON.stringify(city.value));
```

```text
""
```

Добавьте `required`, и браузер сам не пропустит форму.

**6. Сообщение браузера на другом языке.** Если поле обязательное, а оно пустое, браузер показывает свою подсказку, например «Please fill out this field.». Язык сообщения зависит от языка браузера, а не от `lang` на странице. Менять текст сообщения можно только скриптом, и это тема урока 3.5.

## Итог

Что вы теперь умеете:

- связывать `label` с полем через `for` и `id`;
- выбирать тип поля по данным: `email`, `tel`, `number`, `date`;
- ограничивать ввод атрибутами `required`, `min`, `max`, `pattern`, `maxlength`;
- группировать поля через `fieldset` и `legend`;
- объяснять, почему `placeholder` не заменяет подпись.

Теперь у нас есть и разметка страниц, и формы. Но выглядят они пока как в браузере по умолчанию. В следующем уроке мы начнём стилизовать: научимся выбирать элементы селекторами и разберёмся, какое правило CSS победит, когда их несколько.
