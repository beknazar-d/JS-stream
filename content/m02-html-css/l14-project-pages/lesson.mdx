## Зачем это в работе

Пришёл большой тикет: «Домотеке нужны три страницы. Карточка товара, оформление заказа и панель менеджера. Макеты приложены, срок две недели». Это уже не упражнение на одно свойство. Здесь нужно собрать всё, чему вы научились в модуле: семантику, Grid и Flexbox, адаптив, доступность и аккуратные стили.

В середине работы приходит сообщение: «Часть товаров закончилась, нужно показывать надпись «нет в наличии»». Страница уже готова, и её нельзя сломать. Так бывает почти в каждом проекте. Требования меняются, а умение вносить изменение, не ломая сделанное, ценится не меньше, чем умение сверстать с нуля.

В этом проекте шесть этапов. Каждый строится на предыдущем, а у каждого есть макет и проверки. Последний этап большой: вы соберёте итоговую панель менеджера целиком.

```html
<!-- Страница проекта выглядит просто, а внутри ждёт много решений -->
<main class="page">
  <h1 class="page__title">Панель менеджера</h1>
</main>
```

## Объяснение

Представьте стройку. Сначала чертёж и каркас, потом внутренняя отделка, потом проверка комиссией. Если проверять только в конце, переделывать придётся стены. Поэтому в проекте мы идём этапами и проверяем каждый.

Проект P2 состоит из трёх страниц и шести этапов.

- Карточка товара. Этап 1: разметка и десктоп. Этап 2: адаптив на 375, 768 и 1024. Этап 4: новое состояние «нет в наличии».
- Форма оформления заказа. Этап 3: подписи, группы полей, раскладка.
- Панель менеджера. Этап 5: таблица заказов (из `div` в настоящую `table`). Этап 6: итоговая панель.

Работа по макету (design handoff, передача макета) устроена так. У макета есть числа: ширины колонок, зазоры, размеры шрифтов. Вы переносите эти числа в CSS и сверяете. Макет в заданиях нарисован схематично: ориентируйтесь на подписанные размеры и допуск в 2 px. Тексты и шрифты точно совпадать не обязаны.

Адаптив проекта строится по одному принципу: от узкого экрана к широкому (mobile-first). Запустите пример, чтобы увидеть, какая раскладка включается на каких ширинах.

Обратите внимание на границы: 599 и 600, 899 и 900. Ошибки в медиазапросах почти всегда случаются именно на границах. Поэтому в проверках есть ширины 599, 600, 899 и 900.

Ещё один полезный расчёт: ширина колонки сетки.

<Playground example="grid-math" />

Правило: числа из макета проверяются расчётом, а не на глаз.

<Wrong>

```css
.product {
  width: 960px;
}
.product__image {
  width: 480px;
  height: 360px;
}
```

</Wrong>

<Right>

```css
.product {
  width: min(960px, calc(100% - 32px));
}
.product__image {
  width: 100%;
  height: auto;
  aspect-ratio: 4 / 3;
}
```

</Right>

Слева размеры не зависят от окна, и на телефоне страница вылезает за экран. Справа ширина считается от окна, а на широком экране ограничена 960.

Что нужно уметь на каждой странице.

**Карточка товара.** Две колонки на широком экране и одна на узком. Фиксированная левая колонка, гибкая правая. Картинки сохраняют пропорции. Характеристики лежат в списке описаний `dl`. Кнопка — настоящий `button`.

**Форма заказа.** Подпись у каждого поля, группы в `fieldset` с `legend`, типы полей и `autocomplete`. Поля одинаковой высоты. Рядом стоящие поля выровнены, зазоры одинаковы.

**Панель менеджера.** Настоящая таблица с `caption` и `scope`. Прокручиваемый контейнер с `tabindex="0"`. Бейджи статусов с контрастом не меньше 4,5 к 1. Видимый фокус у всех интерактивных элементов.

**Изменение требований.** Правило такое: новое состояние добавляется модификатором, старые правила не меняются. Тогда старый вид гарантированно цел. Проверки старого вида остаются в тестах: они ловят случайные поломки. В этапе 4 вы это делаете руками. В этапе 6 новое требование уже встроено в ТЗ, и его легко потерять: проверьте себя.

## Типичные ошибки

Ошибки проекта чаще «тихие»: страница выглядит неправильно, а в консоли пусто. Но есть и настоящие сообщения.

**1. После публикации не загрузились стили.**

<Wrong>

```html
<link rel="stylesheet" href="/styles.css">
```

</Wrong>

```text
Failed to load resource: the server responded with a status of 404 (Not Found)
```

Консоль браузера (вкладка Console в инструментах разработчика) пишет это для каждого файла, который не нашёлся. Путь с косой чертой в начале ищет файл в корне домена `имя.github.io`, а ваш сайт лежит в подпапке `/репозиторий/`. Уберите косую черту.

<Right>

```html
<link rel="stylesheet" href="styles.css">
```

</Right>

**2. Команда Git запущена не в той папке.**

```text
fatal: not a git repository (or any of the parent directories): .git
```

Git не нашёл репозиторий: вы вне папки проекта или не выполнили `git init`. Перейдите в папку проекта командой `cd`.

**3. Страница вылезает за экран на телефоне.** Сообщения нет. Признак: горизонтальная прокрутка. Причина: фиксированная ширина. Не прячьте её через `overflow-x: hidden`.

**4. Новое состояние сломало обычный вид.**

<Wrong>

```css
.product__buy {
  display: none; /* скрыли для «нет в наличии», но у всех товаров тоже */
}
```

</Wrong>

<Right>

```css
.product--sold-out .product__buy {
  display: none;
}
```

</Right>

Базовое правило нельзя менять: пострадают все товары. Состояние включается модификатором.

**5. Таблица из `div`.** Выглядит как таблица, но скринридер не знает, что это таблица. Используйте `table`, `th` и `scope`.

## Итог

Что вы теперь умеете:

- сверстать страницу по макету, переводя числа макета в CSS, и проверять результат расчётом;
- делать адаптивную раскладку от узкого экрана к широкому и проверять границы медиазапросов;
- размечать формы и таблицы так, чтобы их понимали и скринридер, и клавиатура;
- вносить изменение требований модификатором, не ломая готовый вид;
- проверить проект по списку и опубликовать его на GitHub Pages.

Вы закончили модуль «HTML и CSS»: у вас в портфолио три страницы «Домотеки», которые можно показать. Страницы пока статичные: кнопки ничего не делают, форма не отправляется, таблица не фильтруется. В следующем модуле, «JavaScript в браузере», мы оживим их. Начнём с первого урока, [«DOM: поиск и изменение»](/m03-browser-js/l01-dom-basics): научимся находить элементы страницы и менять их из кода.
