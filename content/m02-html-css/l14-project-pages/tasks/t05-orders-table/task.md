## Контекст

Проект P2, этап 5 из 6. Панель менеджера «Домотеки». Первую версию списка заказов собрали на скорую руку из `div` и сетки CSS: выглядит как таблица, но таблицей не является. Скринридер не скажет, в какой колонке ячейка и какому заказу она принадлежит. Менеджер с клавиатурой не может прокрутить таблицу на телефоне.

Задача — рефакторинг (refactor): заменить `div` на настоящую таблицу и не поменять внешний вид. Проверки внешнего вида (колонки, высоты, цвета) уже есть и проходят на заготовке. После правок они обязаны проходить так же.

## Цель

Перепишите разметку списка заказов на `table`, добавьте доступную прокрутку и поправьте `styles.css` так, чтобы вид не изменился.

## Критерии приёмки

- Список — `table.orders` с `caption`: скрытым визуально (класс `visually-hidden`), но с осмысленным текстом.
- Заголовки колонок — пять `th` с `scope="col"` в `thead`. Строки заказов — четыре `tr` в `tbody`.
- Номер заказа в каждой строке — `th` с `scope="row"`, остальные четыре ячейки — `td`.
- Классы и атрибуты `data-table`, `data-head`, `data-row`, `data-col`, `data-scroll`, `status` и их модификаторы остаются. Внутри таблицы нет `div`.
- Контейнер `.orders-scroll` получает `tabindex="0"`, `role="region"` и `aria-label`: на телефоне клавиатурный пользователь может прокрутить его стрелками.
- На 375 таблица не уже 640 px и прокручивается внутри контейнера, сама страница не прокручивается по горизонтали.
- Внешний вид на 1024 прежний: колонки (относительно левого края таблицы) начинаются в 0, 110, 580, 720 и 840 px, высота строки около 48, шапки около 44, цвета и шрифты те же, суммы по правому краю цифрами одной ширины.

## Ограничения

- Таблица и ячейки должны оформляться через CSS, без атрибутов `width` и `style` в разметке.
- Не удаляйте текст статусов: цвет не должен быть единственным признаком.
- Значения цветов, шрифтов и отступов не меняйте.
