## Зачем это в работе

Пришёл тикет от отдела продаж «Домотеки». Страницы каталога плохо находятся в поиске, а покупатель, который пользуется скринридером (программой, читающей экран вслух), пишет в поддержку: «Не могу найти, где начинается список товаров, и не могу нажать «Добавить в корзину»».

Открываем код. Вся страница — это `div` внутри `div` внутри `div`. Кнопка — тоже `div` с красивым фоном. Для глаза всё в порядке. Для поисковика и для скринридера это сплошной текст без единого ориентира.

Эта проблема называется «div-суп». В этом уроке мы научимся размечать страницу тегами, которые сами говорят, что они такое. Такая разметка называется семантической (semantic, от слова «смысл»).

## Объяснение

HTML — это не про внешний вид. HTML описывает, **что** лежит на странице: заголовок, список, меню, кнопка. А как это выглядит, решает CSS.

Представьте магазин с вывесками. Над входом написано «Касса», «Выдача заказов», «Возврат». Покупатель не ходит по залу и не читает всё подряд. Он смотрит на вывески и идёт, куда нужно. Семантические теги — такие вывески для браузера, поисковика и скринридера.

Вот главные «вывески» страницы:

- `header` — шапка: логотип, меню, поиск.
- `nav` (navigation) — блок навигации, главное меню.
- `main` — основное содержимое страницы. На странице он один.
- `article` — самостоятельный блок, который имеет смысл сам по себе: товар, отзыв, новость.
- `section` — раздел внутри содержимого, у которого есть свой заголовок: «Описание», «Отзывы».
- `aside` — боковой блок, который дополняет основное: «Похожие товары», совет.
- `footer` — подвал: контакты, политика конфиденциальности.

Эти теги называют ориентирами (landmarks). Скринридер умеет перепрыгивать между ними одной клавишей.

Ещё три группы тегов, которые дают структуру:

- **Заголовки** `h1`–`h6` (heading) строят план страницы. Уровень заголовка говорит, насколько он важен и где находится в плане.
- **Списки**: `ul` — маркированный, `ol` — нумерованный, `li` — пункт. Меню, характеристики и товары в каталоге — это списки.
- **Ссылки и кнопки**: `a` ведёт на другой адрес, `button` делает действие на этой странице.

## Пример

Вот карточка товара из «Домотеки». Сначала как её часто пишут в спешке.

<Wrong>

```html
<div class="header">
  <div class="logo">Домотека</div>
  <div class="menu">
    <span class="link">Каталог</span>
    <span class="link">Корзина</span>
  </div>
</div>
<div class="product">
  <div class="title">Чайник T-200</div>
  <div class="btn">Добавить в корзину</div>
</div>
```

</Wrong>

А вот та же карточка с осмысленными тегами.

<Right>

```html
<header>
  <a href="/">Домотека</a>
  <nav aria-label="Основное меню">
    <ul>
      <li><a href="/catalog">Каталог</a></li>
      <li><a href="/cart">Корзина</a></li>
    </ul>
  </nav>
</header>
<main>
  <article>
    <h1>Чайник T-200</h1>
    <button type="button">Добавить в корзину</button>
  </article>
</main>
```

</Right>

Страницы выглядят одинаково, пока нет CSS. Различие в том, что видят все остальные: поисковый робот, скринридер, клавиатура.

В нашем примере `aria-label` даёт меню имя. Когда блоков навигации два (шапка и подвал), по имени их можно различить.

## Как это работает

Посмотрите на схему: страница сверху вниз состоит из ориентиров, и они вложены друг в друга.

<Figure src="page-landmarks.svg" alt="Схема страницы. Сверху блок header, внутри него блок nav. Ниже блок main, в нём слева article с двумя секциями «Описание» и «Отзывы», справа aside «Похожие товары». Внизу блок footer." caption="Ориентиры страницы: header с меню, main с товаром и боковым блоком, footer." />

Из схемы следуют несколько правил.

**1. Один `main`, один `h1`.** `main` отмечает главное содержимое страницы. `h1` называет саму страницу. Название магазина в шапке — это ссылка на главную, а не заголовок.

**2. Заголовки идут по порядку.** После `h1` идёт `h2`, после `h2` идёт `h3`. Вернуться наверх можно: после `h3` снова `h2`. Перепрыгнуть вперёд нельзя: после `h2` нельзя ставить `h4`. Скринридер строит по заголовкам оглавление, и пропуск превращается в дыру.

Уровень заголовка выбирают по месту в плане страницы, а не по размеру шрифта. Если нужен мелкий `h2`, меняют размер в CSS.

**3. Список, если это список.** Если пункты равноправны и их несколько, это `ul`. Скринридер объявит «список из четырёх пунктов», и человек сразу поймёт объём.

**4. Кнопка или ссылка.** Задайте себе один вопрос: что произойдёт по клику?

- Откроется другой адрес: это ссылка, `a` с настоящим `href`.
- Что-то изменится на этой странице (товар добавится, блок раскроется): это кнопка, `button`.

<Playground example="choose-tag" />

Почему нельзя просто взять `div` и навесить на него стиль и обработчик клика? Потому что у `button` уже есть то, что придётся писать руками. Он получает фокус по клавише Tab, срабатывает по Enter и пробелу, и скринридер объявляет его кнопкой. У `div` ничего этого нет.

**5. Картинки и подписи.** У каждой картинки есть `alt` с описанием. Если нужна видимая подпись, картинку оборачивают в `figure`, а подпись кладут в `figcaption`. Дату, которую человек читает как «14 марта 2026», оборачивают в `time` с машинным значением: `datetime="2026-03-14"`.

Раздел «Описание» без остальной страницы бессмыслен, это `section`. Если у блока нет собственного заголовка, чаще всего это просто `div` для вёрстки, и это нормально. Теги `div` и `span` не запрещены, они нужны там, где подходящего смысла нет.

## Типичные ошибки

В HTML нет сообщений об ошибках. Браузер молча принимает любую разметку и старается показать её как есть. Поэтому ошибки семантики не видны глазами, их ищут в консоли разработчика (DevTools) и клавиатурой. Ниже результаты, полученные в Chromium.

**1. Кнопка из `div`.** Попробуйте нажать Tab: фокус перескакивает. Это видно в консоли.

<Wrong>

```html
<div class="buy">Добавить в корзину</div>
```

```js
console.log(document.querySelector(".buy").tabIndex);
```

```text
-1
```

</Wrong>

Значение `-1` значит «в порядок обхода по Tab не входит». Настоящий `button` даёт `0`.

<Right>

```html
<button class="buy" type="button">Добавить в корзину</button>
```

```js
console.log(document.querySelector(".buy").tabIndex);
```

```text
0
```

</Right>

**2. Ссылка-пустышка.** Запись `a href="#"` работает как кнопка только на вид. По клику страница прыгает в начало, а в адресе появляется решётка. Если элемент делает действие, ему нужен `button`. Если он ведёт на адрес, ему нужен настоящий `href`.

**3. Заголовок «по размеру».** Разработчик хочет крупный текст и ставит `h1` на логотип. Получилось два `h1`, а скринридер на вопрос «о чём страница» отвечает «Домотека». Проверка в консоли:

```js
console.log(document.querySelectorAll("h1").length);
```

```text
2
```

Должна быть `1`. Размер шрифта — работа CSS.

**4. Картинка без описания.** У `img` нет `alt`. Скринридер может прочитать вместо картинки имя файла, например «kettle точка p n g», а поисковик не понимает, что на картинке. Пустой `alt=""` допустим только для чисто декоративных картинок. Фото товара таким не является.

**5. Пункты меню без списка.** Ссылки лежат в `nav` одна за другой. Работает, но скринридер не скажет «список из трёх пунктов». Оберните их в `ul` и `li`.

## Итог

Что вы теперь умеете:

- размечать страницу ориентирами `header`, `nav`, `main`, `article`, `section`, `aside`, `footer`;
- строить заголовки по порядку: один `h1`, дальше без пропусков;
- выбирать между `button` и `a`: действие на странице или переход по адресу;
- прятать меню, характеристики и товары в списки;
- объяснять, чем плох div-суп для поиска и для людей, которые пользуются клавиатурой и скринридером.

У нас есть разметка страницы, но пока нет способа принять от покупателя данные. В следующем уроке мы займёмся формами: поля, подписи, типы ввода и проверка прямо в браузере.
