## Зачем это в работе

Пришёл тикет: кнопка «В избранное» должна быть прозрачной с синей рамкой, а она серая. Разработчик открывает стили и находит три правила для этой кнопки. Одно написано через `#catalog .btn`, второе через `.btn--ghost`, третье с `!important` в чужом файле. Он добавляет четвёртое, чуть тяжелее. Кнопка исправилась, а на странице оформления заказа сломалась другая кнопка.

Это не ошибка одного человека. Так ломается любой проект, где стили пишут без правил: каждое правило начинает зависеть от соседей. Через полгода менять цвет страшно.

В этом уроке три инструмента против такого хаоса: именование по БЭМ, компонентный подход и слои `@layer`. А ещё способ переписать старые стили так, чтобы страница выглядела точно так же.

```css
#catalog .btn { background: #e5e7eb; }
.btn--ghost { background: transparent; } /* не работает */
```

## Объяснение

Представьте склад. Если коробки лежат где попало и подписаны как «большая» и «синяя», поиск превращается в игру. Если у каждой есть адрес «стеллаж, полка, ячейка», найти нужное можно за секунду. Хорошие имена классов работают как адреса.

БЭМ (BEM) это правило именования. Название расшифровывается как блок, элемент, модификатор.

- Блок (block) — самостоятельная часть страницы, которую можно перенести в другое место: `product-card`, `site-header`.
- Элемент (element) — часть блока, которая вне блока не имеет смысла: `product-card__title`. Читается как «заголовок карточки». Между блоком и элементом два подчёркивания.
- Модификатор (modifier) — вариант блока или элемента: `product-card--sale`. Между именем и модификатором два дефиса.

Компонентный подход (component approach) продолжает ту же мысль. Каждый блок — компонент: у него своя разметка, свои стили, и он не зависит от того, где лежит. Меняя `product-card`, вы не трогаете `site-header`.

Остаётся вопрос приоритета. Если два правила спорят, побеждает более специфичное (у которого вес больше), а при равенстве более позднее. Вес записывается тройкой: сколько в селекторе идентификаторов (id), классов (вместе с атрибутами и псевдоклассами) и тегов. Сравнивают слева направо. Именно поэтому `#catalog .btn` с весом `1-1-0` побеждает `.btn--ghost` с весом `0-1-0`. И поэтому `!important` и id мешают: они ломают предсказуемость.

Слои `@layer` (cascade layers) решают задачу приоритета по-другому. Вы сами называете группы правил и задаёте их порядок. Слой, объявленный позже, побеждает слой, объявленный раньше, независимо от специфичности.

Модификатор меняет переменную, а элемент читает её. Все правила остались плоскими.

## Как это работает

Посмотрите на схему слоёв.

<Figure src="layers.svg" alt="Три слоя слева направо: reset, components, utilities. В слое components правило с весом 0-3-0 и display inline-flex, в слое utilities правило .u-hidden с весом 0-1-0 и display none. Стрелка показывает, что приоритет растёт вправо, поэтому побеждает .u-hidden." caption="Слой побеждает по порядку, а не по весу. Специфичность сравнивается только внутри одного слоя." />

Объявление порядка слоёв стоит первой строкой файла.

```css
@layer reset, components, utilities;

@layer reset {
  button { padding: 0; }
}

@layer components {
  .card .btn.btn--primary { display: inline-flex; padding: 8px 16px; }
}

@layer utilities {
  .u-hidden { display: none; }
}
```

Что здесь важно.

1. **Позже значит сильнее.** Слой `utilities` перебивает `components`, а `components` перебивает `reset`. Простой `.u-hidden` с весом `0-1-0` побеждает громоздкий `.card .btn.btn--primary` с весом `0-3-0`, потому что лежит в более позднем слое.
2. **Внутри слоя всё как раньше.** Специфичность и порядок в файле работают, но только между правилами одного слоя.
3. **Правила вне слоёв сильнее любых слоёв.** Если в проекте со слоями оставить правило без слоя, оно победит всех. Поэтому в слои кладут всё, и `@media` тоже кладут внутрь слоя.
4. **Для `!important` порядок обратный.** Среди объявлений с `!important` побеждает более ранний слой. Поэтому в проекте со слоями `!important` обычно не нужен вовсе.

<Note>

Слои поддерживают все современные браузеры. Если сомневаетесь, проверьте поддержку на странице `@layer` справочника MDN.

</Note>

## Типичные ошибки

Стили не пишут в консоль сообщений об ошибках: неверное правило просто не применяется. Поэтому здесь в основном «тихие» ошибки и одна реальная из скрипта, который строит классы.

**1. Функции построения классов передали `null` вместо объекта модификаторов.**

<Wrong>

```js
const modifiers = null;
Object.entries(modifiers);
```

</Wrong>

```text
TypeError: Cannot convert undefined or null to object
```

`Object.entries` не принимает `null` и `undefined`. Подставьте пустой объект: `Object.entries(modifiers ?? {})`.

**2. Базовый класс потерян.**

<Wrong>

```html
<div class="product-card--sale">...</div>
```

</Wrong>

Консоль молчит, карточка выглядит сломанной: пропали ширина, отступы и рамка. Модификатор в БЭМ не заменяет блок, а дополняет его.

<Right>

```html
<div class="product-card product-card--sale">...</div>
```

</Right>

**3. Селектор через id, который невозможно перебить.**

<Wrong>

```css
#catalog .btn { background: #e5e7eb; }
.btn--accent { background: #c2410c; } /* не применяется */
```

</Wrong>

Модификатор молча проигрывает. Откройте инструменты разработчика: в панели стилей правило `.btn--accent` будет перечёркнуто. Уберите `#catalog` из селектора.

**4. Правило вне слоя.**

<Wrong>

```css
@layer components, utilities;
@layer utilities { .u-hidden { display: none; } }

.card { display: flex; } /* вне слоя, поэтому побеждает u-hidden */
```

</Wrong>

Карточка с классом `u-hidden` осталась на экране: правило вне слоя сильнее любого слоя. Положите `.card` в слой `components`.

**5. `@media` вне слоя.** Адаптивные правила, написанные после слоёв, но без слоя, тоже побеждают все слои. Кладите `@media` внутрь слоя.
