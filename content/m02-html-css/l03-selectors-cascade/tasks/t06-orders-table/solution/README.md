# Разбор

Главная идея: перед тем как писать правило, посчитайте вес правила, которое хотите победить.

| Правило | Вес |
|---|---|
| `table.grid td` (`text-align`, `color`) | `[0,1,2]` |
| `table.grid tbody tr:nth-child(even) td` (зебра) | `[0,2,4]` |

Сравнение идёт слева направо: сначала идентификаторы, потом классы (включая атрибуты и псевдоклассы), потом теги. Теги в расчёт идут, только когда число классов равно.

**1. Суммы справа.** `.orders td.num`: два класса и один тег, `[0,2,1]`. Классов 2 против 1 у `table.grid td`, поэтому побеждаем, хотя тегов меньше. Простое `td.num` (`[0,1,1]`) проиграло бы: классов поровну, а тегов у библиотеки больше.

**2. Отменённые.** `.orders tr[data-status="cancelled"] td`: класс, атрибут и два тега, `[0,2,2]`. Перебивает цвет `td` из библиотеки `[0,1,2]`. Фона у этих правил нет, зебра нам не мешает.

**3. Новые.** Самое трудное место. В чётной строке зебра весит `[0,2,4]`. Правило `.orders tr[data-status="new"] td` весит `[0,2,2]` и проигрывает: классов поровну, тегов у зебры больше. Добавим класс `.grid`: `.grid.orders tr[data-status="new"] td` весит `[0,3,2]`. Классов 3 против 2, и теги уже не сравниваются.

**4. Срочные.** Рамка у первой ячейки не конфликтует с библиотекой, поэтому хватает простого селектора.

**Почему не `!important`.** Оно победило бы, но следующий разработчик, чтобы перебить его, тоже поставит `!important`. Здесь мы набрали вес честным способом и ничего не сломали.
