## Зачем это в работе

Тикет от дизайнера: «Кнопка «Акция» должна быть красной, а она серая. В CSS я написал `background: red`, и ничего не изменилось. Добавил `!important`, стало красным, но теперь не могу поменять цвет в тёмной теме».

Это обычная история. Правило написано правильно, но другое правило оказалось сильнее. Чтобы управлять оформлением, нужно знать две вещи: как выбирать нужные элементы и как браузер решает, какое из конфликтующих правил победит.

Сам CSS не так сложен. Сложно в нём только это место, поэтому уделим ему целый урок.

## Объяснение

Правило CSS состоит из селектора (selector) и объявлений (declarations).

```css
.price {
  color: #b32d00;
}
```

`.price` — селектор, он отвечает на вопрос «какие элементы?». Внутри фигурных скобок объявления, они отвечают на вопрос «как оформить?».

Представьте, что вы раздаёте указания в магазине. «Всем продавцам надеть жилеты» — широкое указание. «Продавцу из отдела кухонной техники надеть синий жилет» — точнее. «Сегодня Анне надеть красный» — самое точное. Когда указания спорят, побеждает самое точное. Так же работает CSS.

Основные виды селекторов:

- **Тег**: `p`, `a`, `td`. Выбирает все элементы с таким тегом.
- **Класс**: `.price`. Выбирает элементы с `class="price"`.
- **Идентификатор** (id): `#cart`. Выбирает один элемент с `id="cart"`.
- **Атрибут**: `[data-stock="0"]` — точное значение, `[href^="https"]` — начинается с.
- **Потомок**: `.card .price` — любой `.price` внутри `.card`.
- **Прямой ребёнок**: `.card > .price` — только непосредственный.
- **Соседний**: `.old-price + .price` — идёт сразу после.
- **Псевдокласс** (pseudo-class): `:hover` (наведение мыши), `:focus-visible` (фокус с клавиатуры), `:nth-child(even)` (чётные), `:first-child`, `:disabled`.

Селекторы можно склеивать без пробела: `button.btn.sale` — это кнопка, у которой есть оба класса.

## Пример

Каталог «Домотеки». Нужно оформить цену в карточке.

```html
<ul class="catalog">
  <li class="card">
    <p class="old-price">36 000 ₽</p>
    <p class="price">32 900 ₽</p>
  </li>
</ul>
```

```css
.card .price {
  color: #b32d00;
}

.old-price {
  text-decoration: line-through;
}

.card:nth-child(even) {
  background-color: #f3f5f7;
}

a[href^="https"] {
  color: #0066cc;
}
```

Читается почти как обычная речь: «цена внутри карточки — красно-коричневая; старая цена — зачёркнута; чётные карточки — на сером фоне; ссылки на внешние сайты — синие».

А теперь про конфликт. Что будет, если у кнопки два правила?

<Wrong>

```css
.btn-sale {
  background: #dd0000;
}

.btn {
  background: #e8ecef;
}
```

</Wrong>

Кнопка с классами `btn btn-sale` окажется серой. Оба класса весят одинаково, и побеждает нижнее правило. Исправлять нужно весом селектора, а не `!important`.

<Right>

```css
.btn {
  background: #e8ecef;
}

.btn.btn-sale {
  background: #dd0000;
}
```

</Right>

## Как это работает

Когда на один элемент действует несколько правил, браузер выбирает победителя для каждого свойства отдельно. Это называется каскадом (cascade). Порядок проверки такой.

1. **Важность.** Объявление с `!important` побеждает обычное. Это крайний случай, о нём ниже.
2. **Специфичность** (specificity) — вес селектора. Побеждает более точный.
3. **Порядок.** Если вес одинаков, побеждает правило, которое написано ниже.

Вес селектора записывают тройкой чисел. Для каждого вида селекторов своя цифра.

Стрелка показывает, что сравнение идёт слева направо." caption="Вес селектора: сколько идентификаторов, классов и тегов. Сравниваем слева направо." />

Три правила подсчёта.

- Каждый идентификатор добавляет единицу в первую позицию.
- Каждый класс, атрибут и псевдокласс добавляет единицу во вторую позицию.
- Каждый тег добавляет единицу в третью позицию.

Сравниваются позиции слева направо. Сначала смотрим на первую цифру. Больше — победил. Одинаково — смотрим на вторую. И так далее. Поэтому `0-1-2` (класс и два тега) сильнее, чем `0-0-9` (девять тегов): классов больше. Один идентификатор `1-0-0` сильнее любого количества классов.

Обратите внимание на последнюю строку: `!important` выиграл у всех, хотя вес у него самый маленький. Именно поэтому его нельзя использовать как способ чинить стили: перебить его можно только ещё одним `!important`.

**Наследование.** Часть свойств передаётся от родителя к потомку без всяких правил. Задали `color` у `body`, и все тексты внутри стали такого цвета. Наследуются в основном свойства текста: `color`, `font-size`, `line-height`, `font-family`. Рамки, отступы и фон не наследуются: иначе у каждого вложенного элемента появилась бы своя рамка.

<Note>

Универсальный селектор `*` не добавляет ничего к весу. Комбинаторы (пробел, `>`, `+`) тоже не добавляют. Вес `.card > .price` равен весу `.card .price`: `0-2-0`.

</Note>

## Типичные ошибки

CSS не пишет ошибок в консоль: неправильное правило просто не применяется. Зато вы можете увидеть, что сделал браузер, и убедиться в этом в DevTools на вкладке Elements: перечёркнутые строки — это правила, которые проиграли. А ошибки в селекторах из JavaScript видны сразу. Результаты ниже получены в Chromium.

**1. Правило есть, а эффекта нет.** Слабый селектор проиграл сильному.

<Wrong>

```css
.catalog .price { color: #222222; }
.price { color: #b32d00; }
```

</Wrong>

Цена останется тёмной: `0-2-0` против `0-1-0`, порядок не помогает. Усильте селектор:

<Right>

```css
.catalog .price { color: #222222; }
.catalog .card .price { color: #b32d00; }
```

</Right>

**2. Селектор записан с ошибкой.** Из JavaScript это видно сразу.

```js
document.querySelector(".card >");
```

```text
SyntaxError: Failed to execute 'querySelector' on 'Document': '.card >' is not a valid selector.
```

Комбинатор `>` стоит в конце, справа не хватает селектора. В самом CSS такая запись молча игнорируется.

**3. Идентификатор не может начинаться с цифры.**

```js
document.querySelector("#1abc");
```

```text
SyntaxError: Failed to execute 'querySelector' on 'Document': '#1abc' is not a valid selector.
```

Выбирайте идентификаторы, которые начинаются с буквы.

**4. Две точки подряд.**

```js
document.querySelector("div..a");
```

```text
SyntaxError: Failed to execute 'querySelector' on 'Document': 'div..a' is not a valid selector.
```

**5. `!important` как лекарство.** Он помогает ровно один раз, а потом приходится ставить его везде. Если хочется поставить `!important`, сначала посчитайте вес двух правил. Скорее всего, достаточно добавить один класс или поднять правило ниже в файле.

**6. `:nth-child` считает всех детей.** В `li:nth-child(2)` берётся второй ребёнок родителя, и только если он `li`. Если перед списком в родителе стоит заголовок, отсчёт сместится.

## Итог

Что вы теперь умеете:

- выбирать элементы по тегу, классу, атрибуту, положению и состоянию;
- считать вес селектора и сравнивать два правила;
- объяснять, почему побеждает то или иное правило: важность, вес, порядок;
- чинить «не работающие» правила без `!important`;
- знать, какие свойства наследуются.

Теперь, когда мы можем выбрать любой элемент и оформить его, пора разобраться, какого размера он будет. В следующем уроке — блочная модель: как складываются содержимое, отступы и рамка, почему элемент шире, чем вы ожидали, и как работают вертикальные отступы.
