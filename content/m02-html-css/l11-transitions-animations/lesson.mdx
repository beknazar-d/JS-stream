## Зачем это в работе

Два тикета от «Домотеки». Первый: «Кнопка „В корзину“ при наведении дёргает текст под собой». Второй: «Покупателю с вестибулярным расстройством от выезжающих карточек становится дурно».

Оба про движение на странице. Движение полезно: оно показывает, что нажатие принято, что данные загружаются, что блок появился. Но неправильное движение тормозит страницу, а для части людей оно вредно. В этом уроке вы научитесь делать движение дешёвым и отключаемым.

## Объяснение

Есть два инструмента.

**Переход (transition).** Когда значение свойства меняется (например, при наведении), браузер не прыгает, а плавно проходит путь за заданное время. Переход нужен для откликов на действия человека.

**Анимация (animation).** Её запускает не изменение, а сама страница. Вы описываете кадры через `@keyframes`, потом подключаете их к элементу. Анимации нужны для загрузки, появления и привлечения внимания.

Представьте лифт. Переход: нажали кнопку, лифт плавно доехал на этаж. Анимация: лифт сам по расписанию ездит вверх-вниз.

Ещё два понятия.

- **Сдвиг и поворот.** За них отвечает свойство `transform`: `translateX(10px)`, `rotate(45deg)`, `scale(1.2)`. Оно рисует элемент иначе, но не меняет место в раскладке.
- **Режим «уменьшить движение» (reduced motion).** Человек включает его в системе. Страница узнаёт об этом через условие `prefers-reduced-motion: reduce`.

## Пример

Плавное приподнимание карточки при наведении:

```css
.card {
  transition: transform 0.2s ease, box-shadow 0.2s ease;
}

.card:hover {
  transform: translateY(-4px);
  box-shadow: 0 8px 16px rgba(0, 0, 0, 0.15);
}
```

Переход пишут у исходного состояния. Тогда он работает в обе стороны. Запись `transform 0.2s ease` читается: какое свойство, сколько времени, какая плавность.

Вращающийся индикатор загрузки:

```css
.spinner {
  animation: spin 1s linear infinite;
}

@keyframes spin {
  from { transform: rotate(0deg); }
  to   { transform: rotate(360deg); }
}
```

Сравните два способа поднять карточку.

<Wrong>

```css
.card { transition: all 0.3s; }
.card:hover { margin-top: -4px; }
```

</Wrong>

<Right>

```css

```

</Right>

Слева соседние блоки подпрыгивают вместе с карточкой, а `all` тянет за собой все изменённые свойства. Справа движется только сама карточка.

## Как это работает

<Figure src="cost-of-properties.svg" alt="Цепочка из трёх шагов: раскладка, рисование, композиция. Изменение width, margin и top проходит все три шага. Изменение цвета фона и тени проходит рисование и композицию. Изменение transform и opacity проходит только композицию." caption="Чем раньше шаг цепочки, тем дороже изменение. transform и opacity запускают только последний шаг." />

Браузер на каждом кадре делает до трёх шагов. Если меняется размер или отступ, нужны все три, и соседние блоки сдвигаются. Если меняется только `transform` или `opacity`, достаточно сложить готовые слои. Поэтому правила такие.

1. **Анимируйте `transform` и `opacity`.** Двигать: `translate`. Увеличивать: `scale`. Показывать и прятать: `opacity`. Цвет фона и тень допустимы для небольших элементов.
2. **Не анимируйте размеры, отступы и положение:** `width`, `height`, `margin`, `top`, `left`.

<Playground example="cost-table" />

3. **Перечисляйте свойства в `transition`.** `transition: all` анимирует всё, что изменится, включая случайное.
4. **Время.** Отклик на наведение: 0,1–0,3 секунды. Дольше интерфейс кажется ленивым. Браузер отдаёт время строкой, например `0.2s` или `200ms`:

<Playground example="parse-time" />

5. **Для вращения берите `linear`.** С `ease` скорость меняется внутри каждого оборота. Для пульса подходит `ease-in-out`.
6. **Бесконечные анимации используйте только для индикаторов загрузки.** Мигающая плашка рядом с текстом мешает читать.
7. **Режим «уменьшить движение» учитывайте всегда.** Блок пишут в конце файла и отключают в нём `animation` и `transition`:

```css
@media (prefers-reduced-motion: reduce) {
  .product-card,
  .cart-count {
    animation: none;
  }

  .button {
    transition: none;
  }
}
```

Блок стоит после основных правил: при равной специфичности побеждает то, что ниже. Настройку учитывают только у тех, кто её включил, поэтому остальным анимации остаются.

<Note>

Отключать нужно движение, а не содержимое. Если карточки появляются из прозрачного состояния, при `animation: none` они сразу видны. А `animation-play-state: paused` оставил бы их на первом, прозрачном кадре.

</Note>

## Типичные ошибки

Как и в прошлых уроках, консоль молчит: браузер просто не делает того, чего не понял. Что происходит на самом деле, мы проверили в Chromium при написании заданий.

**1. Имя кадров не совпадает.** Если `animation` называет `slide-in`, а кадры названы `slidein`, анимация не запустится: у элемента не окажется ни одной анимации.

<Wrong>

```css
.badge { animation: slide-in 0.6s ease-out both; }
@keyframes slidein { from { opacity: 0; } to { opacity: 1; } }
```

</Wrong>

<Right>

```css
.badge { animation: slide-in 0.6s ease-out both; }
@keyframes slide-in { from { opacity: 0; } to { opacity: 1; } }
```

</Right>

**2. Переход написан в `:hover`.** Тогда плавно идёт только включение, а выключение происходит мгновенно. Переход пишут в исходном состоянии.

<Wrong>

```css
.card:hover { transform: translateY(-4px); transition: transform 0.2s; }
```

</Wrong>

<Right>

```css
.card { transition: transform 0.2s; }
.card:hover { transform: translateY(-4px); }
```

</Right>

**3. Вращение без `linear`.** Стандартная функция `ease` ускоряет и замедляет. Через полсекунды кольцо с `ease` уже повёрнуто примерно на 288 градусов вместо 180.

<Wrong>

```css
.spinner { animation: spin 1s infinite; }
```

</Wrong>

<Right>

```css
.spinner { animation: spin 1s linear infinite; }
```

</Right>

**4. Блок «уменьшить движение» выше основных правил.** Правила ниже его перебивают, и у человека с настройкой анимации не отключаются.

<Wrong>

```css
@media (prefers-reduced-motion: reduce) {
  .cart-count { animation: none; }
}
.cart-count { animation: bump 0.5s 2; }
```

</Wrong>

<Right>

```css
.cart-count { animation: bump 0.5s 2; }
@media (prefers-reduced-motion: reduce) {
  .cart-count { animation: none; }
}
```

</Right>

**5. Отключили анимацию, забыли переход.** `animation: none` не влияет на `transition`. Кнопка продолжает двигаться при наведении.

## Задания

Шесть заданий: от плавного наведения до страницы, которая учитывает настройку «уменьшить движение». Тесты ставят анимации на паузу и сами выбирают момент времени, а наведение мыши имитируют применением правил `:hover`. Включить настройку системы тест не может, поэтому он применяет правила из вашего блока `prefers-reduced-motion` так, как будто условие выполнено.

## Итог

Что вы теперь умеете:

- делать плавные переходы через `transition` и писать их в исходном состоянии;
- описывать анимацию через `@keyframes` и подключать её через `animation`;
- выбирать дешёвые свойства: `transform` и `opacity`;
- не дёргать раскладку и не использовать `transition: all`;
- отключать движение по `prefers-reduced-motion`.

Движение, цвет и размеры работают, когда страница доступна каждому. В следующем уроке мы разберём доступность: контраст, фокус, подписи к картинкам и порядок табуляции.
