## Зачем это в работе

Пришёл тикет от кладовщицы «Домотеки». У неё сломана рука, мышью она не пользуется. Она нажимает Tab, чтобы перейти к кнопке «В корзину», и не видит, где находится: рамка вокруг выбранного элемента убрана, потому что «портит вид».

Через неделю второй тикет, от покупателя. Он слабовидящий и пользуется скринридером (screen reader), программой, которая читает страницу вслух. Скринридер доходит до кнопки со значком корзины и говорит просто «кнопка». Какая кнопка, непонятно.

Третий тикет без жалобы. Менеджер открыл сайт на телефоне на улице, под солнцем, и не смог прочитать серую цену.

Это одна тема: доступность (accessibility, коротко a11y). Она не про «особый режим для немногих». Это клавиатура, плохое освещение, усталые глаза, скринридер, медленный интернет. Доступный сайт удобнее всем.

```html
<button type="button" class="icon-button">
  <svg width="24" height="24" viewBox="0 0 24 24"></svg>
</button>
```

В этой кнопке нет текста. Для глаз значок понятен. Для скринридера кнопки с именем не существует.

## Объяснение

Представьте здание магазина. Для людей с разными возможностями в нём есть пандус, указатели на стенах и подсветка ступеней. Если архитектор забыл про табличку на двери, дверь остаётся дверью, но найти нужную невозможно.

Страница устроена так же. Браузер строит из разметки второе дерево, дерево доступности (accessibility tree). В нём у каждого элемента есть роль (кнопка, ссылка, заголовок), имя (accessible name, то, что скринридер произносит вслух) и состояние (нажата, отмечена, отключена). Скринридер читает именно это дерево, а не картинку на экране.

Пять вещей, с которых начинается доступная вёрстка:

- Контраст (contrast). Цвет текста достаточно отличается от фона.
- Видимый фокус (focus indicator). Видно, какой элемент выбран клавишей Tab.
- Описания картинок. У содержательной картинки есть текстовая замена, у декоративной её нет.
- Имена. У каждой кнопки, ссылки и поля есть понятное название.
- Порядок. Tab ходит по элементам в том же порядке, в каком их видно.

Требования собраны в стандарте WCAG 2.1 (Web Content Accessibility Guidelines, «Руководство по доступности веб-контента»). У него три уровня: A, AA и AAA. Большинство сайтов и законов ориентируются на уровень AA. Мы тоже: он реалистичен и закрывает главное.

Хорошая новость: большая часть доступности достаётся бесплатно, если использовать правильные HTML-элементы. Настоящий `button` уже умеет принимать фокус, нажиматься по Enter и пробелу и называть себя кнопкой.

## Как это работает

Посмотрите на схему. Слева кнопка без имени, справа с именем. Глазами они одинаковы, а в дереве доступности разные.

<Figure src="accessibility-tree.svg" alt="Две колонки. Слева: кнопка со значком корзины без подписи, в дереве доступности роль «кнопка» и нет имени, скринридер говорит «кнопка». Справа: та же кнопка с именем, скринридер говорит «Открыть корзину, кнопка»." caption="Скринридер читает дерево доступности, а не картинку. Без имени кнопка превращается в загадку." />

Разберём по порядку.

**1. Контраст.** Формула такая. Каждый цветовой канал пересчитывается, затем считается относительная яркость (relative luminance): `0,2126 * R + 0,7152 * G + 0,0722 * B`. Контраст равен `(L1 + 0,05) / (L2 + 0,05)`, где L1 яркость более светлого цвета, L2 более тёмного. Результат от 1 (цвета одинаковы) до 21 (чёрное на белом). Порог для обычного текста 4,5, для крупного 3. Крупным считается текст от 18pt (это 24px) или от 14pt жирным (около 18,67px). Рамкам полей, значкам и рамке фокуса достаточно 3 к 1 с соседним цветом.

<Playground example="large-text" />

**2. Видимый фокус.** Браузер рисует вокруг выбранного элемента рамку `outline`. Многие её убирают и ничего не ставят взамен. Это ошибка уровня AA. Правильно оставить рамку и сделать её заметной. Псевдокласс `:focus-visible` показывает её при навигации с клавиатуры и не показывает после щелчка мышью.

```css
:focus-visible {
  outline: 3px solid #0b57d0;
  outline-offset: 2px;
}
```

Рамка тоже должна быть контрастной. На тёмной шапке синий не виден, поэтому там нужен светлый цвет.

**3. Имя.** Браузер выбирает имя элемента в таком порядке (упрощённо): `aria-label`, затем связанный `label`, затем содержимое, затем `alt`. Посмотрите, как это работает.

<Playground example="accessible-name" />

**4. Когда ARIA не нужна.** ARIA (Accessible Rich Internet Applications) это набор атрибутов, которые дополняют HTML: `aria-label`, `aria-hidden`, `role`. Первое правило ARIA: если можно использовать подходящий HTML-элемент, используйте его, а не ARIA. `div` с `role="button"` придётся научить фокусу, Enter, пробелу и состояниям. Настоящий `button` умеет всё это сразу. `aria-label` нужен там, где у элемента нет видимого текста, например у кнопки-значка.

**5. Картинки.** Содержательная картинка получает `alt`, который отвечает на вопрос «что здесь и зачем»: `alt="Электрический чайник Домотека ЧЭ-17, белый"`. Не «картинка» и не имя файла. Декоративная картинка получает пустой `alt=""`: скринридер её пропускает. Если убрать атрибут совсем, некоторые программы прочитают адрес файла.

**6. Порядок Tab.** По умолчанию Tab идёт по ссылкам, кнопкам и полям в порядке разметки. Поэтому порядок в HTML должен совпадать с порядком на экране. Значение `tabindex="0"` включает элемент в этот порядок, `tabindex="-1"` разрешает фокус только из скрипта. Положительные значения (`tabindex="3"`) вытаскивают элемент вперёд и ломают порядок: не используйте.

Ещё один приём: ссылка пропуска (skip link). Это первая ссылка на странице «Перейти к содержимому». Она спрятана и появляется при фокусе. Клавиатурный пользователь одним нажатием Enter обходит всю шапку.

**7. Скрытый текст.** Подпись, которая нужна только скринридеру, прячут классом `.visually-hidden`. `display: none` и `visibility: hidden` тут не подходят: такой текст пропадает и из дерева доступности.

```css
.visually-hidden {
  position: absolute;
  width: 1px;
  height: 1px;
  margin: -1px;
  padding: 0;
  border: 0;
  overflow: hidden;
  clip: rect(0 0 0 0);
  white-space: nowrap;
}
```

<Note>

Проверять доступность можно без специальных программ. Пройдите по странице клавишей Tab: видно ли, где вы? Дойдите до каждой кнопки? Затем откройте инструменты разработчика браузера: в палитре цвета рядом с выбранным цветом показан контраст. Лучшая проверка остаётся живой: хотя бы раз пройдите страницу без мыши.

</Note>

## Типичные ошибки

Большинство ошибок доступности не пишет в консоль ничего. Страница работает, но не для всех. Поэтому здесь два вида примеров: те, что ломают скрипты, и «тихие».

**1. Скрипт ищет ссылку пропуска по неверному классу.**

<Wrong>

```js
document.querySelector('.skip-link').focus();
```

</Wrong>

```text
TypeError: Cannot read properties of null (reading 'focus')
```

`querySelector` не нашёл элемент и вернул `null`. У `null` нет метода `focus`. Проверьте, что в разметке класс совпадает, а сама ссылка добавлена в страницу.

**2. Тихий NaN в проверке контраста.** Сообщение об ошибке не появится вовсе.

<Wrong>

```js
const channel = parseInt("#zzzzzz".slice(1, 3), 16);
console.log(channel);
```

</Wrong>

```text
NaN
```

Опечатка в записи цвета превращается в `NaN`, а расчёт контраста молча даёт `NaN`. Любое сравнение с `NaN` ложно, и проверка «не прошла», хотя цвет просто записан неверно. Проверяйте формат цвета и бросайте понятную ошибку.

**3. Рамка убрана.** Консоль молчит, пока вы не нажмёте Tab.

<Wrong>

```css
button:focus {
  outline: none;
}
```

</Wrong>

Нажмите Tab: выбранной кнопки не видно. Верните рамку.

<Right>

```css
button:focus-visible {
  outline: 3px solid #0b57d0;
  outline-offset: 2px;
}
```

</Right>

**4. Серая подпись.**

<Wrong>

```css
.product__hint {
  color: #999999; /* 2,85 к 1 на белом */
}
```

</Wrong>

Консоль молчит. Только число в расчёте или в палитре цвета инструментов разработчика скажет правду. Затемните цвет, пока контраст не станет не меньше 4,5 к 1: `#767676` на белом даёт 4,54.

**5. `alt` с именем файла или словом «картинка».** Формально атрибут есть, пользы нет. Замените описанием.

## Итог

Что вы теперь умеете:

- считать контраст по формуле и сравнивать его с порогами 4,5 и 3;
- возвращать и настраивать видимый фокус через `:focus-visible`, не убирая `outline` без замены;
- давать имена кнопкам-значкам, подписывать поля и описывать картинки;
- объяснять, когда ARIA нужна, а когда достаточно обычного HTML;
- прятать текст от глаз, но не от скринридера, и добавлять ссылку пропуска.

Все эти правила пригодятся в проекте P2, где вы будете верстать три страницы «Домотеки». В следующем уроке мы займёмся организацией стилей: БЭМ, слоями `@layer` и отказом от `!important`. Когда стили выстроены по правилам, доступность (например, рамку фокуса) можно менять в одном месте и быть уверенным, что она не сломается где-то ещё.
