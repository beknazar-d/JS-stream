## Контекст

Тикет DEL-240. Мы подключаем службу доставки. Ответ приходит как JSON, и сегодня экран заказов получает его через `as Shipment`. На прошлой неделе служба прислала вес `"2.5"` строкой, и в интерфейсе появился `NaN кг`.

Нужна функция, которая принимает непроверенное значение и возвращает либо надёжный `Shipment`, либо список понятных проблем.

## Цель

Напишите в `index.ts` функцию `parseShipment(raw: unknown): Result<Shipment, string[]>`. Тип `Result` уже объявлен: либо `{ ok: true, value }`, либо `{ ok: false, error }`.

## Критерии приёмки

Ответ службы выглядит так: `{ id, status, weightKg, courier }`. Поля проверяются по порядку, ошибки собираются все сразу, текст сообщений фиксирован.

- `id` — непустая строка. Иначе: `id: ожидалась непустая строка`.
- `status` — один из `created`, `in_transit`, `delivered`, `cancelled`. Иначе: `status: неизвестный статус`.
- `weightKg` — конечное число больше нуля. Иначе: `weightKg: ожидалось число больше нуля`.
- `courier` — `null` или объект с числовым `id` и непустой строкой `name`. Иначе: `courier: ожидался null или курьер с id и name`.
- Отсутствующее поле считается неверным. Лишние поля игнорируются и в результат не попадают.
- Если `raw` не объект (`null`, массив, строка, число), результат — `{ ok: false, error: ['ответ: ожидался объект'] }`.
- Если проблем нет, результат — `{ ok: true, value }`, где `value` содержит ровно четыре поля `id`, `status`, `weightKg`, `courier`.
- Тип результата — `Result<Shipment, string[]>`. Читать `value` без проверки `ok` компилятор не даёт.

## Ограничения

- Типы `Shipment`, `Courier`, `ShipmentStatus` и `Result` менять нельзя.
- Не используйте `any` и приведение `as` к `Shipment`.
