# Разбор

В коде два дефекта, и оба про доверие к данным.

1. **Слабый охранник.** `typeof value === 'object'` верно и для `null`, и для массива, и для объекта без нужных полей. Охранник должен проверять каждое поле, которое потом читает код. Порядок важен: сначала `value !== null`, потом `'id' in value`, потом `typeof value.id`. После `in` компилятор знает, что свойство есть, и разрешает читать его как `unknown`.
2. **`as Courier` вместо проверки.** Приведение не проверяет ничего, это обещание разработчика. Здесь оно нарушено: JSON приходит из сети. Исправление: положить результат `JSON.parse` в переменную типа `unknown` и пропустить через охранник.

Обратите внимание на `try/catch`. `JSON.parse` бросает `SyntaxError` на сломанном тексте. Это единственное место, где нужно перехватить исключение: дальше работаем с обычными значениями.

После `if (!isCourier(data)) return …` компилятор знает, что `data` — это `Courier`, поэтому `data.name` и `data.phone` читаются без единого `as`.
