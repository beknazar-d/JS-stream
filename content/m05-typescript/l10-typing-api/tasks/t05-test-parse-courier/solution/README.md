# Разбор

Тесты на валидацию проверяют отказы не меньше, чем успех. Каждое правило из описания — это отдельный случай, который можно нарушить.

1. **id строкой.** Данные из CSV и форм приходят строками. Только тест `parseCourier({ id: '7', … }).ok === false` ловит мутант, который превращает строку в число.
2. **Пробелы.** Проверка `name.trim() === ''` защищает от пустого имени, но возвращаемое значение должно быть обрезанным. Это второе правило, и оно проверяется отдельным тестом, который сравнивает `value` целиком.
3. **Отсутствующее поле.** `phone: null` разрешён, а отсутствие поля нет. Это тонкая граница: `undefined` и `null` для людей похожи, для функции нет.

Заметьте, что в успешных случаях сравнивается весь результат через `toEqual`. Проверки одного `ok` недостаточно: она пропускает ошибку в значении.

Ещё полезно проверить границы числа: ноль, дробь и отрицательное. Мутантов на них нет, но функцию будут переписывать, и именно эти значения ломаются при переписывании чаще всего.
