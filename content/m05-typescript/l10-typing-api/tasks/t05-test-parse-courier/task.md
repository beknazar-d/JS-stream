## Контекст

Данные о курьере приходят из двух источников: из ответа службы доставки и из CSV-выгрузки отдела кадров. Функцию `parseCourier` будут переписывать на более быструю версию. Нужны тесты, которые поймают любую поломку правил.

## Цель

Напишите тесты в `index.test.ts` для функции `parseCourier` из `subject/index.ts` (код показан под описанием). Функция принимает непроверенное значение и возвращает `Result<Courier, string>`:

- значение должно быть объектом;
- `id` — положительное целое число (не строка);
- `name` — строка, не пустая после обрезки пробелов; в результат попадает имя с обрезанными пробелами;
- `phone` — обязательное поле: строка или `null`.

## Критерии приёмки

- Все ваши тесты проходят на показанной реализации.
- Тесты падают на каждой из трёх реализаций с ошибкой.
- Тесты проверяют результат, а не устройство функции: достаточно сравнивать возвращаемые значения.
- Названия тестов описывают случай по-русски.

## Ограничения

- Пишите тесты только в `index.test.ts`. Из `index.js` импортируйте только `parseCourier`.
- Используйте `describe`, `it`, `expect` без импорта.
- Подумайте о значениях, которые ровно на границе правил: пробелы, ноль, отсутствие поля.
