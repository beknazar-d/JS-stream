# Разбор

**Баг в логике.** `groups[key] = [item]` каждый раз создаёт новый массив и затирает прежний. Правильно: создать группу один раз, если её ещё нет, и добавлять в неё элементы.

**Баг в типах.** `any` на входе и выходе разрывает связь между типом списка и типом результата. Обобщённая запись `groupBy<T>(items: T[], keyOf: (item: T) => string): Record<string, T[]>` её восстанавливает. `T` выводится из списка, поэтому колбэк получает доставку целиком, а `byCourier["Анна"][0].adress` сразу подсвечивается.

**Ловушка с ключами.** Обычный объект `{}` наследует свойства `constructor`, `toString` и другие. Проверка `groups[key] ??= []` для ключа `"constructor"` видит функцию и не создаёт группу. `Object.hasOwn(groups, key)` смотрит только на собственные свойства объекта.

Ключ ограничен строкой типом `(item: T) => string`: колбэк с числом не пройдёт проверку. Если ключи бывают числами, их превращают в строку явно: `String(item.id)`.
