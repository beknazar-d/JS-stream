# Разбор

Нужны сразу две вещи: читать `item.id` и вернуть вызывающему его собственный тип записи. Ограничение `T extends { id: number }` даёт обе.

- Внутри функции `T` гарантированно имеет `id: number`, поэтому `item.id` проходит проверку.
- Снаружи `T` остаётся полным типом записи: для списка посылок `findById` возвращает `Parcel | undefined`, и поля `weightKg` и `status` доступны.

Если вместо этого написать параметр `{ id: number }[]`, функция примет любой список записей, но вернёт «голую» запись с одним полем `id`. Ограничение отличается тем, что не стирает остальное.

`Map.set` перезаписывает значение существующего ключа, поэтому при повторе `id` остаётся последняя запись без дополнительных проверок.

Компилятор не принимает список без `id`: типы `{ name: string }[]` не проходят ограничение, и ошибка видна ещё в редакторе, а не на складе.
