# Разбор

Два параметра типа связаны между собой: `T extends Entity<Id>`. Это ограничение говорит: «запись `T` обязана иметь поле `id` того типа, который мы назвали `Id`». Поэтому `createRepository<Courier>()` с `id: string` не компилируется: по умолчанию `Id` равен `number`, а у `Courier` строка.

Значение по умолчанию `Id = number` делает частый случай коротким: `createRepository<StockEvent>()`. Для строк указывают второй параметр: `createRepository<Courier, string>()`.

`Map<Id, T>` подходит по трём причинам: ключ любого типа, порядок добавления сохраняется, `delete` сам возвращает `true` или `false`.

Состояние создаётся внутри фабрики. Если вынести `Map` наружу, все хранилища будут делить одни данные.

`list()` возвращает новый массив через `[...items.values()]`: изменение результата не затронет хранилище.

## Вопросы, которые стоило задать

- Что делать при повторном идентификаторе: ошибка, замена или игнор?
- Возвращать сами объекты или копии?
- Допустимы ли пустые идентификаторы (пустая строка, `0`)?
- Нужен ли порядок, отличный от порядка добавления?

## Допущения в эталоне

Повтор заменяет запись и не меняет её место в списке. Объекты возвращаются без копирования. Тесты эти решения не проверяют.
