## Контекст

Тикет PLAT-77. В «Домотеке» три сервиса хранят данные в памяти, пока нет базы: журнал складских событий (идентификатор числом), список курьеров (идентификатор строкой вида `"c-17"`) и справочник зон. Каждая команда написала свой класс с методами «добавить, найти, список, удалить». Платформенная команда просит один общий `createRepository`, который подойдёт всем трём.

Заказчик написал: «Сделайте просто, как у нас в Excel: добавил запись, нашёл по номеру». Деталей нет. Что делать с повторным номером, с пустым списком, с записью без номера, не сказано.

## Цель

В `index.ts` реализуйте `createRepository<T, Id>()`: фабрику, которая создаёт хранилище записей в памяти. Типы `Entity` и `Repository` уже объявлены, но пока они не обобщённые: сделайте их обобщёнными и реализуйте фабрику.

Хранилище умеет:

- `add(item)` — добавить запись;
- `get(id)` — найти запись по идентификатору;
- `list()` — все записи в порядке добавления;
- `remove(id)` — удалить запись, вернуть `true`, если она была, и `false`, если нет.

## Критерии приёмки

- `createRepository<StockEvent>()` работает с числовыми идентификаторами без указания второго параметра: по умолчанию `Id` — `number`.
- `createRepository<Courier, string>()` работает со строковыми идентификаторами.
- Тип записи должен иметь поле `id` того же типа, что `Id`. Для `createRepository<Courier>()`, где `id` строка, компилятор сообщает об ошибке.
- `get` с идентификатором неверного типа не компилируется.
- `get` для неизвестного идентификатора возвращает `undefined`.
- `list()` возвращает записи в порядке добавления и каждый раз новый массив: изменение результата не влияет на хранилище.
- Два хранилища независимы: запись в одном не видна в другом.
- `remove` возвращает `true`, если запись была, и `false`, если нет. После удаления `get` возвращает `undefined`.

## Неясности

В тикете не сказано: что делать, если добавить запись с уже существующим идентификатором (ошибка, замена, игнор)? Что с пустым идентификатором? Нужно ли возвращать копии записей или сами объекты? Запишите вопросы и допущения в `assumptions.txt` до кода. Тесты проверяют только однозначные случаи и повторные идентификаторы не трогают.

## Ограничения

- Менять только `index.ts` и `assumptions.txt`.
- Без `any` и без `as`.
