# Разбор

`Record<DeliveryStatus, string>` — объект, у которого есть ровно пять ключей из `DeliveryStatus`, и значение каждого — строка. Если в `DeliveryStatus` появится шестой статус, объект `statusLabels` перестанет проходить проверку (ошибка TS2741 или TS2739), пока подпись не добавят. Так «забытый» статус ловится при сборке, а не у покупателя.

Сравните с описанием `{ [status: string]: string }`. Оно допускает любые ключи, в том числе опечатки, и не требует, чтобы все статусы были. Проверка теряется.

Для счётчиков тот же приём: `Record<DeliveryStatus, number>` с нулями для всех статусов. Начинать с пустого объекта нельзя: тогда нет нулей, а тип не даст вернуть неполный объект. Дальше `counters[delivery.status] += 1` — безопасно, потому что ключ точно существует.

Исходный список не меняется: функция только читает его.
