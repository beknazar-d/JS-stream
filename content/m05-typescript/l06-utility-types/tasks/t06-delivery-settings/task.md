## Контекст

Тикет PLAT-130. Тарифы доставки «Домотеки» хранятся как настройки. Есть общие значения по умолчанию, а каждый регион может переопределить часть из них: Урал меняет `perKg`, Калининград — валюту, остальное берёт общее. Сейчас везде используется один интерфейс `DeliverySettings`, и из-за этого:

- переопределение приходится заполнять целиком, хотя нужно одно поле;
- публичный API случайно отдаёт внутреннюю заметку `note`;
- настройки можно изменить на лету в любом месте кода.

Бизнес написал: «Сделайте нормально: чтобы регионы меняли только то, что им нужно, и ничего лишнего наружу не уходило». Что именно считать «лишним», что делать с отрицательными значениями и как округлять стоимость, в письме нет.

## Цель

В `index.ts` соберите типы из `DeliverySettings` через utility types и реализуйте три функции:

- `SettingsOverride` — переопределение региона: любые поля, каждое по отдельности;
- `ResolvedSettings` — итоговые настройки: все поля заполнены, менять их нельзя;
- `PublicSettings` — то, что видит внешний API: только `baseFee`, `perKg` и `currency` (тоже без возможности менять);
- `CalcFeeArgs` и `Fee` — типы параметров и результата функции `calcFee`, взятые из неё самой;
- `resolveSettings(defaults, override)` — настройки региона на основе общих;
- `publicSettings(settings)` — публичное представление;
- `calcFee(settings, weightKg, orderTotal)` — стоимость доставки.

## Критерии приёмки

- `resolveSettings` возвращает новые настройки: значения из `override` поверх `defaults`. Общие настройки `defaults` не меняются.
- Поля `override` со значением `undefined` пропускаются: остаётся значение по умолчанию.
- `publicSettings` возвращает объект ровно с тремя полями: `baseFee`, `perKg`, `currency`.
- `calcFee`: если `orderTotal` не меньше `freeFrom`, доставка бесплатная (0). Иначе `baseFee + perKg * weightKg`.
- В `SettingsOverride` можно указать любое подмножество полей, в том числе пустое. Неизвестные поля компилятор не принимает.
- Все поля `ResolvedSettings` и `PublicSettings` доступны только для чтения: присваивание не компилируется.
- `CalcFeeArgs` и `Fee` получены через `Parameters` и `ReturnType`, а не переписаны вручную.

## Неясности

В тикете не сказано: что делать с отрицательными и нулевыми значениями (`perKg: -5`)? Округлять ли стоимость до рубля? Разрешены ли дробные килограммы? Нужно ли проверять валюту при расчёте? Запишите вопросы и допущения в `assumptions.txt` до кода. Тесты проверяют только целые неотрицательные значения.

## Ограничения

- Менять `index.ts` (типы и функции) и `assumptions.txt`. Интерфейс `DeliverySettings` и `defaultSettings` оставьте.
- Без `any` и без `as`.
