# Разбор

Главная идея: `unknown` не даёт использовать значение без проверки, и это защищает от `null`, который превращается в `0`, и от `true`, который превращается в `1`.

1. Результат сначала `NaN` («не получилось»). Ветки заполняют его, если значение подошло.
2. `typeof value === "number"` сужает тип до `number`. Внутри ветки компилятор уже знает, что это число.
3. Для строки проверяется формат регулярным выражением до `Number()`. Так `""` и `"abc"` отсеиваются, а `Number("")` не превращается в тихий ноль.
4. Общая проверка в конце ловит `NaN`, `Infinity`, ноль и отрицательные числа: `Number.isFinite` и `weight <= 0`.
5. Все остальные типы (`null`, `undefined`, объекты, `true`) не попали ни в одну ветку, и `weight` остался `NaN`. Они бросают ту же ошибку.

## Вопросы, которые стоило задать

- Запятая как разделитель: в российских формах она встречается часто.
- Пробелы вокруг числа и единицы измерения.
- Экспонента, шестнадцатеричная запись.
- Нужен ли вес ноль (например, для документов без веса).

## Допущения в эталоне

Принимаются только числа и строки в строгом десятичном формате через точку. Остальное считается ошибкой. Тесты эти решения не проверяют.
