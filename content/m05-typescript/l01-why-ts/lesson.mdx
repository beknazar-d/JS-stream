## Зачем это в работе

Сервис доставки «Домотеки» получил жалобу. Курьерам в приложении показывался маршрут на `undefined` вместо адреса. Причина нашлась за час: один разработчик переименовал поле `address` в `deliveryAddress`, а другой экран продолжал читать старое имя. Код запустился, консоль промолчала, ошибка всплыла только у курьера.

Такие поломки видны заранее. Программа, которая знает, какие поля бывают у заказа, подчеркнёт старое имя красным ещё в редакторе. Этим и занимается TypeScript.

```ts
const order = { id: 1042, deliveryAddress: "Казань, Баумана 5" };
console.log(order.address);
```

```text
error TS2339: Property 'address' does not exist on type '{ id: number; deliveryAddress: string; }'.
```

## Объяснение

TypeScript — это JavaScript плюс описание типов (types). Тип говорит, какие значения может хранить переменная и что с ними можно делать. Вы пишете `.ts` файл, компилятор (compiler) его проверяет, а затем убирает типы и выдаёт обычный JavaScript.

Представьте проверку на складе перед отправкой. Коробку сверяют с накладной до того, как она уехала. В дороге накладной уже нет, едет только коробка. Так и здесь: проверка идёт при компиляции (compile time), а в рантайме (runtime) остаётся один JavaScript.

<Figure src="compile-time.svg" alt="Схема из четырёх блоков слева направо: файл index.ts с кодом и типами, проверка типов компилятором tsc, файл index.js без типов, запуск в Node или браузере. Под проверкой пунктирный блок: при ошибке типа запуска не будет." caption="Типы живут только до запуска. После компиляции остаётся JavaScript." />

Из этого следуют два вывода.

1. TypeScript находит ошибки до запуска: опечатки в именах полей, не тот тип аргумента, забытый случай.
2. TypeScript не проверяет данные, которые приходят в рантайме. Ответ сервера, текст из формы, содержимое файла — всё это может не совпасть с вашими типами, и компилятор об этом не узнает.

## Пример

Запустите пример. Мы сказали компилятору, что `parcels` — число. Он поверил. В рантайме это строка.

Что произошло. `JSON.parse` возвращает `any` (любое значение, о нём ниже). Конструкция `as { parcels: number }` — это заявление «поверь, здесь число». Проверки она не делает. Поэтому `typeof` показал `string`, а `+ 1` склеил строки и получил `71`.

<Wrong>

```ts
const data = JSON.parse(text) as { parcels: number };
console.log(data.parcels + 1); // "71", а типы не возражают
```

</Wrong>

<Right>

```ts
const parcels: number = Number(data.parcels);
console.log(parcels + 1); // 8
```

</Right>

## Как это работает

**Аннотации.** Тип записывают после двоеточия: `let count: number = 3`. Базовые типы: `number` (все числа), `string` (текст), `boolean` (`true` и `false`). Массив записывается как тип элемента со скобками: `string[]`, `number[]`.

**Вывод типов (type inference).** Часто писать тип не нужно, компилятор выводит его из значения. `const prices = [120, 80, 45]` уже имеет тип `number[]`.

- У `const city = "Казань"` тип `"Казань"`: константа не поменяется, поэтому тип такой же узкий, как значение.
- У `let courier = "Иван"` тип `string`: переменную можно перезаписать другой строкой.

Практика: аннотируйте параметры функций и возвращаемые значения на границах, а для локальных переменных оставляйте вывод.

<Playground example="inference" />

**Режим strict.** В этом курсе TypeScript всегда работает в строгом режиме (`strict`). Он включает набор проверок. Две главные:

- нельзя оставить параметр без типа: он стал бы `any` неявно (implicit any);
- `null` и `undefined` — отдельные значения: в переменную типа `string` их положить нельзя.

Подробно про настройки поговорим в уроке про `tsconfig`.

**any и unknown.** Оба типа принимают любое значение, но ведут себя противоположно.

- `any` выключает проверку. С ним можно делать что угодно, ошибки уйдут в рантайм. Это путь обратно в JavaScript.
- `unknown` честно говорит «не знаю, что здесь». Пользоваться значением можно только после проверки, например через `typeof`.

<Playground example="unknown-guard" />

<Note>

Проверка `typeof value === "number"` внутри `if` сужает тип: в этой ветке компилятор уже знает, что `value` — число. Сужение типов мы разберём подробно в уроке про объединения. Сейчас запомните: `unknown` приходится проверять, и это хорошо.

</Note>

Правило: когда тип значения неизвестен (ответ сервера, текст из формы), берите `unknown`, а не `any`.

## Типичные ошибки

Сообщения ниже получены запуском компилятора TypeScript 6.0.3 в режиме `strict`.

**1. Не тот тип значения.**

<Wrong>

```ts
const quantity: number = "12";
```

</Wrong>

```text
error TS2322: Type 'string' is not assignable to type 'number'.
```

Сообщение читается так: «тип `string` нельзя положить в тип `number`». Либо превратите значение (`Number("12")`), либо поправьте аннотацию, если данные действительно строки.

**2. Не тот тип аргумента.**

<Wrong>

```ts
function total(a: number, b: number) { return a + b; }
total("1", 2);
```

</Wrong>

```text
error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.
```

Похоже на первую ошибку, но речь об аргументе функции. Компилятор называет и то, что вы передали, и то, что функция ждёт.

**3. Неверное число аргументов.**

```text
error TS2554: Expected 2 arguments, but got 1.
```

Такое сообщение появится, если вызвать `total(1)`. Параметры функции обязательны, пока вы не сделали их необязательными.

**4. Параметр без типа.**

<Wrong>

```ts
function weigh(value) { return value; }
```

</Wrong>

```text
error TS7006: Parameter 'value' implicitly has an 'any' type.
```

В строгом режиме компилятор не угадывает тип параметра сам. Допишите аннотацию: `value: number`.

**5. Использовали unknown без проверки.**

<Wrong>

```ts
const raw: unknown = "5";
raw.toFixed(2);
```

</Wrong>

```text
error TS18046: 'raw' is of type 'unknown'.
```

Это та самая защита. Сначала проверьте тип: `if (typeof raw === "number") { ... }`.

**6. Пустое значение там, где его не ждали.**

<Wrong>

```ts
const code: string = null;
```

</Wrong>

```text
error TS2322: Type 'null' is not assignable to type 'string'.
```

В строгом режиме `null` не входит в `string`. Как описать «строка или `null`», узнаем в уроке про объединения.
