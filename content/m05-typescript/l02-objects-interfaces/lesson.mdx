## Зачем это в работе

Тикет от курьерской службы: «В приложении у некоторых заказов нет улицы, а у других нет квартиры. Иногда падает экран». Оказалось, что адрес приходит из трёх источников, и в каждом свой набор полей. Разработчики держали форму адреса в голове и в комментариях.

Если форма записана в коде, компилятор проверяет её сам. Забыли `street` при создании заказа — ошибка сразу. Читаете `apartment` как обязательное — компилятор напомнит, что оно бывает пустым.

```ts
const order: Order = { id: 1042 };
```

```text
error TS2741: Property 'status' is missing in type '{ id: number; }' but required in type 'Order'.
```

## Объяснение

Объект — это набор полей. Форму объекта (shape) описывают двумя способами: `interface` и `type`. Для объектов они почти равны, и в этом курсе действует простое правило: форму объекта пишем через `interface`, а `type` берём для псевдонимов и объединений (их разберём в уроке 5.4).

Представьте бланк накладной. В бланке напечатаны графы: номер, получатель, адрес. Одни графы обязательные, другие можно оставить пустыми, номер после выдачи не исправляют. Бланк не интересуется, кто его заполнил. Ему важно, что графы на месте. Так и в TypeScript: тип проверяет форму, а не происхождение объекта. Это называется структурной типизацией (structural typing).

В описании формы три приёма:

- обычное свойство обязательно: `status: string`;
- вопросительный знак делает свойство необязательным: `comment?: string`. Значение такого свойства — строка или `undefined`;
- `readonly` запрещает перезаписывать свойство после создания: `readonly id: number`.

Вложенные объекты описываются отдельными типами. Тип одного объекта можно использовать как тип поля другого.

## Как это работает

Посмотрите, как компилятор проверяет три разных объекта по одному описанию.

<Figure src="object-shape.svg" alt="Слева описание interface Order: id только для чтения, status обязательное, comment необязательное. Справа три карточки: объект с id и status подходит; объект только с id даёт ошибку TS2741; литерал с лишним полем courier даёт ошибку TS2353, но если положить его в переменную, ошибки не будет." caption="Проверяется форма: нужные поля есть, лишние допустимы, кроме литерала на месте." />

**Лишние свойства.** Правило для объекта-литерала, записанного прямо в месте присваивания или в вызове функции, строже: любое поле вне описания считается ошибкой. Это защищает от опечаток. Напишете `custmer` вместо `customer` — компилятор скажет, что такого поля нет. Но если сначала положить объект в переменную, а потом передать её, лишние поля пропускаются: форма подходит. Запустите пример и убедитесь, что `shelf` остаётся в объекте.

<Playground example="excess" />

**Наследование.** Если у двух типов общие поля, не копируйте их. Выделите общий тип и расширьте его:

```ts
interface Person { id: number; name: string }
interface Courier extends Person { vehicle: string }
```

`Courier` получает `id` и `name` от `Person` и добавляет своё поле.

**Словарь.** Иногда ключи заранее неизвестны, например остатки по артикулам. Для этого есть индексная сигнатура (index signature): `{ [sku: string]: number }` — любые строковые ключи, значения числа.

**readonly живёт только до компиляции.** После сборки типов нет, и запрет исчезает вместе с ними. Защититься в рантайме можно через `Object.freeze`.

<Playground example="readonly-runtime" />

<Note>

`readonly` действует на одном уровне: поле нельзя заменить, но объект внутри можно менять. Если `address` помечен `readonly`, присвоить новый адрес нельзя, а поменять `order.address.city` можно.

</Note>

## Типичные ошибки

Сообщения получены запуском компилятора TypeScript 6.0.3 в режиме `strict`.

**1. Не хватает обязательного поля.**

<Wrong>

```ts
interface Order { readonly id: number; status: string; comment?: string }
const order: Order = { id: 1 };
```

</Wrong>

```text
error TS2741: Property 'status' is missing in type '{ id: number; }' but required in type 'Order'.
```

Компилятор называет и недостающее поле, и тип, который его требует. Добавьте `status` или сделайте поле необязательным, если оно действительно может отсутствовать.

**2. Лишнее поле в литерале.**

<Wrong>

```ts
const order: Order = { id: 1, status: "new", extra: true };
```

</Wrong>

```text
error TS2353: Object literal may only specify known properties, and 'extra' does not exist in type 'Order'.
```

Чаще всего это опечатка в имени. Если поле нужно, добавьте его в описание типа.

**3. Опечатка при чтении поля.**

<Wrong>

```ts
order.statuss;
```

</Wrong>

```text
error TS2551: Property 'statuss' does not exist on type 'Order'. Did you mean 'status'?
```

Хорошее сообщение: компилятор сам предлагает исправление.

**4. Присваивание в поле только для чтения.**

<Wrong>

```ts
order.id = 2;
```

</Wrong>

```text
error TS2540: Cannot assign to 'id' because it is a read-only property.
```

Вместо правки создайте новый объект с нужными значениями: `{ ...order, status: "paid" }`.

**5. Необязательное поле прочитали как обязательное.**

<Wrong>

```ts
const length = order.comment.length;
```

</Wrong>

```text
error TS18048: 'order.comment' is possibly 'undefined'.
```

Поле может отсутствовать. Проверьте его перед использованием.

**6. Не тот тип значения в поле.**

```text
error TS2322: Type 'string' is not assignable to type 'number'.
```

Такое сообщение появится для `{ id: "1", status: "new" }`: поле `id` ждёт число.
