## Контекст

Тикет LOG-337. На складе печатают наклейки на посылки, а диспетчеру нужна сводка по партии. Типы `Address` и `Parcel` уже описаны, их менять нельзя. Нужно описать тип сводки и две функции.

## Цель

В `index.ts` опишите интерфейс `Summary` и реализуйте `formatLabel(parcel)` и `summarize(parcels)`.

`Summary` содержит три обязательных числовых поля: `count` (сколько посылок), `totalWeightKg` (суммарный вес), `fragileCount` (сколько хрупких).

Наклейка `formatLabel` собирается из частей, разделённых ` — `:

1. `№{id} {recipient}, {city}, {street}` и, если указана квартира, `, кв. {apartment}`;
2. `{weightKg} кг`;
3. `ХРУПКОЕ`, только если `fragile` равно `true`;
4. заметка `note`, если она указана.

Пример: `№12 Анна Соколова, Казань, Баумана 5, кв. 7 — 2.5 кг — ХРУПКОЕ — позвонить за час`.

## Критерии приёмки

- `formatLabel` собирает строку по правилам выше; части без значения не выводятся и не оставляют лишних разделителей.
- `summarize([])` возвращает `{ count: 0, totalWeightKg: 0, fragileCount: 0 }`.
- Хрупкими считаются посылки, у которых `fragile` строго равно `true`. Если поле не указано или равно `false`, посылка не хрупкая.
- Все поля `Summary` обязательны, типы чисел.
- Код компилируется в режиме `strict` без ошибок, без `!` и `as`.

## Ограничения

- Типы `Address` и `Parcel` не меняйте.
- Не используйте `any`, `as` и восклицательный знак после значения.
