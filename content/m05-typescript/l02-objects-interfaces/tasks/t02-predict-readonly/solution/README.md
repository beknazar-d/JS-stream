# Разбор

После компиляции остаётся такой код: `readonly`, `?` и `as` исчезли.

1. `parcel.id` даёт `99`. Запись `(parcel as { id: number }).id = 99` обошла запрет: приведение типа убирает `readonly` в глазах компилятора, а в рантайме запрета не было никогда.
2. `copy.id` даёт `1`. Копия `{ ...parcel, weightKg: 5 }` сделана до записи, это другой объект.
3. `parcel.note` даёт `undefined`: поле не задано.
4. `parcel.note ?? "без заметки"` даёт запасное значение, потому что слева `undefined`.
5. `Object.keys(copy).length` даёт `2`: в копии поля `id` и `weightKg`. Поля `note` нет, необязательное свойство не создаётся само.
6. `JSON.stringify(parcel)` даёт `{"id":99,"weightKg":2}`.

Вывод: `readonly` помогает не ошибиться в своём коде, но не защищает от данных и приведений типов. Для защиты в рантайме есть `Object.freeze`.
