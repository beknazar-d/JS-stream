# Разбор

Типы выводятся из примеров по простому правилу: что есть везде — обязательное, чего нет хотя бы в одном — необязательное.

1. В `PickupPoint` обязательны `city` и `street`, а `floor` и `intercom` необязательные: во втором примере их нет.
2. `PickupRequest` собирает вложенные типы: `pickup: PickupPoint`, `cargo: Cargo`. Так типы читаются проще, а `Cargo` можно использовать отдельно.
3. `contacts` обязателен: во втором примере он есть, просто пустой. Пустой массив — допустимое значение типа `string[]`, а отсутствующее поле — это другое.
4. Этаж проверяется через `!== undefined`. Проверка `if (floor)` выбросила бы этаж `0`, и в сводке пропала бы часть, которая указана.
5. `totalWeight` — цикл с накоплением. Пустой список даёт `0`.

## Вопросы, которые стоило задать

- Может ли список контактов быть пустым, и как работать с такой заявкой?
- В каких единицах вес и может ли он приходить строкой?
- Может ли `cargo` отсутствовать?
- Нужен ли комментарий в сводке и может ли он быть пустым?

## Допущения в эталоне

Вес — число в килограммах, `cargo` есть всегда, пустой массив контактов допустим. Проверка формата входящих данных (что JSON действительно такой) вынесена в отдельную задачу: типы не проверяют данные в рантайме.
