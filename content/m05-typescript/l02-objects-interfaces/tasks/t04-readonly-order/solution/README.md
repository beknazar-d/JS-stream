# Разбор

1. Слово `readonly` ставится перед каждым полем. После этого обе функции из заготовки перестают собираться: `TS2540: Cannot assign to 'status' because it is a read-only property`. Компилятор сам показал, где заказ менялся.
2. Вместо изменения функции возвращают копию: `{ ...order, status: "paid" }`. Spread копирует все поля, а следующее за ним поле перезаписывает одно значение. Исходный объект не затронут.
3. Тип параметров и результата остался прежним: `Order`. Поведение для вызывающего кода сохранилось, изменилась только гарантия: случайная запись теперь не скомпилируется.

`readonly` проверяется на этапе компиляции. В рантайме его нет, поэтому настоящую копию мы делаем сами. Это же защита от обхода через `Object.assign` и `as`: компилятор такие места не видит, а ревью должно видеть.

`readonly` действует на один уровень. Если бы внутри заказа был вложенный объект, его поля пришлось бы защищать отдельно.
