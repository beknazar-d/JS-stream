## Контекст

Тикет LOG-325. В отчёте сегодня показали не ту сумму: функция скидки изменила заказ, который лежал в общем списке, и все остальные экраны увидели новую цену. Решили запретить менять заказ после создания: правки возвращают новый объект, а компилятор не даёт случайно присвоить значение полю.

## Цель

В `index.ts` сделайте поля заказа доступными только для чтения и перепишите функции так, чтобы они возвращали новый заказ, а исходный не меняли.

## Критерии приёмки

- Все четыре поля `Order` (`id`, `createdAt`, `status`, `total`) только для чтения. Присваивание в любое из них — ошибка типов.
- `markPaid(order)` возвращает новый заказ со `status: "paid"`; исходный заказ остаётся прежним; остальные поля сохраняются.
- `applyDiscount(order, percent)` возвращает новый заказ с суммой, уменьшенной на `percent` процентов и округлённой до целого (`Math.round`); исходный заказ остаётся прежним.
- Типы параметров и результатов функций не меняются.

## Ограничения

- Не используйте `any`, `as` и `Object.assign` для записи в исходный объект.
- Копию объекта проще всего получить через spread: `{ ...order, status: "paid" }`.
