# Разбор

Идея в три шага: сбросить, проверить, показать.

1. **Сброс.** `setCustomValidity('')` снимает прежнее своё сообщение. Если этого не сделать, поле останется «неверным» навсегда: пока в нём есть непустое сообщение, `validity.valid` равно `false`, даже когда значение уже исправили. Это самая частая ошибка с `setCustomValidity`. Сбрасываем и в начале `validate`, и при вводе в поле (событие `input` всплывает до формы).
2. **Проверка.** После сброса `validity` описывает только встроенные правила. Флаги `valueMissing`, `typeMismatch`, `patternMismatch` показывают причину. Ищем первый поднятый флаг среди тех, для которых у поля есть сообщение.
3. **Показ.** Текст попадает в абзац под полем через `textContent`. Поле получает `aria-invalid="true"` (скринридер скажет «недопустимое значение») и `aria-describedby` с `id` абзаца (скринридер прочитает текст ошибки вместе с названием поля). Фокус уходит на первое неверное поле.

`fields.filter((field) => !validate(field))` проверяет все поля, а не только первое: пользователь видит все ошибки сразу. Если бы вместо `filter` стоял `some` или `find`, цикл остановился бы на первой ошибке.

`reportValidity` здесь не нужен: он показывает пузырь браузера, а мы выводим сообщения сами.
