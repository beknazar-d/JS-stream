# Разбор

Браузер умеет проверять поля сам. Это называется встроенной проверкой (constraint validation). Каждое правило из тикета — атрибут.

- `required` — поле нельзя оставить пустым (`validity.valueMissing`).
- `type="email"` — значение должно быть похоже на адрес (`validity.typeMismatch`).
- `pattern` — регулярное выражение; оно проверяет значение целиком, якоря `^` и `$` добавлять не нужно (`validity.patternMismatch`). В HTML-атрибуте слэши в `\+7\d{10}` пишутся как есть, ничего не экранируется дважды. `title` показывается в подсказке браузера.
- `type="number"` с `min`, `max` и шагом по умолчанию (1): значения 0 и 11 дают `rangeUnderflow` и `rangeOverflow`, а 1.5 — `stepMismatch`.
- `minlength` и `maxlength` ограничивают длину при вводе пользователем. Скриптом такое значение не проверить, поэтому тесты смотрят на сами атрибуты.

Если форма невалидна, браузер не посылает событие `submit`: он показывает подсказку у первого неверного поля. Атрибут `novalidate` отключает эту проверку при отправке, поэтому в форме заказа он не нужен.
