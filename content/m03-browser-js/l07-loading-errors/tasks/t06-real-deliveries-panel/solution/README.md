# Разбор

## Вопросы, которые стоило задать

1. **Тексты сообщений.** Есть ли утверждённые формулировки? Эти слова увидят люди, и их обычно согласовывают.
2. **Старый список при ошибке.** Показывать последние известные данные или убрать? Для доставок устаревшие данные могут ввести в заблуждение, поэтому мы очищаем список. Но у другого заказчика может быть наоборот.
3. **Код ошибки.** Показывать пользователю «503» или нет? Для менеджера и поддержки это полезно.
4. **Автоповтор.** Повторять запрос автоматически или только по кнопке? Тикет говорит «дайте мне повторить», мы поняли это как ручной повтор.
5. **Состав строки.** Кроме города, что показывать? Мы добавили номер и статус.

Ответы записываются в `assumptions.txt`, чтобы их можно было подтвердить, не читая код.

## Как устроено решение

- **Одна функция на все исходы.** `loadDeliveries` вызывается при открытии страницы, по «Обновить» и по «Повторить».
- **Защита от параллельных запросов.** Флаг `loading` включается в начале и выключается в `finally`. Пока он поднят, новые вызовы просто выходят. Без него два запроса могли бы обогнать друг друга, и более старый ответ перезаписал бы свежий.
- **Таймаут.** Контроллер передаёт `signal` в `fetch`, таймер на 800 мс вызывает `abort()`. По имени ошибки `AbortError` отличаем таймаут от сбоя сети.
- **`finally`.** Сбрасывает таймер и флаг при любом исходе: успех, ошибка статуса, пустой список, таймаут, сеть. Если бы флаг сбрасывался только в успешной ветке, одна ошибка заблокировала бы страницу навсегда.
- **Пустой список** — отдельный исход с сообщением.
- **Доступность.** `#status` — живая область, поэтому новые сообщения озвучиваются. Все тексты данных идут через `textContent`.
