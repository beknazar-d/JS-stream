## Зачем это в работе

Вторник, утро. Менеджер «Домотеки» открывает панель доставок. Страница белая. Он ждёт, обновляет, закрывает вкладку и звонит разработчику: «У вас всё сломалось». На самом деле сервер просто ответил ошибкой 503, а страница об этом промолчала.

Сеть ненадёжна. Запрос может идти долго, упасть или вернуть пустой список. Хороший интерфейс всегда говорит человеку, что происходит сейчас, и предлагает, что делать дальше. В этом уроке вы научите страницу это делать.

## Объяснение

У любого списка, который приходит с сервера, четыре состояния (states).

1. **Загрузка (loading).** Запрос идёт. Человек видит «Загружаем…».
2. **Ошибка (error).** Не получилось. Человек видит причину и кнопку «Повторить».
3. **Пусто (empty).** Всё хорошо, но данных нет. Человек видит «Доставок на сегодня нет».
4. **Список (list).** Данные есть. Сообщения не нужны.

Ошибка бывает трёх видов, и сообщения у них разные.

- **Плохой статус.** Сервер ответил, но с 503 или 500. Пишем «Не удалось загрузить» и статус.
- **Нет сети.** `fetch` выбросил ошибку `TypeError`. Пишем «Нет соединения с сервером».
- **Слишком долго.** Сервер молчит. Здесь нужен таймаут (timeout) — предел ожидания, после которого запрос отменяют. Пишем «Сервер отвечает слишком долго».

Отменяют запрос через `AbortController`. Это «пульт отмены»: вы создаёте его, передаёте в `fetch` его сигнал (`signal`) и в нужный момент нажимаете `abort()`. Момент выбирает таймер: `setTimeout(функция, миллисекунды)` вызывает функцию один раз через заданное время, а `clearTimeout(таймер)` отменяет его, если ждать уже не нужно.

Аналогия: вы заказываете такси. Приложение пишет «Ищем машину» (загрузка). Если машин нет, оно говорит «Не нашли, попробовать ещё раз?» (ошибка и «Повторить»). Если вы ждёте уже пять минут, приложение само отменяет заказ и предупреждает вас (таймаут). Приложение не молчит ни в одном случае.

## Пример

Разметка с живой областью для сообщений и скрытой кнопкой.

```html
<p id="status" role="status"></p>
<button id="retry" type="button" hidden>Повторить</button>
<ul id="deliveries"></ul>
```

Функция загрузки с таймаутом и всеми исходами.

```js
const TIMEOUT_MS = 800;
const list = document.querySelector('#deliveries');
const status = document.querySelector('#status');
const retry = document.querySelector('#retry');

function showError(message) {
  status.textContent = message;
  retry.hidden = false;
}

async function loadDeliveries() {
  status.textContent = 'Загружаем доставки…';
  retry.hidden = true;

  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), TIMEOUT_MS);
  try {
    const response = await fetch('/api/deliveries', { signal: controller.signal });
    if (!response.ok) {
      showError('Не удалось загрузить доставки (' + response.status + ')');
      return;
    }
    const deliveries = await response.json();
    list.textContent = '';
    if (deliveries.length === 0) {
      status.textContent = 'Доставок на сегодня нет';
      return;
    }
    status.textContent = '';
    for (const delivery of deliveries) {
      const item = document.createElement('li');
      item.textContent = delivery.city + ' — ' + delivery.status;
      list.append(item);
    }
  } catch (error) {
    if (error.name === 'AbortError') showError('Сервер отвечает слишком долго');
    else showError('Нет соединения с сервером');
  } finally {
    clearTimeout(timer);
  }
}

retry.addEventListener('click', loadDeliveries);
loadDeliveries();
```

Блок `finally` выполняется всегда: после успеха, после ошибки и после `return` внутри `try`. Поэтому таймер сбрасывается в одном месте.

## Как это работает

Схема показывает переходы между состояниями.

<Figure src="states.svg" alt="Схема из четырёх блоков. Из блока «Загрузка» три стрелки. Успех с данными ведёт в блок «Список» со статусом без текста. Успех с пустым массивом ведёт в блок «Пусто» с сообщением, что данных нет. Ошибка статуса, сбой сети или таймаут ведут в блок «Ошибка» с текстом и кнопкой «Повторить». Из «Ошибки» пунктирная стрелка с подписью «кнопка Повторить» возвращает в «Загрузку»." caption="Из загрузки есть три выхода, а из ошибки один путь назад: кнопка «Повторить»." />

Правила, которые стоит запомнить.

1. **Каждое состояние задаёт всё сразу.** Текст статуса, видимость кнопки, содержимое списка. Так не бывает «ошибка, но кнопки нет».
2. **Перед запросом ставьте «загрузку».** Иначе после повторного нажатия на экране останется старая ошибка.
3. **Таймаут = контроллер + таймер.** Таймер вызывает `abort()`, `fetch` завершается ошибкой `AbortError`, `catch` показывает нужное сообщение.
4. **Таймер сбрасывайте в `finally`.** Иначе он сработает после успешного ответа.
5. **Не запускайте второй запрос, пока идёт первый.** Достаточно флага `loading`: в начале `if (loading) return;`, а в `finally` `loading = false`. Иначе старый ответ может прийти позже нового и затереть его.
6. **Скринридер озвучивает только живые области.** Элемент для сообщений получает `role="status"` или `aria-live="polite"` заранее. Тогда любое изменение его текста будет прочитано. Список на время загрузки можно пометить `aria-busy="true"`.
7. **Фокус на «Повторить».** После ошибки удобно перевести фокус на кнопку. Но у скрытого элемента (`hidden`) фокус не получить: сначала `retry.hidden = false`, потом `retry.focus()`.

<Note>

Здесь сеть ненадёжна «понарошку»: сервер заданий отвечает по списку, например сначала 503, потом 200. Так можно проверять кнопку «Повторить» одним и тем же набором данных.

</Note>

## Типичные ошибки

**1. Нет `catch`, и в консоли необработанная ошибка.** Если запрос не дошёл до сервера, а ловить некому, страница так и остаётся в «Загрузке…», а консоль пишет:

```text
TypeError: Failed to fetch
```

**2. Отмену приняли за поломку сети.** Если не проверить имя ошибки, и таймаут, и отключённый интернет покажут одно сообщение. Для отмены Chrome пишет:

```text
AbortError: signal is aborted without reason
```

Проверяйте `error.name === 'AbortError'`.

**3. Таймер не сброшен.** Ответ пришёл за 100 мс, а через 800 мс на странице появляется «Сервер отвечает слишком долго». Сбрасывайте `clearTimeout` в `finally`.

**4. Запрос не отменяется.** Вы показали сообщение по таймеру, но `signal` в `fetch` не передали. Запрос висит и позже перезапишет страницу. Отменять нужно сам запрос.

**5. Флаг `loading` остаётся поднятым.** Он сбрасывается только в успешной ветке. После первой ошибки страница перестаёт загружаться. Сбрасывайте флаг в `finally`.

**6. Тот же контроллер использован дважды.** После `abort()` его сигнал отменён навсегда. Новый запрос с этим сигналом сразу завершится ошибкой `AbortError`. Для каждой попытки создавайте новый `AbortController`.

**7. Кнопка «Повторить» вызывает функцию сразу.** Запись `addEventListener('click', load())` запускает загрузку при подключении обработчика. Передавайте функцию без скобок.

**8. Сообщения тихие.** Текст ошибки появился, а `role="status"` нет. Зрячий видит, незрячий нет.

## Итог

Что вы теперь умеете:

- показывать четыре состояния списка: загрузка, ошибка, пусто, список;
- различать плохой статус, сбой сети и таймаут и писать для каждого свой текст;
- отменять запрос через `AbortController` и сбрасывать таймер в `finally`;
- делать кнопку «Повторить» и защищаться от параллельных запросов;
- озвучивать состояния для скринридера через `role="status"` и `aria-busy`.

Пока страница забывала всё при перезагрузке: корзина, фильтры, выбранное окно доставки пропадали. В следующем уроке вы научите её запоминать данные в браузере с помощью Web Storage и аккуратно разбирать то, что там лежит.
