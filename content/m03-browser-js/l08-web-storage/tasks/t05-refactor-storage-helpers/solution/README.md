# Разбор

Повторялись две пары действий: «прочитать JSON с запасным значением» и «записать JSON». Теперь это две функции.

```js
function readJson(key, fallback) {
  try {
    const value = JSON.parse(localStorage.getItem(key));
    return value === null ? fallback : value;
  } catch {
    return fallback;
  }
}
```

Здесь два защитных слоя.

1. `try/catch` ловит `SyntaxError` на обрезанном или чужом тексте.
2. Проверка `value === null` нужна для отсутствующего ключа: `getItem` вернёт `null`, а `JSON.parse(null)` не бросит ошибку, а вернёт `null`. Без проверки на первом визите вместо `[]` придёт `null`.

`writeJson` в одну строку записывает `JSON.stringify(value)`.

Пользы три. Защита от повреждённых данных написана один раз. Формат хранения (JSON) известен только помощникам: если завтра понадобится версия формата или срок хранения, правка в одном месте. Код страницы теперь читается как намерение: `readJson('favorites', [])`.

Что не менялось: рендер, обработчики и порядок работы остались прежними, поэтому поведение страницы сохранилось.
