# Разбор

Структура решения: одно состояние, одна функция отрисовки.

1. **Состояние — массив `cart`** с позициями `{ id, qty }`. Цены и названия в нём не хранятся: страница берёт их из каталога (словарь `catalog`). Так цена на странице остаётся единственным источником истины, а в хранилище лежит минимум данных.
2. **Любое изменение идёт через `change`:** вычислить новый массив, сохранить, перерисовать. Поэтому нельзя забыть сохранить в одном из обработчиков.
3. **`render` строит список заново.** Для каждой позиции создаются элементы через `createElement` и `textContent`: в разметку не попадает ни одного куска HTML из данных.
4. **`loadCart` проверяет данные из хранилища** тремя шагами: `try/catch` вокруг `JSON.parse`, `Array.isArray`, `filter` по форме позиции.
5. **Панель.** `hidden`, `aria-expanded` и `sessionStorage` меняются в одной функции `setOpen`, поэтому не расходятся. `sessionStorage` подходит: состояние нужно на время вкладки, а не навсегда.

## Вопросы, которые стоило задать

1. Что делает «минус» при количестве 1: убирает позицию, блокируется или спрашивает подтверждение? В решении принято допущение «убирает».
2. Есть ли ограничение на количество одного товара (остаток на складе, лимит на заказ)? Пока лимита нет, но `qty` проверяется только на положительное целое.
3. Что делать с позицией, которой нет в каталоге (товар сняли с продажи)? Решение молча не показывает её. Лучше спросить: сообщить покупателю или удалить из хранилища.
4. Нужен ли срок жизни корзины: должна ли она очищаться через месяц?
5. Что если корзина открыта в двух вкладках? Нужна ли синхронизация между ними (событие `storage`)?
