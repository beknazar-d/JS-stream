## Зачем это в работе

Покупательница «Домотеки» выбрала чайник и блендер, ушла читать отзывы, закрыла вкладку. На следующий день открыла сайт, а корзина пустая. Она не вернётся: проще купить в другом магазине.

Страница после перезагрузки забывает всё: переменные живут только в памяти. Чтобы корзина пережила перезагрузку, её нужно где-то записать. Для небольших данных в браузере есть готовое место: Web Storage («веб-хранилище»). Без сервера и без регистрации.

## Объяснение

Web Storage — это маленькое хранилище «ключ — значение» внутри браузера. Оно привязано к сайту: чужой сайт ваши данные не увидит. Хранилищ два.

- `localStorage` живёт между визитами. Закрыли браузер, включили через неделю, данные на месте.
- `sessionStorage` живёт, пока открыта вкладка. Закрыли вкладку, данные пропали. У каждой вкладки своё.

Методы у них одинаковые.

- `setItem(ключ, значение)` — записать.
- `getItem(ключ)` — прочитать. Если ключа нет, вернётся `null`.
- `removeItem(ключ)` — удалить один ключ.
- `clear()` — удалить всё.

Главное правило: хранилище держит только строки. Число, массив и объект оно превращает в строку само, и обычно не так, как вы ожидаете.

Аналогия: шкафчик в раздевалке. Ключ — номер шкафчика, значение — записка внутри. Записка всегда бумажная: хотите положить туда список, перепишите его текстом. Для этого в JavaScript есть `JSON.stringify` (объект в строку) и `JSON.parse` (строка обратно в объект). `localStorage` — шкафчик, который вам оставляют на месяцы. `sessionStorage` — шкафчик на один визит.

## Пример

Запоминаем сортировку каталога. Это самый простой случай: значение уже строка.

```js
const sort = document.querySelector('#sort');

const saved = localStorage.getItem('sort');
if (saved) sort.value = saved;

sort.addEventListener('change', () => {
  localStorage.setItem('sort', sort.value);
});
```

</Note>

## Как это работает

<Figure src="storage-cycle.svg" alt="Схема: массив в памяти страницы превращается в строку через JSON.stringify и setItem и попадает в хранилище; обратно идёт через getItem и JSON.parse. Ниже два блока: localStorage живёт между визитами и общий для вкладок, sessionStorage живёт, пока открыта вкладка." caption="Данные проходят через строку: туда JSON.stringify, обратно JSON.parse." />

Три правила на каждый день.

1. **Только строки.** `setItem('qty', 3)` запишет `"3"`, а `getItem` вернёт строку. Всё, что не строка, превращайте сами: числа через `Number(...)`, структуры через JSON.
2. **Данным из хранилища доверять нельзя.** Их мог записать старый код, расширение браузера или сам покупатель в консоли. Читайте в три шага: `try/catch` вокруг `JSON.parse`, проверка формы (`Array.isArray`, нужные поля), значение по умолчанию.
3. **Запасное значение — для отсутствующего ключа.** `getItem` вернёт `null`, а `JSON.parse(null)` не бросает ошибку, а возвращает `null`. Без проверки вместо пустой корзины у вас окажется `null`.

Что ещё полезно знать.

- JSON сохраняет не всё. `Date` превращается в строку, `undefined` и функции пропадают, `NaN` становится `null`. Даты после чтения нужно создавать заново.
- Лимит объёма — порядка 5 МБ на сайт, зависит от браузера. Это место для корзины и настроек, а не для каталога на тысячи товаров. Если лимит исчерпан, `setItem` бросает ошибку.
- В приватном режиме и при запрещённых данных сайта браузер может отказать в доступе. Код, который не должен ломать страницу, оборачивайте в `try/catch`.
- Хранилище синхронное: каждый вызов блокирует страницу. Большие объёмы там держать нельзя, а часто писать не стоит.
- Не храните пароли и токены доступа. Любой скрипт на вашей странице прочитает хранилище. Для корзины и сортировки это не страшно, для секретов — опасно.

## Типичные ошибки

**1. Записали массив без `JSON.stringify`.** В хранилище лежит `[object Object]`, а при чтении:

<Wrong>

```js
localStorage.setItem('cart', cart);
const again = JSON.parse(localStorage.getItem('cart'));
```

</Wrong>

<Right>

```js
localStorage.setItem('cart', JSON.stringify(cart));
const again = JSON.parse(localStorage.getItem('cart'));
```

</Right>

Сообщение консоли в Node.js 22 при разборе такой строки:

```text
SyntaxError: "[object Object]" is not valid JSON
```

**2. Битые данные в `JSON.parse`.** Обрезанный текст:

```text
SyntaxError: Expected property name or '}' in JSON at position 1 (line 1 column 2)
```

Пустая строка:

```text
SyntaxError: Unexpected end of JSON input
```

Слово `undefined`, которое получается, если записать в хранилище значение `undefined` без JSON:

```text
SyntaxError: "undefined" is not valid JSON
```

Лечение одно: `try/catch` и значение по умолчанию.

**3. Сложили число из хранилища как есть.** Записали `qty = 3`, прочитали `"3"`, прибавили единицу и получили `"31"`. Превращайте явно: `Number(localStorage.getItem('qty'))`.

**4. Забыли про отсутствующий ключ.** `JSON.parse(localStorage.getItem('cart')).length` на первом визите падает, потому что `JSON.parse(null)` вернул `null`. В Node.js 22 это такое сообщение:

```text
TypeError: Cannot read properties of null (reading 'length')
```

**5. Слишком много данных.** В Chromium при переполнении лимита `setItem` бросает:

```text
QuotaExceededError: Failed to execute 'setItem' on 'Storage': Setting the value of 'a' exceeded the quota.
```

**6. Проверка формы пропущена.** JSON корректен, но это объект вместо массива. Ошибка случается позже и в другом месте: `data.filter is not a function`. Проверяйте `Array.isArray` сразу при чтении.

## Итог

Что вы теперь умеете:

- хранить настройки и корзину в `localStorage`, а данные на время вкладки в `sessionStorage`;
- помнить, что хранилище держит только строки, и превращать объекты через `JSON.stringify` и `JSON.parse`;
- читать данные безопасно: `try/catch`, проверка формы, значение по умолчанию;
- отличать, что хранить локально (корзина, сортировка), а что нет (пароли, большие данные).

До сих пор состояние страницы жило в памяти или в хранилище, а адрес оставался неизменным. Но покупатель хочет отправить другу ссылку на каталог с уже выбранными фильтрами. Для этого состояние нужно положить в адрес страницы. Этим займёмся в следующем уроке: URLSearchParams и History API.
