## Зачем это в работе

Маркетолог «Домотеки» собрал подборку: чайники в наличии, сначала дешёвые. Он хочет отправить её в рассылке одной ссылкой. Клиент нажимает и сразу видит подборку, а не общий каталог, в котором надо повторять выбор.

Ещё сценарий. Покупатель выбрал категорию, добавил фильтр, посмотрел результат и нажал «Назад». Он ждёт прежний набор фильтров. Если страница не записывает шаги в историю браузера, «Назад» выбросит его вообще из каталога.

Оба сценария решает одно: состояние страницы живёт в её адресе. Для этого нужны две вещи: умение читать и собирать адрес (`URL` и `URLSearchParams`) и умение записывать шаги в историю (History API).

## Объяснение

Адрес страницы — это строка из частей. Для нас важны три.

- путь (`pathname`): `/catalog`;
- строка запроса (`search`): `?category=kettles&sort=price-asc`;
- якорь (`hash`): `#reviews`.

Строка запроса состоит из пар «имя=значение» через `&`. Вручную её резать не нужно: объект `URLSearchParams` («параметры строки запроса») разбирает и собирает её сам. Он кодирует пробелы, амперсанды и русские буквы, а при чтении раскодирует их.

История браузера — стопка записей. Каждая запись помнит адрес и, если вы попросили, ещё объект состояния (`state`). Методы объекта `history`:

- `pushState(state, title, url)` добавляет новую запись и меняет адрес. Страница не перезагружается. Второй аргумент, заголовок, браузеры игнорируют: передают пустую строку;
- `replaceState(state, title, url)` подменяет текущую запись;
- `history.back()` и `history.forward()` двигаются по стопке, как кнопки браузера.

Когда человек переходит по истории, браузер сообщает об этом событием `popstate` («извлечение из истории»). В `event.state` лежит объект, который вы записали в эту запись, или `null`, если для неё состояния не было.

Аналогия: стопка закладок в книге. `pushState` кладёт новую закладку поверх. «Назад» перекладывает вас на предыдущую. Если вы положили новую закладку, пока стояли посередине стопки, все закладки впереди выбрасываются.

Обратите внимание на две вещи. Значения по умолчанию в адрес не попадают: без фильтров адрес чистый, `/catalog`. И неизвестная категория `toaster` из ссылки заменяется на значение по умолчанию: адрес мог набрать кто угодно, ему нельзя верить.

Страница с историей выглядит так.

```js
function applyFilters(filters) {
  render(filters);
  history.pushState(filters, '', buildUrl(filters));
}

window.addEventListener('popstate', (event) => {
  const filters = event.state ?? DEFAULTS;
  showControls(filters);
  render(filters);
});
```

Функция `applyFilters` вызывается, когда человек поменял фильтр: рисует список и записывает шаг. Обработчик `popstate` вызывается, когда человек перешёл по истории: он только показывает прежнее состояние.

<Note>

Как читать адрес в настоящем браузере: `new URLSearchParams(location.search)`. В тренажёре страница живёт в изолированной песочнице, и её `location` не меняется. `pushState`, `replaceState`, `back` и `popstate` работают как настоящие, а адрес после них тесты читают специальной функцией `currentUrl()`. Поэтому в заданиях адрес всегда передаётся функции строкой: `parseFilters(url)`. Это не обходной путь, а удобная привычка: такую функцию легко проверить без браузера.

</Note>

Последние две строки вывода показывают главное. После возврата на запись `kettles` новый `pushState` стёр запись `inStock=1`. Кнопка «Вперёд» стала недоступна.

Правила, которые стоит запомнить.

1. **`pushState` — на действие человека.** Выбрал фильтр: записывайте. Перешёл по истории: только показывайте, ничего не записывайте.
2. **Состояние — маленький объект.** Только данные, которые браузер умеет копировать: числа, строки, массивы, обычные объекты. Функции и элементы страницы записать нельзя.
3. **Адрес — для людей и ссылок, состояние — для вашего кода.** Если страницу открыли по готовой ссылке, состояния нет, есть только адрес. Поэтому при загрузке адрес разбирают через `parseFilters`, а после перехода по истории берут `event.state`.
4. **`replaceState` — когда шаг не нужен в истории.** Например, поправили адрес при загрузке или записываете каждое нажатие клавиши в поиске. Каждая буква не должна создавать запись.
5. **Адрес только своего сайта.** Другой домен в `pushState` запрещён браузером.

## Типичные ошибки

**1. Склейка строк вместо `URLSearchParams`.** Поиск «кофе & чай» ломает адрес.

<Wrong>

```js
history.pushState(null, '', '?q=' + text);
```

</Wrong>

<Right>

```js
const params = new URLSearchParams({ q: text });
history.pushState(null, '', '?' + params);
```

</Right>

**2. Относительный адрес без базы.** Конструктор `URL` не принимает путь без базового адреса:

```text
TypeError: Invalid URL
```

Решение: второй аргумент, `new URL(url, 'https://domoteka.example')`.

**3. `pushState` внутри `popstate`.** Возврат по истории создаёт новую запись, «Вперёд» перестаёт работать. Это одна из самых частых ловушек.

**4. Забыли про `state === null`.** У первой записи истории состояния нет. Код `event.state.category` падает:

```text
TypeError: Cannot read properties of null (reading 'category')
```

Поставьте запасное значение: `event.state ?? DEFAULTS`.

**5. Состояние, которое нельзя скопировать.** В состояние положили функцию. Chromium отвечает:

```text
DataCloneError: Failed to execute 'pushState' on 'History': () => 1 could not be cloned.
```

**6. Чужой адрес.** Попытка записать в историю адрес другого сайта:

```text
SecurityError: Failed to execute 'pushState' on 'History': A history state object with URL 'https://evil.example/' cannot be created in a document with origin 'https://shop.test' and URL 'https://shop.test/catalog'.
```

**7. Вера адресу.** Параметр `?category=toaster` пришёл из письма с опечаткой. Проверяйте значения по списку допустимых, как данные из `localStorage`.

## Итог

Что вы теперь умеете:

- читать и собирать адрес через `URL` и `URLSearchParams`, не склеивая строки;
- превращать адрес в проверенные фильтры и фильтры в чистый адрес;
- записывать шаги в историю через `pushState` и подменять запись через `replaceState`;
- восстанавливать состояние по `popstate` из `event.state`, не создавая лишних записей;
- объяснять, чем адрес в тренажёре отличается от настоящего `location`.

Каталог умеет хранить состояние в адресе. Но товаров в нём тысячи, и грузить их все сразу нельзя. Пока человек листает, страница должна подгружать следующую порцию, а картинки ниже экрана не нужно скачивать вообще. Для этого браузер умеет сообщать, что элемент появился на экране. В следующем уроке разберём Intersection Observer.
