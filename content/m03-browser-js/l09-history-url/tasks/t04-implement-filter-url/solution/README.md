# Разбор

## parseFilters

1. `new URL(url, base)` понимает и полный адрес, и относительный путь, и просто `?sort=rating`: относительный адрес достраивается от `base`. Базовый адрес выдуманный: нам нужны только параметры. Якорь `#...` в `searchParams` не попадает.
2. `try/catch` нужен для мусорного адреса вроде `http://`: конструктор `URL` на нём бросает ошибку. Функция из ТЗ не должна падать.
3. Каждое значение проверяется по списку допустимых: адрес пришёл снаружи и верить ему нельзя. Так же мы проверяли данные из хранилища.
4. `inStock` сравнивается со строкой `'1'`: все параметры адреса — строки.
5. Повтор параметра обрабатывается сам: `get` возвращает первое значение.

## buildUrl

`URLSearchParams` собирает строку запроса и кодирует значения. В адрес попадает только то, что отличается от значений по умолчанию: чистая ссылка `/catalog` означает «без фильтров», а `parseFilters('/catalog')` вернёт те же значения по умолчанию. Поэтому цикл `parseFilters(buildUrl(f))` даёт нормализованные фильтры.

## Почему функции принимают строку

В настоящем браузере адрес читают из `location.search`. Но функция, которая принимает строку, проще: её можно проверить без браузера, вызвать для адреса из `event.state` или из ссылки на странице. Тренажёр работает так же: в песочнице `location` не меняется, и адрес всегда передаётся функции явно.
