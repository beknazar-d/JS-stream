## Контекст

Тикет DOM-187 от менеджера по маркетингу «Домотеки»:

> Хочу отправлять клиентам ссылки вроде «чайники в наличии, сначала дешёвые», и чтобы человек видел подборку сразу. И чтобы кнопка „Назад“ в браузере возвращала прошлый набор фильтров, а не выкидывала из каталога. Список товаров берите из API.

Фильтры уже есть в разметке, функции `parseFilters` и `buildUrl` готовы (вы написали их в предыдущих заданиях). Осталось соединить всё в рабочую страницу: загрузка, фильтрация, сортировка, запись в историю и восстановление по «Назад».

## Цель

Допишите `script.js`: загрузите товары из `/api/products`, показывайте их по фильтрам, записывайте каждое изменение фильтров в историю браузера и восстанавливайте состояние страницы при переходах по истории и по готовому адресу.

## Критерии приёмки

- Товары загружаются один раз (`GET /api/products`). Фильтрация и сортировка выполняются на странице, без новых запросов.
- Список `#results` содержит элементы `li` с атрибутом `data-id`, в порядке сортировки. `#count` показывает число найденных товаров.
- Сортировки: `popular` — по полю `sold` от большего к меньшему, `price-asc` и `price-desc` — по цене. Фильтр «в наличии» оставляет товары с `stock` больше нуля.
- Если ничего не найдено, у элемента `#empty` нет атрибута `hidden`, иначе он скрыт.
- Изменение любого из трёх фильтров (`#category`, `#sort`, `#in-stock`) добавляет запись в историю: `history.pushState(filters, '', buildUrl(filters))`. Состояние записи — объект `{ category, sort, inStock }`. При загрузке страницы записи не добавляются.
- Переход по истории (`popstate`) показывает фильтры из `event.state` в элементах управления и обновляет список. Для записи без состояния (самой первой) показываются значения по умолчанию. Новых записей переход не создаёт.
- Функция `applyUrl(url)` приводит страницу в соответствие с адресом, переданным строкой: читает его через `parseFilters`, обновляет элементы управления и список. В историю она ничего не пишет. При загрузке вызывается `applyUrl` с адресом страницы.

## Неясности

Менеджер описал не всё. Часть решений придётся принять самим.

- Что считать «популярным», если у двух товаров одинаковое число продаж?
- Что показывать, пока товары загружаются, и что, если API не ответил?
- Нужно ли запоминать фильтры между визитами, или адрес страницы и есть память?

Прежде чем писать код, запишите в `assumptions.txt` вопросы, которые вы бы задали менеджеру, и допущения, которые принимаете, пока ответа нет. Автоматические проверки не зависят от вашего выбора по этим трём пунктам.

## Ограничения

- Не меняйте `index.html`.
- Готовые `parseFilters` и `buildUrl` можно дорабатывать, но их контракт менять нельзя.
- Названия товаров выводите через `textContent`.
- В настоящем браузере адрес страницы читают через `location.search`. В тренажёре `location` не меняется, поэтому после перехода по истории используйте `event.state`.
