## Зачем это в работе

Тикет из поддержки «Домотеки»: «Когда я ищу чайник, страница моргает на каждой букве, а потом иногда показывает не то, что я искал. Администратор жалуется, что сервер завален запросами».

Разработчик повесил поиск на событие `input`. Пользователь печатает «чайник», это шесть букв, и на сервер уходит шесть запросов. Пять из них никому не нужны. К тому же ответы приходят в любом порядке, и список на экране может оказаться ответом на «чай», а не на «чайник».

В этом уроке вы научитесь делать так, чтобы реакция на частые события была одна и вовремя. Два приёма называются дебаунс (debounce) и троттлинг (throttle). Третий инструмент — отмена устаревшего запроса через `AbortController`.

## Объяснение

Начнём с таймера. Функция `setTimeout(fn, 300)` не выполняет `fn` сейчас. Она просит браузер выполнить её через 300 миллисекунд и сразу возвращает число — номер таймера. Если таймер ещё не сработал, его можно отменить: `clearTimeout(номер)`.

```js
const timerId = setTimeout(() => console.log('Сохранено'), 300);
clearTimeout(timerId); // сообщение не появится
```

Аналогия для дебаунса: лифт. Вы нажимаете кнопку, и двери закрываются через пару секунд. Если за это время подошёл ещё один человек, двери открываются снова и отсчёт идёт с нуля. Лифт едет, только когда никто не подходил целую паузу.

**Дебаунс** делает то же самое с вызовом функции. Каждое новое событие отменяет прежний таймер и запускает новый. Функция срабатывает один раз, когда события закончились и прошла пауза. Для поиска это то, что нужно: нам важна не каждая буква, а итоговый запрос.

**Троттлинг** устроен иначе. Он пропускает вызов не чаще одного раза за интервал, пока события идут. Для прокрутки страницы это подходит: полоска прогресса должна двигаться по ходу, а не только после остановки. Но пересчитывать её на каждый пиксель не нужно.

Коротко: дебаунс ждёт тишины, троттлинг ограничивает частоту.

## Пример

Сначала модель, чтобы увидеть разницу на числах. Нажатия клавиш заданы моментами времени в миллисекундах. Измените задержку и посмотрите, сколько запросов получится.

<Playground example="debounce-model" />

Теперь настоящий код. Функция `debounce` принимает функцию и задержку, а возвращает новую функцию, которую можно вешать на событие:

```js
function debounce(fn, delay) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

const search = debounce((text) => console.log('Ищем:', text), 300);
search('ч');
search('чай');
search('чайник'); // через 300 мс выведется только «Ищем: чайник»
```

Переменная `timer` живёт снаружи возвращаемой функции. Благодаря замыканию (closure) все вызовы `search` видят один и тот же `timer`. Поэтому второй вызов может отменить таймер первого.

Теперь сравните два обработчика поля поиска.

<Wrong>

```js
searchInput.addEventListener('input', () => {
  loadProducts(searchInput.value); // запрос на каждую букву
});
```

</Wrong>

<Right>

```js
const debouncedLoad = debounce(loadProducts, 300);
searchInput.addEventListener('input', () => {
  debouncedLoad(searchInput.value);
});
```

</Right>

Слева шесть букв дают шесть запросов. Справа, если человек печатает без пауз длиннее 300 мс, уходит один.

## Как это работает

<Figure src="debounce-vs-throttle.svg" alt="Три строки на общей оси времени. Верхняя: десять событий подряд. Средняя, дебаунс: один кружок после последнего события, между ними пунктир с подписью «пауза равна задержке». Нижняя, троттлинг: три кружка с равными промежутками, пока события идут." caption="Одни и те же события. Дебаунс вызывает функцию один раз после паузы, троттлинг — раз в интервал." />

Три правила на каждый день.

1. **Таймер нужно хранить.** Без переменной `timer` нечего отменять. Каждый вызов создаст свой независимый таймер, и дебаунса не получится.
2. **Каждому событию — `clearTimeout`, потом `setTimeout`.** Порядок важен: сначала отмена старого, потом запуск нового.
3. **Выбирайте по смыслу.** Нужен итог — дебаунс: поиск при вводе, проверка логина, автосохранение черновика. Нужны промежуточные значения — троттлинг: прокрутка, изменение размера окна, перетаскивание.

Троттлинг пишется так. Запоминаем момент последнего вызова, остальные вызовы в интервале пропускаем:

```js
function throttle(fn, interval) {
  let lastCall = 0;
  return function (...args) {
    const now = Date.now();
    if (now - lastCall >= interval) {
      lastCall = now;
      fn(...args);
    }
  };
}
```

Здесь пропущенные вызовы теряются. Если нужно, чтобы последнее событие всё равно обработалось, к такой версии добавляют отложенный вызов в конце. Эту доработку вы сделаете в задании.

<Playground example="throttle-model" />

**Вторая проблема поиска: устаревший ответ.** Дебаунс уменьшает число запросов, но не убирает гонку (race condition). Человек напечатал «мик», сделал паузу, запрос ушёл. Тут же он дописал «сер», ушёл второй запрос. Сервер на «мик» отвечал медленно, и его ответ пришёл последним. На экране оказался список по «мик», хотя в поле написано «миксер».

<Playground example="stale-response" />

Лекарство — отменять прошлый запрос перед новым. Для этого есть `AbortController`:

```js
let controller;

async function load(text) {
  if (controller) controller.abort();
  controller = new AbortController();
  try {
    const response = await fetch('/api/search?q=' + encodeURIComponent(text), {
      signal: controller.signal,
    });
    render(await response.json());
  } catch (error) {
    if (error.name === 'AbortError') return; // отмена — не ошибка
    showError();
  }
}
```

Отменённый `fetch` отклоняет промис с ошибкой `AbortError`. В `catch` её надо отличить от настоящего сбоя и просто выйти.

<Note>

Дебаунс и отмена запроса решают разные задачи. Дебаунс экономит запросы. Отмена защищает от устаревших ответов. В рабочем поиске нужны оба.

</Note>

## Типичные ошибки

Сообщения ниже мы получили запуском в Chromium.

**1. Забыли вернуть функцию из `debounce`.** Если `debounce` только запускает таймер и ничего не возвращает, то при вызове результата получится:

```text
TypeError: debounced is not a function
```

<Wrong>

```js
function debounce(fn, delay) {
  setTimeout(fn, delay); // нет return function
}
const debounced = debounce(load, 300);
debounced(); // TypeError
```

</Wrong>

<Right>

```js
function debounce(fn, delay) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}
```

</Right>

**2. `debounce` вызывают внутри обработчика.** Ошибки в консоли нет, но дебаунса тоже нет: каждый раз создаётся новая функция с новым `timer`, и отменять нечего.

<Wrong>

```js
input.addEventListener('input', () => {
  debounce(load, 300)(input.value); // новый timer на каждую букву
});
```

</Wrong>

<Right>

```js
const debouncedLoad = debounce(load, 300); // один раз, снаружи
input.addEventListener('input', () => debouncedLoad(input.value));
```

</Right>

**3. Отмена выглядит как ошибка сети.** Если не проверить имя ошибки, пользователь увидит «Не удалось загрузить» при каждой отмене. В консоли будет:

```text
AbortError: signal is aborted without reason
```

<Wrong>

```js
} catch (error) {
  showError('Не удалось загрузить');
}
```

</Wrong>

<Right>

```js
} catch (error) {
  if (error.name === 'AbortError') return;
  showError('Не удалось загрузить');
}
```

</Right>

**4. Функцию в `setTimeout` вызвали сразу.** `setTimeout(save(), 300)` выполняет `save` немедленно, а в таймер уходит результат вызова. Браузер при этом не жалуется: `setTimeout(undefined, 10)` молча ничего не делает. Скобки нужны только при вызове, при передаче их нет.

<Wrong>

```js
setTimeout(hideToast(), 300);
```

</Wrong>

<Right>

```js
setTimeout(hideToast, 300);
```

</Right>

## Итог

Что вы теперь умеете:

- откладывать действие через `setTimeout` и отменять его через `clearTimeout`;
- писать свою функцию `debounce` и объяснять, зачем ей переменная `timer` снаружи;
- отличать ситуации для дебаунса (поиск при вводе) и троттлинга (прокрутка);
- отменять устаревший запрос через `AbortController` и не показывать отмену как ошибку.

Дебаунс убирает лишние запросы, но в браузерном JS есть и другие ловушки: `this` в обработчиках, обработчики, которые навешиваются повторно, и ответы, которые приходят не в том порядке. В следующем уроке разберём их на примерах с багами.
