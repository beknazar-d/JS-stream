# Разбор

Задача складывается из трёх слоёв, и каждый решает свою проблему.

1. **Дебаунс** (`debounce(loadResults, 300)`) уменьшает число запросов. Он создан один раз снаружи обработчика.
2. **Отмена** (`AbortController`) защищает от устаревших ответов. Перед новым запросом прошлый отменяется, и его ответ не придёт. В `catch` отмену узнают по `error.name === 'AbortError'` и выходят молча.
3. **Состояния** отвечают пользователю на вопрос «что сейчас происходит»: «Загрузка…», «Ничего не найдено», «Не удалось загрузить результаты» с кнопкой повтора. Ответ с кодом 4xx или 5xx не вызывает исключение в `fetch`, поэтому `response.ok` проверяется вручную и бросает свою ошибку.

Кнопка «Повторить» вызывает `loadResults(lastText)`. Для этого последний текст запоминается.

## Вопросы, которые стоило задать

- С какой длины запроса начинать поиск? Поиск по одной букве даёт огромный список и нагружает сервер.
- Что показывать при пустом поле: ничего, популярные товары или подсказку?
- Нужна ли цена в списке и в каком формате? Что с товарами без цены?
- Пробелы по краям считать частью запроса?
- Сколько товаров показывать, если нашлись сотни: всё, первые N или с пагинацией?

## Допущения в эталоне

Пустое поле очищает список. Запрос обрезается (`trim`). Цена показана после названия. Тесты эти решения не проверяют: другие разумные ответы тоже засчитываются.
