# Разбор

Идея этапа: **адрес страницы — главный хранитель состояния**. Остальное (поля, список, запрос) выводится из него.

1. **Две чистые функции.** `buildSearch` превращает состояние в строку, `parseState` делает обратное. Они не знают про DOM, поэтому их легко проверить отдельно. `parseState` — граница доверия: адрес может ввести кто угодно, поэтому `sort` и `category` сверяются со списками, а `page` проверяется как целое число не меньше 1.
2. **Одна точка изменения состояния.** Все пользовательские действия идут через `changeState`. Она сравнивает адреса: если ничего не изменилось, запись в историю не нужна (повторный выбор того же значения). Если изменилось, она пишет `pushState`, а потом грузит данные. Благодаря дебаунсу, поставленному перед `changeState`, набор слова даёт одну запись.
3. **`popstate` — другая дорога.** «Назад» уже поменял запись истории, поэтому обработчик только применяет состояние: берёт его из `event.state`, обновляет поля (`showControls`) и грузит данные. Если вызвать здесь `changeState`, она сделает `pushState`, и «Вперёд» пропадёт.
4. **Старт.** Начальное состояние читается из `location.search`. `replaceState` кладёт состояние в первую запись, чтобы возврат к ней работал. Поля заполняются из состояния, ведь страницу могли открыть по ссылке.
5. **Резервный путь.** Для записи без состояния (первая в реальном браузере) берётся `parseState(location.search)`.

Запись `buildSearch(state) || location.pathname` важна для настоящего браузера: пустая строка в `pushState` оставила бы старые параметры.

## Вопросы, которые стоило задать

- Что показывать по ссылке на несуществующую страницу (`page=99`): пустой список, последнюю страницу?
- Должны ли имена параметров быть стабильными (старые ссылки в рассылках, аналитике)?
- Нужна ли кнопка «Сбросить фильтры»?
- Нужен ли поиск в адресе: в нём может оказаться личная информация?
- Должна ли каждая страница пагинации быть отдельной записью истории или лучше `replaceState`?

## Допущения в эталоне

Страница сверх диапазона не обрезается, кнопки сброса нет, параметры называются `q`, `category`, `sort`, `page`. Тесты это не проверяют.

## Чек-лист самопроверки

Откройте проект, пройдитесь по сценарию: выбрать категорию, поменять сортировку, ввести поиск, нажать «Назад» три раза, «Вперёд» дважды, обновить страницу. На каждом шаге адрес, поля и список должны совпадать.
