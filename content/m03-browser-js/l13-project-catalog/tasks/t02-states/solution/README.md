# Разбор

У запроса четыре исхода, и у каждого есть свой вид страницы:

1. **Идёт.** `#status` — «Загрузка…», `aria-busy` у списка `true` (читалки экрана понимают, что список обновляется), кнопка повтора скрыта.
2. **Успех с данными.** Статус пуст, карточки показаны.
3. **Успех без данных.** Список пуст, но статус «Ничего не найдено»: пустая страница выглядела бы как поломка.
4. **Ошибка.** Сообщение, пустой список и кнопка «Повторить».

Важные детали:

- `fetch` не бросает исключение на ответ 503. Исключение будет только при падении сети. Поэтому `response.ok` проверяется вручную, и ошибка бросается самим кодом. Обе ситуации попадают в один `catch`.
- В конце `aria-busy` ставится в `false` и для успеха, и для ошибки. Для этого код после `try/catch` общий.
- «Обновить», «Повторить» и первая загрузка вызывают одну функцию `loadProducts`. Тогда состояния не расходятся.
- В начале функции кнопка повтора скрывается: после успешного повтора её не нужно прятать отдельно.

## Что оставлено на следующие этапы

Адрес запроса пока фиксированный. Когда появятся страницы и поиск, он будет собираться из состояния, а «Повторить» повторит запрос с теми же параметрами.
