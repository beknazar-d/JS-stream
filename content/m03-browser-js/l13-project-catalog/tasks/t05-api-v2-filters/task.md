## Контекст

Середина проекта, и приходят сразу два сообщения.

**От бэкенд-команды:** «Во вторник выкатываем API версии 2. Ответ теперь `{ data: [...], meta: { total, page, pages } }`. Цена называется `priceMinor` и приходит в копейках. Вместо `inStock` теперь остаток `stock` в штуках. Версия 1 отключается». Сервер в `api.js` уже обновлён, поэтому каталог на странице сейчас пустой, а в консоли ошибка.

**От заказчика:** «Раз уж трогаете каталог: добавьте фильтр по категории и сортировку по цене. Поле поиска оставьте».

Задача WEB-690. В разметку добавлены `#category` и `#sort`.

## Цель

Этап 5 из 6. Перейдите на формат API версии 2 и добавьте фильтр по категории и сортировку. Всё, что работало раньше (состояния, страницы, поиск с дебаунсом и отменой), должно продолжать работать.

## Критерии приёмки

- Карточки строятся из `data`, общее число и число страниц берутся из `meta`.
- Цена показывается в рублях: `priceMinor` делится на 100 (например, `299000` -> `2 990 ₽`).
- Товар в наличии, если `stock` больше нуля; иначе `Нет в наличии` и класс `card--out`.
- Выбор в `#category` добавляет в запрос `category=<значение>`; значение «Все категории» (пустое) параметр не добавляет.
- Выбор в `#sort` добавляет `sort=price-asc` или `sort=price-desc`; «По популярности» (`popular`) параметр не добавляет.
- Поиск, категория, сортировка и страница работают вместе: в каждом запросе все текущие значения. Смена категории или сортировки сбрасывает страницу на 1.
- Состояния загрузки, ошибки и пустого результата работают как раньше.

## Неясности

В сообщениях нет ответов на вопросы: показывать ли копейки, если они есть; сбрасывать ли поиск при смене категории; как упорядочены товары с одинаковой ценой. Запишите вопросы и допущения в `assumptions.txt` до кода. Тесты используют только суммы без копеек. Показ вида `2 990 ₽` и `2 990,00 ₽` одинаково допустим.

## Ограничения

- Разметку, стили, `data.js` и `api.js` не меняйте.
- Сортировку делает сервер. Не сортируйте массив на клиенте.
