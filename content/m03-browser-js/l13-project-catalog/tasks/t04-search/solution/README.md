# Разбор

Поиск — ещё одна часть состояния рядом с номером страницы. Это главное решение: не отдельный запрос «для поиска», а `state.q`, который `buildQuery` добавляет к тому же запросу.

1. **Дебаунс стоит между полем и состоянием.** Обработчик `input` вызывает дебаунснутую функцию, которая и меняет состояние, и запускает загрузку. Дебаунс создан один раз снаружи обработчика.
2. **Сброс страницы.** Новый поиск всегда `page: 1`. Иначе человек на третьей странице получит пустой экран.
3. **Отмена.** В `loadProducts` перед запросом прошлый отменяется. Это защищает не только поиск, но и страницы, и «Обновить». В `catch` отмена узнаётся по `error.name === 'AbortError'` и выходит молча. Именно поэтому `aria-busy` и статус для отменённого запроса не трогаются: их ведёт новый запрос.
4. **Повтор.** «Повторить» вызывает `loadProducts`, а он собирает запрос из состояния, поэтому параметры те же.
5. `q` добавляется в запрос только если не пусто. Пустой поиск — это каталог целиком.

## Вопросы, которые стоило задать

- Искать только по названию или по описанию и категории тоже?
- С какой длины начинать поиск? Нужно ли предупреждение для запросов из одной буквы?
- Регистр и ё/е: считать одинаковыми?
- Сохранять ли поиск при перезагрузке (это встретится на последнем этапе)?

## Допущения в эталоне

Ищем по названию, с первого символа, без учёта регистра (это делает сервер), пробелы по краям отбрасываем. Тесты эти решения не проверяют.
