## Контекст

Тикет ORD-301. После оформления покупатель видит страницу «Сводка заказа»: кому и куда едет заказ, список товаров, скидка по промокоду, доставка и итог. Сейчас на странице пустая разметка. Данные заказа приходят объектом, а имя и адрес вводит сам покупатель, поэтому им нельзя доверять.

Заказ выглядит так: `{ customer, address, items: [{ title, qty, price }], promoCode }`. Поле `promoCode` необязательное.

## Цель

Напишите в `script.js` функцию `renderOrder(order)`, которая заполняет страницу. Строки таблицы создавайте из шаблона `#row-template`. Вызов с примером заказа уже стоит в конце файла.

## Критерии приёмки

- `.greeting` содержит `Заказ для ИМЯ`, `.address` — `Доставка: АДРЕС`.
- В `tbody` по строке `.order-row` на товар: в ячейках `.order-row__title` название, `.order-row__qty` количество, `.order-row__sum` сумма строки (`price * qty`) через `formatPrice`.
- `.subtotal` — сумма строк через `formatPrice`.
- Промокод `DOM10` даёт скидку 10% от суммы товаров, округлённую `Math.round`. Тогда `.promo-row` показан, а `.discount` содержит `-` и сумму через `formatPrice`, например `-1 297 ₽`. Без промокода и с любым другим кодом `.promo-row` скрыт.
- Доставка считается по сумме после скидки: от 5000 ₽ включительно бесплатно, текст `Бесплатно`, иначе 390 ₽ (`formatPrice(390)`) в `.delivery`.
- `.grand-total` равен сумме после скидки плюс доставка.
- Пустой список товаров: `.order-empty` показано, таблица скрыта (`hidden`), `.subtotal` и `.grand-total` содержат `0 ₽`, `.delivery` содержит `—`.
- Данные покупателя (имя, адрес, названия) выводятся только как текст.
- Повторный вызов с другим заказом полностью заменяет прежнее состояние.
- Шаблон `#row-template` остаётся нетронутым.

## Ограничения

- Не меняйте `index.html` и `styles.css`.
- Не используйте `innerHTML`.
