# Разбор

Функция сначала считает, потом выводит. Расчёты лежат в обычных переменных, поэтому их легко проверить глазами.

1. **Тексты покупателя.** Имя и адрес идут через `textContent`: разметка в них не разбирается.
2. **Строки.** `replaceChildren()` убирает прежние строки, затем для каждого товара клонируется шаблон. `template.content` не трогаем, только клон. Сумму строки накапливаем в `subtotal`.
3. **Скидка.** Промокод сравниваем со строкой `'DOM10'`. Скидка округляется `Math.round`, неизвестный код даёт ноль.
4. **Доставка.** Порог включительный (`>=`) и считается по сумме после скидки. Числа порога и цены вынесены в константы, чтобы их было видно и легко менять.
5. **Состояния.** Блоки, которые то видны, то нет, управляются выражением `hidden = условие`. Это работает в обе стороны, поэтому после пустого заказа таблица возвращается.
6. **Пустой заказ** — отдельная ветка: итоги сводятся к `0 ₽`, а вместо доставки стоит тире.

Что стоило проверить у менеджера: что делать с дробной скидкой (рублей или копеек), что считается порогом (до или после скидки). В тикете это записано явно, поэтому вопросов нет.
