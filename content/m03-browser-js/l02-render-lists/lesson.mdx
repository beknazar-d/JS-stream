## Зачем это в работе

В прошлом уроке товары уже лежали в разметке. На деле каталог приходит как данные: массив объектов. Менеджер хочет, чтобы страница сама строила карточки по списку, а при пустом списке показывала понятное сообщение.

Есть и вторая задача, неприятная. В отзывах покупатели пишут что угодно. Один из них вписал в поле имени кусок HTML, и этот кусок попал на страницу как есть. Так делают взломы. Сегодня вы научитесь строить список из данных и вставлять чужой текст безопасно.

## Объяснение

Страница создаёт элементы из кода тремя способами.

1. **`createElement`.** Метод `document.createElement('li')` создаёт пустой элемент. Он пока не на странице. Вы заполняете его и затем добавляете в дерево.
2. **`template`.** Тег `template` хранит заготовку разметки. Браузер её не показывает. Вы клонируете заготовку, заполняете копию и добавляете. Так удобно, когда карточка сложная.
3. **`innerHTML`.** Присваивание строки разметки. Это быстро писать, но опасно, если в строке чужой текст.

Для добавления и удаления есть методы:

- `parent.append(a, b)` — добавить в конец; принимает элементы и строки;
- `parent.prepend(a)` — добавить в начало;
- `element.remove()` — убрать элемент из страницы;
- `parent.replaceChildren()` — убрать всех детей. Если передать узлы, они займут место прежних.

Список строится одной функцией. Она получает массив, очищает контейнер и добавляет по элементу на каждый объект. Если массив пуст, функция показывает сообщение.

Аналогия: конвейер на складе. Данные — это коробки, шаблон — форма для карточки. Каждая коробка проходит по ленте, и из неё получается готовая карточка на витрине.

## Пример

Разметка: пустой список и шаблон карточки.

```html
<ul class="catalog"></ul>
<p class="empty" hidden>Ничего не найдено</p>

<template id="card-template">
  <li class="card">
    <h3 class="card__title"></h3>
    <p class="card__price"></p>
  </li>
</template>
```

Скрипт строит список по массиву.

```js
const template = document.querySelector('#card-template');
const list = document.querySelector('.catalog');
const empty = document.querySelector('.empty');

function renderCatalog(products) {
  list.replaceChildren();
  empty.hidden = products.length > 0;

  for (const product of products) {
    const card = template.content.cloneNode(true);
    card.querySelector('.card__title').textContent = product.title;
    card.querySelector('.card__price').textContent = product.price + ' ₽';
    list.append(card);
  }
}

renderCatalog([
  { title: 'Чайник K-200', price: 2990 },
  { title: 'Тостер T-2', price: 2190 },
]);
```

Три детали. `replaceChildren()` в начале убирает прежние карточки, поэтому повторный вызов не плодит дубликаты. `cloneNode(true)` копирует шаблон целиком с вложенными тегами. Заголовок и цена вставляются через `textContent`.

Теперь самое важное: что будет, если название содержит разметку.

<Wrong>

```js
// название товара попадает в разметку как есть
card.innerHTML = '<h3>' + product.title + '</h3>';
```

</Wrong>

<Right>

```js
// название остаётся текстом
card.querySelector('.card__title').textContent = product.title;
```

</Right>

Картинка не загрузится, и сработает обработчик `onerror`, а в нём может быть любой код. Это называется XSS (cross-site scripting, «межсайтовый скриптинг»): чужой код выполняется на вашей странице и от вашего имени.

## Как это работает

Схема сравнивает два свойства на одной и той же строке.

<Figure src="inner-vs-text.svg" alt="Вверху строка с именем пользователя: тег img с обработчиком onerror. Слева стрелка к textContent: на странице видна та же строка как текст, это безопасно. Справа стрелка к innerHTML: браузер создаёт настоящий элемент img, код из onerror выполняется, это опасно." caption="textContent показывает строку как есть. innerHTML разбирает её как разметку." />

Правила, которые стоит запомнить.

1. **Данные пользователя — только `textContent`.** Имена, комментарии, адреса, поисковые запросы. Правило без исключений.
2. **`innerHTML` допустим для своих констант.** Например, `innerHTML = ''` для очистки или фиксированная разметка без чужих данных. Но лучше `replaceChildren()`.
3. **`innerHTML +=` ещё и ломает страницу.** Строка перечитывается целиком, все прежние элементы создаются заново. Обработчики на них пропадают, введённый в поля текст сбрасывается.
4. **Очищайте перед рендером.** Функция, которая только добавляет, при повторном вызове даст дубликаты.
5. **Клонируйте шаблон.** Добавление `template.content` без клона перенесёт узлы из шаблона, и второй раз их уже не получится использовать.
6. **Пустой список — тоже состояние.** Показывайте сообщение через `hidden`, а не оставляйте пустую страницу.

<Note>

Тег `script`, вставленный через `innerHTML`, не выполняется. Но этого мало для безопасности: код запускается через атрибуты вроде `onerror` у `img`. Не полагайтесь на то, что «скрипты браузер не запустит».

</Note>

## Типичные ошибки

Сообщения получены в Chromium.

**1. Списку передали строку вместо узла.** `appendChild` принимает только узел.

```text
TypeError: Failed to execute 'appendChild' on 'Node': parameter 1 is not of type 'Node'.
```

Используйте `append` для строк или `createTextNode`.

**2. Контейнер не найден.** Скрипт ищет список до его появления или с опечаткой.

```text
TypeError: Cannot read properties of null (reading 'append')
```

**3. Забыли очистить.** Ошибки нет: при втором вызове рендера карточки удваиваются. Смотрите на страницу.

**4. Добавили `null` через `append`.** Ошибки тоже нет: на страницу попадёт текст `null`, потому что `append` превращает аргумент в строку. Проверяйте значения перед вставкой.

**5. Вставили чужой текст через `innerHTML`.** Нет ни ошибки, ни предупреждения. Страница выглядит нормально, пока кто-то не вставит разметку. Ищите `innerHTML` рядом с данными в код-ревью.

## Итог

Что вы теперь умеете:

- создавать элементы через `createElement` и `template` и добавлять их через `append`, `prepend`;
- строить список из массива одной функцией и очищать его перед отрисовкой;
- показывать состояние «пусто» через `hidden`;
- объяснять, почему вставка текста пользователя через `innerHTML` опасна, и использовать `textContent`.

Пока страница меняется только при загрузке. Но кнопка «В корзину» должна работать по клику, а поле поиска по вводу. Об этом следующий урок: события.
