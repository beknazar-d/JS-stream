## Зачем это в работе

Три тикета из поддержки «Домотеки» за одну неделю.

1. «Кнопка „В корзину“ работает с первого раза, а после обновления списка один клик добавляет сразу три штуки».
2. «В итоговой цене пишет NaN рублей, если стереть количество».
3. «Ищу миксер, а на экране остаётся список чайников».

Во всех трёх случаях консоль чистая. Код выглядит разумно, тесты на обычных данных проходят, а баг показывается только в определённой последовательности действий. Такие ошибки стоят дороже всего: их долго ищут.

Этот урок — разбор. Мы собрали пять ловушек браузерного JavaScript. У каждой есть признак, причина и безопасная привычка. Знакомая ловушка превращается в пять минут работы вместо вечера.

## Объяснение

Представьте механика, который перед выездом проверяет автомобиль по списку: масло, шины, свет, тормоза. Не потому что всё ломается, а потому что поломки повторяются. Ваш список на ближайшие месяцы такой:

1. `this` в обработчике: обычная функция и стрелка ведут себя по-разному.
2. Обработчики, которые копятся при каждой перерисовке.
3. `innerHTML +=`, после которого старые элементы перестают реагировать.
4. Гонка ответов: старый запрос возвращается позже нового.
5. Значения из полей формы: всегда строки, и из них легко получить `NaN`.

Начнём с первой, потому что она сбивает с толку чаще всех. Слово `this` означает «тот, у кого вызвали функцию». Для обработчика события это элемент, на котором он висит. Но только если функция объявлена через `function`. У стрелки (`=>`) своего `this` нет: она берёт его снаружи, из места, где записана. В обычном скрипте снаружи находится `window`.

## Пример

Запустите модель. Браузер вызывает обработчик так, будто `this` равен элементу. В коде мы повторяем это через `call`.

<Playground example="this-handlers" />

Обычная функция получила `button` и вернула его `id`. Стрелка проигнорировала `call` и вернула `id` объекта, внутри которого была записана.

В браузере это выглядит так:

```html
<button class="buy" data-id="7">В корзину</button>
```

<Wrong>

```js
const button = document.querySelector('.buy');
button.addEventListener('click', () => {
  addToCart(this.dataset.id); // this здесь window
});
```

</Wrong>

<Right>

```js
const button = document.querySelector('.buy');
button.addEventListener('click', (event) => {
  addToCart(event.currentTarget.dataset.id);
});
```

</Right>

Слева `window.dataset` не существует, и мы получаем ошибку. Справа элемент берётся из события. Это работает и в стрелке, и в обычной функции, поэтому `event.currentTarget` — безопасная привычка. Не путайте его с `event.target`: это самый глубокий элемент под курсором. Если внутри кнопки лежит значок, `target` будет значком, а `currentTarget` останется кнопкой.

## Как это работает

**Ловушка 2: обработчики копятся.** Функцию `render` вызывают при каждом обновлении списка. Если внутри неё есть `addEventListener`, то при каждом вызове добавляется ещё один обработчик. Две одинаковые по тексту стрелки — это две разные функции, и браузер не склеивает их.

<Playground example="duplicate-listeners" />

<Wrong>

```js
function render() {
  list.innerHTML = items.map(toHtml).join('');
  list.addEventListener('click', onListClick); // при каждой перерисовке
}
```

</Wrong>

<Right>

```js
function render() {
  list.innerHTML = items.map(toHtml).join('');
}
list.addEventListener('click', onListClick); // один раз, снаружи
```

</Right>

Справа обработчик висит на списке, а не на отдельных кнопках. Список при перерисовке не заменяется, только его содержимое. Этот приём называется делегированием (event delegation), вы его уже знаете.

**Ловушка 3: `innerHTML +=`.** Запись `list.innerHTML += '<li>...</li>'` выглядит как «добавить в конец». На самом деле браузер превращает всё содержимое в строку, дописывает хвост и строит все элементы заново. Старые элементы исчезают, обработчики, которые висели на них, пропадают вместе с ними. Переменная со ссылкой на старую кнопку продолжает жить, но кнопка уже не на странице.

<Wrong>

```js
list.innerHTML += '<li><button class="del">Удалить</button></li>';
```

</Wrong>

<Right>

```js
list.insertAdjacentHTML('beforeend', '<li><button class="del">Удалить</button></li>');
// или createElement и list.append(item)
```

</Right>

Справа новые элементы дописываются, а старые остаются нетронутыми.

**Ловушка 4: гонка ответов.** Сервер не обязан отвечать в том порядке, в каком получил запросы.

<Figure src="response-race.svg" alt="Ось времени от 0 до 900 миллисекунд. Длинный отрезок от 300 до 900: запрос «чай» идёт долго. Короткий отрезок от 620 до 670: запрос «чайник» вернулся быстро. В момент 900 ответ на «чай» приходит последним и затирает список." caption="Запрос «чай» ушёл раньше, но вернулся позже. Последним в список пишет устаревший ответ." />

Лекарство вы уже знаете из прошлого урока: отменить прошлый запрос через `AbortController`. Есть и второй способ, когда отменять нечего. Номер запроса записывают в переменную и сравнивают после ответа:

```js
let lastRequestId = 0;

async function loadCategory(slug) {
  const id = ++lastRequestId;
  const response = await fetch('/api/products?category=' + slug);
  const items = await response.json();
  if (id !== lastRequestId) return; // пришёл устаревший ответ
  render(items);
}
```

**Ловушка 5: значения из формы.** Поле всегда отдаёт строку. `'3' + 1` даст `'31'`, а не `4`. Пустое поле превращается в `0` через `Number('')`, а текст с буквами — в `NaN`. Запустите пример и посмотрите на разницу.

<Playground example="form-numbers" />

Правило: прочитали — проверили — только потом считаем. Если проверка не пройдена, покажите понятное сообщение, а не `NaN рублей`.

<Note>

Поле `input type="number"` не спасает: пустое поле и поле с мусором дают пустую строку в `value`. Проверять всё равно придётся.

</Note>

## Типичные ошибки

Сообщения ниже получены запуском в Chromium.

**1. `this` в стрелке.** Консоль:

```text
TypeError: Cannot read properties of undefined (reading 'id')
```

Так выглядит `this.dataset.id`, где `this` равно `window`: у окна нет свойства `dataset`, и `undefined` не умеет читать `id`. Решение — `event.currentTarget`.

**2. Клик считается несколько раз или не считается вообще.** Ошибки нет. После трёх перерисовок один клик вызывает обработчик три раза (ловушка 2). После `innerHTML +=` старые кнопки молчат (ловушка 3). Признак один: поведение зависит от того, сколько раз что-то обновляли.

**3. Кнопка есть на странице, а клик не работает.** Проверьте в консоли `button.isConnected`. Если вернулось `false`, переменная держит старый элемент, которого уже нет на странице. Присваивание `list.innerHTML = ...` заменило всё содержимое списка, и кнопку надо искать заново.

**4. Элемент не найден.**

```text
TypeError: Cannot read properties of null (reading 'addEventListener')
```

Это `document.querySelector('#nope')`, который вернул `null`. Частая причина: скрипт выполняется до того, как нужный элемент появился в разметке, или в селекторе опечатка.

**5. `NaN` в интерфейсе.** Ошибки нет, просто на странице «NaN ₽». Причина: из поля прочитали строку, которую `Number` не смог превратить в число. Проверка:

<Wrong>

```js
const total = Number(qtyInput.value) * price; // пусто → 0 ₽, «abc» → NaN ₽
totalOutput.textContent = total + ' ₽';
```

</Wrong>

<Right>

```js
const text = qtyInput.value.trim();
const qty = Number(text);
if (text === '' || !Number.isInteger(qty) || qty < 1) {
  totalOutput.textContent = 'Введите количество от 1';
} else {
  totalOutput.textContent = qty * price + ' ₽';
}
```

</Right>

## Итог

Что вы теперь умеете:

- объяснить, чему равен `this` в обычной функции и в стрелке, и брать элемент через `event.currentTarget`;
- не вешать обработчики внутри `render` и использовать делегирование;
- добавлять элементы без `innerHTML +=`;
- защищаться от гонки ответов отменой запроса или номером запроса;
- проверять значения из формы, прежде чем считать.

Дальше вы соберёте из этих кусочков первый большой проект модуля. В уроке 3.13 нужно сделать каталог по API: поиск с дебаунсом, фильтры и сортировку в адресе страницы, состояния загрузки и ошибок. Все пять ловушек из этого урока в нём тоже встретятся.
