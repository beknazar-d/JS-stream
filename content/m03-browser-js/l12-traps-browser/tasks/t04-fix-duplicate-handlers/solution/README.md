# Разбор

Причина — `list.addEventListener` внутри `render`. Функцию вызывают при запуске, после каждого клика и по кнопке «Обновить». Каждый вызов добавляет ещё один обработчик на тот же `ul`. Это новые стрелки, а не одна и та же функция, поэтому браузер их не склеивает.

Считаем. После запуска один обработчик. Первый клик: он срабатывает один раз (+1) и вызывает `render`, обработчиков становится два. Второй клик: срабатывают два обработчика (+2), потом их три. Отсюда «1, 2, 3, ...».

Исправление: подписка один раз снаружи `render`. `ul` сам не заменяется, меняется только его содержимое (`innerHTML` у списка). Поэтому обработчик на списке переживает любые перерисовки. Нужную кнопку находит `event.target.closest('button[data-action]')`. Это делегирование.

## Почему не подошли другие способы

- `{ once: true }` снимает обработчик после первого срабатывания, а не убирает дубли.
- `removeEventListener` работает только с той же самой функцией, которую добавляли. Новая стрелка на каждой перерисовке — другая функция.
- Не перерисовывать список — значит не показывать изменения.
