# Разбор

Три симптома из письма — три разные причины.

**1. Работает только последняя кнопка «Удалить» (`innerHTML +=`).** Запись `rows.innerHTML += ...` пересобирает всё содержимое таблицы. Новые строки создаются заново, и обработчики, которые висели на старых кнопках, пропадают вместе со старыми строками. Живым остаётся обработчик, который только что повесили на последнюю кнопку. Исправление: добавлять строку через `append` и повесить один обработчик на `tbody` (делегирование).

**2. Красное в консоли (`this` в стрелке).** В `() => { this.closest('tr') }` `this` равен `window`. У окна нет метода `closest`: `TypeError: this.closest is not a function`. Исправление: брать элемент из события или искать через `event.target.closest('.del')`.

**3. Цепочка цифр, нули и `NaN` (значения из формы).** Из поля приходит строка. В `qty += item.qty` строка склеивается со строкой: `0 + '3' + '2'` даёт `'032'`. Пустое поле даёт `0` после умножения, а текст даёт `NaN`. Исправление: функция `parseNumber` обрезает пробелы, пустую строку отклоняет отдельно, остальное превращает через `Number` и отсеивает `NaN` и бесконечности. Цифры хранятся числами.

Бонус: строки создаются через `textContent`, а не склеиваются в HTML, поэтому название вроде `<b>` не ломает таблицу.

## Вопросы, которые стоило задать

- Допустимы ли количество `0`, отрицательное и дробное? Для разных товаров ответы разные (штуки и килограммы).
- Допустима ли нулевая цена и цена с копейками? Как хранить деньги: рубли или копейки?
- Куда добавлять новую строку и что делать с одинаковыми названиями: объединять с существующей?
- Нужно ли подтверждение перед удалением и возможность отмены?
- Нужна ли запятая как десятичный разделитель (в русской раскладке её вводят чаще точки)?

## Допущения в эталоне

Эталон принимает любые конечные числа с точкой, добавляет строку в конец и удаляет без подтверждения. Тесты проверяют только однозначные случаи: целые положительные числа, пустое поле и текст вместо числа.
