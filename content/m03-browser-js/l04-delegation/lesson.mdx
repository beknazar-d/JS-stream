## Зачем это в работе

В корзине «Домотеки» у каждой строки есть кнопка «Удалить». Строки приходят из данных и добавляются, когда покупатель кладёт товар. Если вешать обработчик на каждую кнопку, придётся не забыть подключить его и к новым строкам. Забыли, и новый товар удалить нельзя.

Есть способ проще: повесить один обработчик на весь список. Он работает и для старых строк, и для будущих. Этот приём называется делегированием событий (event delegation), а держится он на всплытии.

## Объяснение

Всплытие (bubbling). Когда вы нажимаете на значок внутри кнопки, событие `click` случается на значке. Затем оно поднимается к родителю, то есть к кнопке, потом к строке, потом к списку, и так до самой страницы. На каждом уровне браузер вызывает те обработчики, которые там подключены.

Поэтому список «слышит» все клики по своим потомкам. Остаётся понять, кто именно получил клик. Для этого у события есть два свойства:

- `event.target` — самый глубокий элемент, на котором случилось событие. Например, значок внутри кнопки;
- `event.currentTarget` — элемент, на котором висит обработчик. Для обработчика на списке это всегда список.

Но `target` не всегда нужный элемент. Нужна кнопка, а клик пришёл на значок. Поможет метод `closest`:

```js
const button = event.target.closest('.remove');
```

Он идёт от элемента вверх по родителям и возвращает первого, кто подходит под селектор. Начинает с самого элемента. Если ничего не нашёл, вернёт `null`.

Получается шаблон делегирования:

1. подключаем один обработчик на общего родителя;
2. внутри ищем нужный элемент через `event.target.closest(селектор)`;
3. если результат `null`, значит клик был не по нужному месту, выходим;
4. иначе работаем с найденным элементом.

Аналогия: вахтёр в офисном здании. Вместо того чтобы посадить человека у каждой двери, вы ставите одного на входе. Он смотрит, к кому идёт посетитель, и решает, пустить ли его. Новые кабинеты в здании появляются, а вахтёр всё тот же.

## Пример

Разметка корзины.

```html
<ul id="cart">
  <li class="cart-row" data-id="k200">
    <span class="title">Чайник K-200</span>
    <button class="remove"><span class="icon">×</span></button>
  </li>
  <li class="cart-row" data-id="b50">
    <span class="title">Блендер B-50</span>
    <button class="remove"><span class="icon">×</span></button>
  </li>
</ul>
```

Один обработчик на весь список.

```js
const cart = document.querySelector('#cart');

cart.addEventListener('click', (event) => {
  const button = event.target.closest('.remove');
  if (!button) return;
  if (!cart.contains(button)) return;

  const row = button.closest('.cart-row');
  row.remove();
});
```

Что здесь важно. Клик по значку внутри кнопки тоже срабатывает, потому что `closest` поднимется от значка к кнопке. Клик по названию товара выходит на `if (!button) return`. Строки, которые вы добавите позже, будут удаляться тем же обработчиком: он висит на списке, а не на кнопках.

Сравним два подхода.

<Wrong>

```js
// проверяем только то, куда попал клик: значок не пройдёт проверку
cart.addEventListener('click', (event) => {
  if (event.target.classList.contains('remove')) {
    event.target.closest('.cart-row').remove();
  }
});
```

</Wrong>

<Right>

```js
// closest находит кнопку, даже если нажали на значок внутри неё
cart.addEventListener('click', (event) => {
  const button = event.target.closest('.remove');
  if (!button) return;
  button.closest('.cart-row').remove();
});
```

</Right>

## Как это работает

Схема показывает путь клика по значку.

<Figure src="bubbling.svg" alt="Слева вложенные прямоугольники: список ul, в нём строка li, в ней кнопка button, в ней значок span. Справа стрелка вверх от значка: сначала сработает обработчик кнопки, затем строки, затем списка. Внизу подпись: target всегда значок, currentTarget меняется на каждом шаге." caption="Событие поднимается от значка к списку. target не меняется, currentTarget меняется." />

Правила, которые стоит запомнить.

1. **Всплывает почти всё.** Не всплывают `focus` и `blur` (для делегирования есть `focusin` и `focusout`), а также `mouseenter` и `mouseleave`. Клики, ввод и клавиши всплывают.
2. **`target` — где случилось, `currentTarget` — где слушаем.** В делегированном обработчике `currentTarget` всегда сам список, а нужный элемент ищите от `target`.
3. **Всегда `closest`.** Сравнение `target.classList.contains(...)` не сработает, когда внутри кнопки есть значок или текст в отдельном теге.
4. **Всегда проверяйте `null`.** Человек нажимает на пустое место списка, `closest` возвращает `null`, и следующая строка падает. Добавляйте `if (!button) return`.
5. **Вложенные списки.** `closest` может подняться выше вашего списка и найти чужую кнопку. Добавьте `list.contains(button)`.
6. **Данные читайте с найденного элемента.** `button.dataset.id`, а не `event.target.dataset.id`.
7. **Одного обработчика достаточно, если страницу перерисовывают.** Список остаётся на месте, а строки внутри пересоздаются, и обработчик продолжает работать.

А теперь про `stopPropagation`. Метод останавливает всплытие: выше по дереву событие уже не пойдёт. Соблазн велик: «щелчок по значку не должен выбирать всю карточку». Но это скрытое действие на расстоянии. Все обработчики выше, в том числе чужие, перестают получать событие: аналитика не видит клики, выпадающее меню не закрывается по клику снаружи. Найти такую ошибку трудно.

<Wrong>

```js
// сердечко запрещает событию всплывать
heart.addEventListener('click', (event) => {
  event.stopPropagation();
  toggleFavorite(heart);
});
```

</Wrong>

<Right>

```js
// один обработчик на списке разбирается, куда попал клик
list.addEventListener('click', (event) => {
  const heart = event.target.closest('.heart');
  if (heart) {
    toggleFavorite(heart);
    return;
  }
  const card = event.target.closest('.card');
  if (card) selectCard(card);
});
```

</Right>

<Note>

Если нужен вызов обработчика ещё на этапе спуска события вниз (захват), передайте третьим аргументом `{ capture: true }`. В повседневной работе это почти не нужно, достаточно всплытия.

</Note>

## Типичные ошибки

Сообщения получены в Chromium.

**1. Клик мимо кнопки.** `closest` вернул `null`, а код дальше обращается к его свойствам.

```text
TypeError: Cannot read properties of null (reading 'dataset')
```

Добавьте проверку: `if (!button) return;`.

**2. Данные читают с `target`, а не с найденного элемента.** Ошибки нет. Клик по значку даёт `undefined` в `dataset.id`, а в тексте на странице появляется слово `undefined`.

**3. Обработчик подключили к кнопкам, а строки перерисовали.** Ошибки нет, но после перерисовки кнопки новые и обработчика у них нет. Подключайте обработчик к элементу, который не пересоздаётся.

**4. Обработчик на списке, а проверки нет.** Ошибки нет, но любой клик в списке удаляет строку или увеличивает счётчик. Проверяйте, что нашли именно кнопку.

**5. `stopPropagation` ломает аналитику.** Ошибки нет, просто клики по сердечку не попадают в счётчик, который слушает документ. Ищите вызовы `stopPropagation`, когда события «пропадают».

## Итог

Что вы теперь умеете:

- объяснять всплытие и отличать `target` от `currentTarget`;
- находить нужный элемент через `event.target.closest(селектор)` и проверять `null`;
- вешать один обработчик на список вместо сотни и получать работающие строки, добавленные позже;
- понимать, почему `stopPropagation` ломает чужой код.

Вы умеете реагировать на клики, клавиши и ввод. Самое частое место, где всё это встречается вместе, — форма. В следующем уроке разберём, как читать данные формы, проверять их встроенной валидацией браузера и показывать понятные сообщения об ошибках.
