## Зачем это в работе

Каталог «Домотеки» пока живёт в разметке: три чайника написаны руками в HTML. Цена изменилась, товар закончился, привезли новинку, и разработчик снова правит страницу. Так не работает ни один магазин.

Настоящие данные лежат на сервере. Страница спрашивает их у сервера и выводит то, что пришло. В этом уроке вы научитесь делать запрос из JavaScript: получать список товаров, проверять, что сервер ответил успешно, разбирать ответ и отправлять данные обратно.

## Объяснение

Запрос к серверу делает функция `fetch` (с английского «сходить и принести»). Сервер, к которому обращается страница, называют API (application programming interface, «программный интерфейс»): это набор адресов, которые отвечают данными, а не страницами. Данные приходят в формате JSON (JavaScript Object Notation) — это текст, который выглядит как объекты и массивы JavaScript.

Запрос занимает время: сеть не мгновенна. Поэтому `fetch` не возвращает ответ сразу. Он возвращает обещание (Promise) — «квитанцию»: ответ будет позже. Чтобы дождаться его, внутри функции используют слово `await`, а саму функцию помечают словом `async`.

- `async function` — функция, внутри которой можно писать `await`. Она всегда возвращает обещание.
- `await` — «подожди здесь результата». Ждёт только эта функция, остальная страница живёт как раньше: кнопки нажимаются, текст прокручивается.

Ответ приходит в два этапа:

1. `await fetch(адрес)` даёт объект `Response`, как только сервер ответил. В нём уже есть статус (`status`, например 200 или 404) и признак успеха `ok`.
2. `await response.json()` читает тело и превращает JSON-текст в данные. Это тоже обещание, поэтому второй `await`.

Аналогия: заказ в кафе. Вы сделали заказ (fetch) и получили чек (обещание). Пока кухня готовит, вы можете сидеть с телефоном (страница работает). Когда официант принёс поднос (ответ), вы смотрите, что на нём: тот ли это заказ и всё ли в порядке (`ok`). Только потом открываете коробку и едите (`json()`).

## Пример

Загрузка списка товаров в `ul`.

```html
<button id="reload" type="button">Обновить</button>
<ul id="products"></ul>
<p id="status" role="status"></p>
```

```js
const list = document.querySelector('#products');
const status = document.querySelector('#status');

async function loadProducts() {
  const response = await fetch('/api/products');
  if (!response.ok) {
    status.textContent = 'Не удалось загрузить товары (' + response.status + ')';
    return;
  }
  const products = await response.json();
  status.textContent = '';
  list.textContent = '';
  for (const product of products) {
    const item = document.createElement('li');
    item.textContent = product.title + ' — ' + product.price + ' ₽';
    list.append(item);
  }
}

document.querySelector('#reload').addEventListener('click', loadProducts);
loadProducts();
```

Сеть в примерах урока недоступна, поэтому живые примеры работают с готовыми объектами `Response`: у них те же `status`, `ok` и `json()`, что и у настоящих ответов. Сначала о статусах.

## Как это работает

Схема показывает путь запроса и два места, где всё может пойти не так.

<Figure src="fetch-flow.svg" alt="Схема пути запроса. Страница вызывает await fetch и обращается к серверу, сервер возвращает объект Response со статусом, признаком ok и телом. Если сети нет, fetch выбрасывает ошибку, и её ловит блок catch. Если ответ пришёл, проверяется response.ok. Для неуспешного статуса 404, 500 или 503 показывается сообщение об ошибке. Для успешного вызывается await response.json, и данные выводятся на страницу через textContent." caption="Два вида ошибок: сети нет (fetch выбрасывает ошибку) и сервер ответил плохим статусом (fetch ошибку не выбрасывает)." />

Правила, которые стоит запомнить.

1. **`fetch` выбрасывает ошибку, только если ответа нет вообще.** Нет сети, адрес не существует, соединение оборвалось. Тогда в Chrome вы получите `TypeError: Failed to fetch`.
2. **Ответ 404 или 500 — это не ошибка для `fetch`.** Сервер ответил, поэтому обещание выполнено. Вы сами обязаны проверить `response.ok` или `response.status`.
3. **`ok` истинно для статусов от 200 до 299.** Это и 200, и 201 (создано), и 204 (нет содержимого).
4. **Тело читается один раз.** Вторая попытка вызвать `json()` или `text()` у того же ответа закончится ошибкой.
5. **Для ошибок сети используйте `try/catch`.** Блок `try` выполняет код, а `catch` перехватывает выброшенную ошибку:

```js
try {
  const response = await fetch('/api/products');
  const products = await response.json();
  render(products);
} catch (error) {
  status.textContent = 'Нет соединения с сервером';
}
```

Одним `try/catch` вы поймаете и ошибку сети, и ошибку разбора JSON. Но плохой статус он не поймает, его проверяет `if (!response.ok)`.

6. **Чтобы отправить данные, добавьте второй аргумент.**

```js
const response = await fetch('/api/orders', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'Анна', qty: 2 }),
});
```

`JSON.stringify` превращает объект в текст. Заголовок `Content-Type` сообщает серверу, что внутри JSON. Значение, которое подставляется в адрес (например, артикул), пропускайте через `encodeURIComponent`.

<Note>

В этом уроке `async` и `await` показаны на самом простом уровне: одна функция, один запрос подряд. Как работают обещания внутри, что будет при нескольких запросах сразу и как устроена очередь задач, вы разберёте в модуле про асинхронность.

</Note>

## Типичные ошибки

**1. `await` не в async-функции.** Вы написали `await` в обычном скрипте или в функции без `async`:

```text
SyntaxError: await is only valid in async functions and the top level bodies of modules
```

Добавьте слово `async` перед `function`.

**2. Забыли `await` перед `fetch`.** В переменной лежит обещание, а не ответ:

```text
TypeError: response.json is not a function
```

**3. Забыли `await` перед `response.json()`.** Вместо списка в переменной обещание, цикл не может его перебрать:

```text
TypeError: products is not iterable
```

А если вывести такое значение на страницу, вы увидите `[object Promise]`.

**4. Сервер вернул не JSON.** Вместо данных пришла страница ошибки:

```text
SyntaxError: Unexpected token '<', "<!doctype "... is not valid JSON
```

Если тело вообще пустое, будет `Unexpected end of JSON input`. Сначала проверьте `response.ok`, а для сомнительных ответов оберните чтение в `try/catch`.

**5. Нет сети или неверный адрес.** `fetch` выбрасывает ошибку, которую никто не ловит:

```text
TypeError: Failed to fetch
```

В Firefox текст другой, но смысл тот же. Ловите ошибку через `try/catch` и сообщайте человеку, что произошло.

**6. Прочитали тело дважды.**

```text
TypeError: Failed to execute 'json' on 'Response': body stream already read
```

Прочитайте тело один раз и сохраните результат в переменную.

**7. Запрос на чужой домен.** Если страница обращается к другому сайту, а тот не разрешил этого заголовком, браузер блокирует ответ и пишет в консоль про политику CORS. Это не ошибка вашего кода: сервер должен разрешить запросы с вашего адреса.

**8. Данные с сервера вставили через `innerHTML`.** Если в названии товара окажется разметка, она выполнится. Используйте `textContent`.

## Итог

Что вы теперь умеете:

- делать запрос через `await fetch(...)` внутри `async`-функции;
- проверять `response.ok` и `response.status` и не путать плохой статус с отсутствием сети;
- читать JSON через `await response.json()` и отправлять JSON методом `POST`;
- оборачивать чтение ответа в `try/catch`;
- выводить данные сервера через `textContent`.

Пока мы считали, что сервер всегда отвечает быстро и без сбоев. В жизни запрос может идти долго, упасть и повториться. В следующем уроке вы научите страницу показывать загрузку, объяснять ошибку, предлагать «Повторить» и вовремя отменять слишком долгий запрос.
