## Зачем это в работе

В каталоге «Домотеки» сорок карточек, у каждой фотография. Если браузер скачает все сразу, мобильный покупатель потратит трафик на картинки, которые не увидит, а страница будет открываться медленно. Хорошо бы загружать фотографию, когда человек долистал до неё.

И второй сценарий: тысячи товаров не показывают одной страницей. Их подгружают порциями: человек дошёл до конца списка, и появляются следующие товары. Для обоих сценариев нужно одно: знать, что элемент появился на экране.

Раньше для этого слушали событие `scroll` и считали координаты. Это тормозит страницу и путает расчёты. Теперь есть специальный инструмент: Intersection Observer («наблюдатель за пересечением»).

## Объяснение

Intersection Observer следит за элементами и сообщает, когда они входят в область видимости или выходят из неё. Расчёты за вас делает браузер.

Работа в три шага.

1. Создаёте наблюдателя и даёте ему функцию-колбэк: `new IntersectionObserver(callback, options)`.
2. Говорите, за кем следить: `observer.observe(element)`. Элементов может быть сколько угодно.
3. Браузер вызывает колбэк, когда что-то изменилось. В колбэк приходит массив записей `entries`. У каждой записи есть `target` (элемент), `isIntersecting` (виден ли он сейчас) и `intersectionRatio` (какая доля видна).

Когда слежение больше не нужно, вызывают `observer.unobserve(element)` для одного элемента или `observer.disconnect()` для всех сразу.

Настройки (второй аргумент):

- `rootMargin` — насколько расширить область слежения. Записывается как CSS-отступ в строке: `'200px 0px'` (сверху и снизу по 200, по бокам 0). Так загрузка начинается заранее;
- `threshold` — какая доля элемента должна быть видна, чтобы сработал колбэк. `0` — любое пересечение (по умолчанию), `1` — элемент виден целиком.

Аналогия: охранник у входа в магазин. Вы говорите ему: «Сообщи, когда подойдёт этот человек». Он не ходит туда-сюда с вопросами, а стоит и ждёт. Расширенная область слежения — это когда вы просите предупредить заранее, ещё на подходе.

## Пример

Ленивая загрузка картинки. Адрес лежит в `data-src`, а `src` пуст, поэтому браузер ничего не скачивает.

```html
<img data-src="/img/kettle.jpg" alt="Чайник Bosch" width="320" height="240">
```

```js
const observer = new IntersectionObserver((entries) => {
  for (const entry of entries) {
    if (!entry.isIntersecting) continue;
    const img = entry.target;
    img.src = img.dataset.src;
    observer.unobserve(img);
  }
}, { rootMargin: '200px 0px' });

document.querySelectorAll('img[data-src]').forEach((img) => observer.observe(img));
```

Наблюдатель один на все картинки. В колбэке видимые картинки получают `src`, а слежение за ними прекращается. Начинаем за 200 пикселей до экрана, чтобы фото успело загрузиться.

Посмотрим на поведение наблюдателя в модели. Это не настоящий браузер, но порядок уведомлений тот же.

<Playground example="observer-model" />

Обратите внимание на первые три строки: сразу после `observe` пришли записи для всех трёх фотографий, в том числе с `false`. Это важнейшая особенность. Дальше уведомления приходят только при изменении.

<Note>

В тренажёре страница лежит в скрытом окне вне экрана, поэтому настоящий `IntersectionObserver` не срабатывает: для него ничего не пересекает видимую область. Тесты подставляют заглушку и сами вызывают ваш колбэк с записями, как это сделал бы браузер. Поэтому в заданиях наблюдатель создаётся внутри функции (`initLazyImages()`, `initInfiniteScroll()`): тест вызывает её после подстановки заглушки. В обычном браузере ваш код работает без изменений.

</Note>

Бесконечная прокрутка устроена так же, но следят не за картинками, а за пустым блоком в конце списка. Его называют «сторож» (sentinel). Когда сторож приближается к экрану, загружают следующую страницу.

<Playground example="pagination" />

В коде три переменные состояния: номер следующей страницы, флаг «идёт загрузка» и признак «есть ещё страницы». Последний вызов в примере ничего не загрузил: страницы кончились.

Сколько запаса давать? Это арифметика: за время загрузки страница проедет скорость прокрутки умножить на время.

<Playground example="margin-choice" />

Правила, которые стоит запомнить.

1. **Всегда проверяйте `isIntersecting`.** Колбэк вызывается сразу после `observe` и для невидимых элементов.
2. **Обходите все записи.** Они приходят пачкой: если за кадр появились два элемента, придёт одно уведомление с двумя записями.
3. **`unobserve` после работы.** Для ленивой картинки больше нет смысла следить после загрузки.
4. **Один наблюдатель на много элементов.** Не создавайте нового для каждой картинки. В колбэке нужный элемент в `entry.target`.
5. **`unobserve` и `disconnect` — разные вещи.** Первый для одного элемента, второй отключает всё.
6. **Защита от дублей при загрузке порциями.** Флаг «идёт загрузка» и признак «есть ещё»: иначе одна страница запросится дважды, а после последней придёт запрос в никуда.
7. **Сторож может остаться на экране.** Если после подгрузки он всё ещё виден, новое уведомление не придёт: наблюдатель сообщает об изменении. Решение: `unobserve` и снова `observe`, тогда браузер скажет о текущем состоянии заново.
8. **Бесконечная лента вредит доступности.** Пользователь с клавиатурой не доберётся до подвала. Нужна кнопка «Показать ещё» или ссылка на подвал. Это решение стоит обсуждать с дизайнером заранее.

## Типичные ошибки

**1. Нет проверки `isIntersecting`.** Все картинки загружаются при открытии страницы. Ошибки в консоли нет, и именно поэтому её трудно найти: откройте сетевую панель.

<Wrong>

```js
entries.forEach((entry) => {
  entry.target.src = entry.target.dataset.src;
});
```

</Wrong>

<Right>

```js
entries.forEach((entry) => {
  if (!entry.isIntersecting) return;
  entry.target.src = entry.target.dataset.src;
});
```

</Right>

**2. Только `entries[0]`.** Вторая картинка из пачки остаётся пустой.

**3. `rootMargin` числом.** Chromium отвечает:

```text
SyntaxError: Failed to construct 'IntersectionObserver': rootMargin must be specified in pixels or percent.
```

Нужна строка с единицами: `'200px'` или `'200px 0px'`.

**4. Порог вне диапазона.** Значение `threshold` должно быть от 0 до 1:

```text
RangeError: Failed to construct 'IntersectionObserver': Threshold values must be numbers between 0 and 1
```

**5. Колбэк не функция.** Если перепутать аргументы и передать настройки первыми:

```text
TypeError: Failed to construct 'IntersectionObserver': parameter 1 is not of type 'Function'.
```

**6. Наблюдают не элемент.** Например, `observe(null)` потому, что `querySelector` ничего не нашёл:

```text
TypeError: Failed to execute 'observe' on 'IntersectionObserver': parameter 1 is not of type 'Element'.
```

**7. `disconnect` вместо `unobserve`.** После первой загрузки наблюдатель отключился от всех картинок, остальные не загрузятся никогда.

**8. Нет флага загрузки.** Две быстрые прокрутки запросили одну и ту же страницу, в списке дубли.

## Итог

Что вы теперь умеете:

- создавать `IntersectionObserver`, следить за элементами и обходить пачку записей;
- проверять `isIntersecting` и снимать слежение через `unobserve`;
- подбирать `rootMargin` и `threshold` по скорости прокрутки и времени загрузки;
- грузить картинки лениво и подгружать товары порциями без дублей и лишних запросов;
- объяснять, чем бесконечная лента вредит доступности и как это смягчить.

Теперь страница реагирует на прокрутку и подгружает данные. Но есть похожая задача: человек вводит текст в поиск, а страница на каждую букву шлёт запрос к серверу. Это тоже нужно сдерживать. В следующем уроке разберём дебаунс и троттлинг: как откладывать и ограничивать частые события.
