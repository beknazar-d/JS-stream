# Разбор

Старый код создавал наблюдателя в цикле и «зашивал» в колбэк конкретную картинку через замыкание. Один наблюдатель умеет следить за любым числом элементов, а в колбэке нужный элемент приходит в записи: `entry.target`. Поэтому замыкание не нужно.

Что поменялось.

1. **Один `new IntersectionObserver`** вне цикла. Цикл остался только для `observe`.
2. **Колбэк проходит по всем записям.** У старого наблюдателя за одну картинку всегда приходила одна запись, поэтому `entries[0]` работало. У общего записей может быть много: они приходят пачкой.
3. **`unobserve(img)`, а не `disconnect()`.** `unobserve` прекращает слежение за одним элементом. `disconnect` отключает наблюдателя от всех элементов. В старом коде это было одно и то же (наблюдатель следил за одной картинкой), в новом — совсем разные вещи, и это главная ловушка рефакторинга.

Поведение для покупателя не изменилось: картинка грузится, когда подходит к экрану, и больше за ней никто не следит.

Когда в каталог добавят новые карточки (например, подгрузят следующую страницу), достаточно снова вызвать `observer.observe(img)` для новых картинок. С одним общим наблюдателем это проще, чем создавать нового для каждой.
