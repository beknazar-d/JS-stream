# Разбор

Решение состоит из трёх частей: состояние, загрузка, наблюдатель.

## Состояние

- `nextPage` — какую страницу просить следующей;
- `loading` — идёт ли запрос прямо сейчас;
- `hasMore` — остались ли страницы.

Без `loading` получится гонка. Пока сервер отвечает, наблюдатель может сообщить о сторожe ещё раз, и та же страница запросится дважды: в списке появятся дубли.

## Загрузка

`loadNextPage` сначала проверяет флаги и выходит, если грузить нельзя или нечего. Потом показывает `#status`, запрашивает страницу, добавляет товары, обновляет `hasMore` по `totalPages`. Номер следующей страницы берётся из ответа (`data.page + 1`), а не из локального счётчика, который мог сбиться.

Названия выводятся через `textContent`, поэтому `<b>Pro</b>` из названия остаётся текстом и не превращается в разметку.

## Наблюдатель

```js
observer = new IntersectionObserver(
  (entries) => {
    if (entries.some((entry) => entry.isIntersecting)) loadNextPage();
  },
  { rootMargin: '300px 0px' },
);
```

Колбэк только решает «пора ли». `rootMargin: '300px 0px'` начинает загрузку за 300 пикселей до сторожа, чтобы покупатель не упирался в конец списка.

Две тонкости.

1. **Повторное наблюдение.** Наблюдатель сообщает о сторожe, когда тот *пересёк границу*. Если после подгрузки сторож всё ещё на экране (высокий монитор, мало товаров), нового сообщения не будет, и лента застрянет. `unobserve` и снова `observe` заставляют браузер сообщить о текущем состоянии заново.
2. **Конец ленты.** Когда страниц нет, `unobserve(sentinel)` снимает слежение. Флаг `hasMore` защищает и от запоздалых вызовов колбэка.

## Вопросы, которые стоило задать

1. Что показывать при ошибке сети: сообщение, автоповтор, кнопку? Есть ли ограничение на число повторов?
2. Как до подвала сайта доберётся пользователь клавиатуры или скринридера? Бесконечная лента без запасного пути вредит доступности: нужна кнопка «Показать ещё» или ссылка «К подвалу».
3. Что происходит при возврате «Назад»: должна ли лента запомнить загруженные страницы и позицию прокрутки? Это можно решать через историю или через `sessionStorage`.
4. Сколько товаров в порции и что делать, если на странице их меньше шести? Сейчас размер порции жёстко задан в запросе.
5. Нужен ли общий предел числа загруженных карточек, чтобы страница не разрасталась без конца?
