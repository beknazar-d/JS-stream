## Контекст

Тикет ONB-310. Новые разработчики теряют первый день на настройку: у одного не стоит Node.js, у другого версия старая, у третьего сломан npm. Команда хочет скрипт `check-setup`, который запускает `node -v` и `npm -v` и сообщает обо всех проблемах сразу, а не по одной.

Запуск команд делает другая часть скрипта. Вам нужна функция, которая принимает уже полученный вывод двух команд и решает, что с окружением.

```text
$ node -v
v22.22.0
$ npm -v
10.9.4
```

Если команда не найдена, вместо версии придёт текст ошибки терминала:

```text
$ node -v
bash: node: command not found
```

## Цель

Допишите функцию `checkSetup(nodeOutput, npmOutput, minNodeMajor)` в `index.js`. Она возвращает массив строк с описанием проблем. Если проблем нет, массив пустой.

## Критерии приёмки

- Всё в порядке (например, `"v22.22.0"`, `"10.9.4"`, минимум `22`): результат `[]`.
- Вывод `node -v` не похож на версию (не начинается с «v» после `trim()` или после «v» нет числа): в массив попадает ровно `"Node.js не найден. Установите версию LTS с nodejs.org и откройте новый терминал."`.
- Node.js найден, но его мажорная версия меньше `minNodeMajor`: в массив попадает `"Node.js 18 устарел: нужна версия 22 или новее."` (числа подставляются реальные: найденная версия и `minNodeMajor`).
- Вывод `npm -v` не похож на версию (первая часть до точки не число): в массив попадает ровно `"npm не найден. Он ставится вместе с Node.js: переустановите Node.js."`.
- Проверки независимы: если плохи и Node.js, и npm, в массиве два сообщения, сначала про Node.js, потом про npm.
- Пробелы и перевод строки по краям вывода не мешают.

## Ограничения

- Не используйте регулярные выражения: хватит `trim`, `startsWith`, `slice`, `split`, `Number`, `Number.isNaN` и `push`.
- Функция не запускает команды сама и не читает файлы, она только разбирает переданные строки.
- Для строки из переменных используйте сложение строк: `"Node.js " + major + " устарел"`.
