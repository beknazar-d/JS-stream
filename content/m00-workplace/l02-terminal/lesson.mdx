## Зачем это в работе

Вы пишете коллеге: «Скрипт не запускается». Он отвечает одним вопросом: «А ты в какой папке?» Вы не знаете, что ответить.

Терминал всегда находится в какой-то папке. Команды работают с файлами этой папки. Если вы запускаете `node src/index.js`, а терминал стоит не там, Node.js ищет файл не в том месте и пишет `Cannot find module`.

В этом уроке вы научитесь отвечать на три вопроса: где я, что здесь лежит, как попасть туда, куда нужно.

## Объяснение

Папка (folder, по-английски также directory) — это контейнер для файлов и других папок. Папки вкладываются друг в друга, как коробки: коробка в коробке.

Путь (path) — это адрес файла или папки. Он перечисляет папки, через которые нужно пройти. Папки в пути разделены косой чертой.

Представьте многоэтажный дом. Полный адрес: «Россия, Москва, улица, дом, квартира». Короткий адрес для соседа: «через две двери налево». Первый одинаков для всех. Второй зависит от того, откуда вы идёте.

Так и в терминале.

- Абсолютный путь (absolute path) — полный адрес от самого верха. Он работает откуда угодно. На macOS и Linux начинается с `/`, например `/home/anna/shop`. На Windows начинается с буквы диска: `C:\Users\anna\shop`.
- Относительный путь (relative path) — адрес от той папки, где вы стоите сейчас. Она называется текущей папкой (current working directory). Например, `src/index.js`: «здесь есть папка src, в ней файл index.js».

В относительных путях есть два особых имени:

- `.` (одна точка) — текущая папка;
- `..` (две точки) — папка на уровень выше.

Ещё одно сокращение: `~` (тильда) означает домашнюю папку пользователя: `/home/anna` на Linux, `/Users/anna` на macOS. Оно работает в macOS, Linux и PowerShell. В старой командной строке Windows (cmd) его нет.

## Пример

Посмотрите, из чего состоит путь. Он обычная строка, и его можно разрезать по косой черте.

<Playground example="path-parts" />

Обратите внимание на первый элемент: он пустой. Путь `/home/...` начинается с косой черты, и перед ней ничего нет. Эта пустая часть и есть признак абсолютного пути.

Теперь пять основных команд. Знак доллара и название папки — это приглашение терминала, вводить их не нужно.

```text
anna@vm:~/shop$ pwd
/home/anna/shop
anna@vm:~/shop$ ls
 README.md   docs   hello.js  'price lists'   src
anna@vm:~/shop$ cd src
anna@vm:~/shop/src$ pwd
/home/anna/shop/src
anna@vm:~/shop/src$ cd ../docs
anna@vm:~/shop/docs$ pwd
/home/anna/shop/docs
```

- `pwd` (print working directory) печатает, где вы сейчас.
- `ls` (list) показывает содержимое текущей папки.
- `cd папка` (change directory) переходит в папку.
- `mkdir имя` (make directory) создаёт новую папку.
- `cd ..` поднимает вас на уровень выше.

Приглашение терминала само показывает текущую папку, поэтому `pwd` нужен нечасто. Но в сообщениях об ошибках и в командах важно понимать, где вы.

### Windows и macOS: что отличается

| Что сделать | macOS и Linux | Windows PowerShell | Windows cmd |
| --- | --- | --- | --- |
| Где я | `pwd` | `pwd` | `cd` без аргументов |
| Что здесь лежит | `ls` | `ls` или `dir` | `dir` |
| Перейти в папку | `cd папка` | `cd папка` | `cd папка` |
| Создать папку | `mkdir имя` | `mkdir имя` | `mkdir имя` |
| Подняться выше | `cd ..` | `cd ..` | `cd ..` |

Различия такие:

- разделитель в путях: `/` на macOS и Linux, `\` на Windows (PowerShell понимает и `/`);
- Windows начинает пути с буквы диска: `C:\`, `D:\`;
- в терминале VS Code на Windows по умолчанию открывается PowerShell. Команды из таблицы в нём работают.

Два совета, которые экономят часы. Клавиша `Tab` дописывает имя файла или папки: введите начало и нажмите её. Клавиша «стрелка вверх» вызывает предыдущую команду.

## Как это работает

Терминал помнит одну текущую папку. Каждая команда с относительным путём начинает отсчёт от неё. `cd` меняет эту папку, остальные команды её только читают.

Когда вы пишете `cd ../docs`, терминал делает это по шагам.

1. Берёт текущую папку: `/home/anna/shop/src`.
2. Склеивает с вашим путём: `/home/anna/shop/src/../docs`.
3. Упрощает: `..` убирает предыдущую папку, `.` ничего не меняет. Получается `/home/anna/shop/docs`.

Пример ниже показывает, почему простой склейки недостаточно: две точки остаются в строке.

Если путь начинается с `/` (или с буквы диска), он абсолютный, и текущая папка не используется. Подняться выше корня нельзя: из корня `cd ..` оставляет вас в корне.

Те же правила работают, когда вы запускаете скрипты: `node src/index.js` ищет `src` от текущей папки. Поэтому вопрос «в какой я папке» важнее всего.

## Типичные ошибки

Сообщения ниже получены в терминале bash (macOS и Linux). У PowerShell тексты другие, но причины те же.

**1. Такой папки нет.**

<Wrong>

```text
anna@vm:~/shop$ cd papka
bash: cd: papka: No such file or directory
```

</Wrong>

«No such file or directory» значит «нет такого файла или папки». Проверьте написание через `ls`. Ошибка бывает и в регистре: на macOS и Linux `Src` и `src` — разные папки.

**2. Пробел в имени папки.**

<Wrong>

```text
anna@vm:~/shop$ cd price lists
bash: cd: too many arguments
```

</Wrong>

Терминал решил, что `price` и `lists` — два разных слова. Если в имени есть пробел, возьмите путь в кавычки или нажмите `Tab`, чтобы терминал сам поставил защиту.

<Right>

```text
anna@vm:~/shop$ cd "price lists"
anna@vm:~/shop/price lists$
```

</Right>

**3. Папка уже существует.**

```text
anna@vm:~/shop$ mkdir src
mkdir: cannot create directory ‘src’: File exists
```

Создавать нечего: папка уже есть. Это не поломка, просто сообщение.

**4. Скрипт запущен не из той папки.** Вы уже в `src` и повторяете команду для корня проекта.

<Wrong>

```text
anna@vm:~/shop/src$ node src/index.js
node:internal/modules/cjs/loader:1386
  throw err;
  ^

Error: Cannot find module '/home/anna/shop/src/src/index.js'
    ...
```

</Wrong>

Посмотрите на путь в сообщении: `src/src/index.js`. Node.js приклеил `src/index.js` к текущей папке `src`. Либо вернитесь командой `cd ..`, либо запустите из этой папки как `node index.js`.

<Right>

```text
anna@vm:~/shop/src$ node index.js
hi
```

</Right>

## Итог

Что вы теперь умеете:

- ответить, где вы сейчас (`pwd`), что здесь лежит (`ls`) и перейти в другую папку (`cd`);
- отличить абсолютный путь от относительного;
- понимать, что `.` — это текущая папка, а `..` — папка выше;
- читать ошибки `No such file or directory` и `Cannot find module` и находить причину в пути;
- помнить, что на Windows путь выглядит иначе, а команды в PowerShell те же.

Теперь вы можете спокойно работать в проектной папке. Дальше будем сохранять историю изменений: следующий урок про Git.
