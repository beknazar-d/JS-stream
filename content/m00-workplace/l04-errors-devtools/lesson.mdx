## Зачем это в работе

Тестировщик присылает скриншот: красный текст в консоли и подпись «заказ с доставкой не оформляется». Вы смотрите на десять строк непонятных слов и не знаете, с чего начать.

Хорошая новость: в этих десяти строках почти всегда написано, что сломалось и где. Нужно только уметь их читать. Это умение экономит больше времени, чем любой другой навык начинающего разработчика.

В этом уроке вы разберёте сообщение об ошибке по частям, научитесь находить файл и строку и пользоваться двумя инструментами отладки (debugging, поиск и исправление ошибок): `console.log` и точками останова.

## Объяснение

Когда код не может выполниться, Node.js или браузер останавливают программу и печатают сообщение об ошибке (error). Оно состоит из четырёх частей.

1. Место: файл и номер строки, где программа остановилась.
2. Тип ошибки (например, `TypeError`).
3. Текст: что именно не получилось.
4. Стектрейс (stack trace, «след вызовов»): список функций, которые привели к этому месту.

Представьте стопку записок. Каждая функция, когда вызывает другую, кладёт сверху записку: «я вызвала вот эту». Когда случается ошибка, стопку читают сверху вниз. Верхняя записка — где сломалось. Ниже — кто туда привёл. В самом низу — с чего всё началось.

Типы ошибок, которые вы встретите чаще всего:

- `SyntaxError` — код написан с нарушением правил языка (забыли скобку или кавычку). Программа даже не стартует.
- `ReferenceError` — использовано имя, которого нет (опечатка в имени переменной).
- `TypeError` — со значением делают то, что с ним делать нельзя: вызывают не функцию или читают свойство у `undefined`.

## Пример

Сценарий из жизни: расчёт доставки по весу. Вес приходит текстом с запятой, например `"2,5"`. Три функции вызывают друг друга. Вот файл `src/delivery.js`:

```js
function parseWeight(text) {
  return Number(text.replace(",", "."));
}

function shippingCost(weightText) {
  const kg = parseWeight(weightText);
  return 150 + kg * 40;
}

export function orderShipping(weightText) {
  return shippingCost(weightText);
}
```

И файл `src/index.js`, который его вызывает дважды: с весом и без:

```js
import { orderShipping } from "./delivery.js";

console.log("Доставка:", orderShipping("2,5"));
console.log("Доставка:", orderShipping(undefined));
```

Результат запуска `node src/index.js`:

```text
Доставка: 250
file:///home/anna/shop/src/delivery.js:2
  return Number(text.replace(",", "."));
                     ^

TypeError: Cannot read properties of undefined (reading 'replace')
    at parseWeight (file:///home/anna/shop/src/delivery.js:2:22)
    at shippingCost (file:///home/anna/shop/src/delivery.js:6:14)
    at orderShipping (file:///home/anna/shop/src/delivery.js:11:10)
    at file:///home/anna/shop/src/index.js:4:26
    at ModuleJob.run (node:internal/modules/esm/module_job:343:25)
    at async onImport.tracePromise.__proto__ (node:internal/modules/esm/loader:665:26)
    at async asyncRunEntryPointWithESMLoader (node:internal/modules/run_main:117:5)

Node.js v22.22.0
```

Читаем по порядку.

1. Первая строка вывода, `Доставка: 250`, — первый вызов отработал.
2. `delivery.js:2` — сломалось в файле `delivery.js` на строке 2. Стрелка `^` показывает место в строке.
3. `TypeError: Cannot read properties of undefined (reading 'replace')`: «нельзя читать свойство `replace` у значения `undefined`». Значит, в переменной `text` лежит `undefined`, а не строка.
4. Стектрейс. Верхняя строка `at parseWeight (…delivery.js:2:22)`: функция `parseWeight`, строка 2, столбец 22. Ниже: её вызвал `shippingCost`, того — `orderShipping`, того — файл `index.js` на строке 4. Эта строка вызывает `orderShipping(undefined)`.
5. Строки `node:internal/...` — внутренности Node.js. Их пропускаем: ищем строки со своими файлами.

Ошибка находится в строке 2, а причина — в строке 4 файла `index.js`, где передали `undefined`. Стектрейс нужен именно для этого: место ошибки и место причины часто разные.

## Как это работает

Два способа отладки: напечатать значения или остановить программу и посмотреть.

### Способ 1: console.log

Метод `console.log` вы уже знаете. Есть ещё два: `console.warn` для предупреждений и `console.error` для ошибок. В DevTools они подсвечиваются по-разному, а в терминале `error` и `warn` идут в отдельный поток.

<Playground example="console-levels" />

Отладка логами: печатаете значения на каждом шаге и ищете место, где они перестали быть такими, как вы ждали.

<Playground example="debug-logs" />

Во втором вызове видно: `ratePerKg` равен `undefined`, поэтому `cost` стал `NaN`. Сообщения об ошибке нет, но по логам причина найдена за секунду. Подписывайте значения («ratePerKg:»), иначе в куче чисел вы не поймёте, что откуда. Когда ошибка найдена, лишние логи удаляйте.

### Способ 2: точка останова

Точка останова (breakpoint) — отметка на строке: программа дойдёт до неё и замрёт. Вы увидите значения всех переменных и сможете идти дальше по одной строке.

Как это сделать в браузере (Chrome, Edge, Firefox похожи):

1. Откройте DevTools (developer tools, «инструменты разработчика»): клавиша `F12` или `Ctrl+Shift+I` (на macOS `Cmd+Option+I`).
2. Откройте вкладку Sources («Источники»), выберите свой файл.
3. Щёлкните по номеру строки: появится синяя отметка.
4. Обновите страницу. Программа остановится на этой строке.
5. Справа в блоке Scope («Область») видны значения переменных.

Кнопки управления:

- Resume (`F8`) — продолжить до следующей точки;
- Step over (`F10`) — выполнить строку целиком и перейти к следующей;
- Step into (`F11`) — зайти внутрь вызываемой функции;
- Step out (`Shift+F11`) — выйти из текущей функции.

В самом коде точку останова можно поставить словом `debugger;`: если DevTools открыты, браузер остановится на этой строке. В VS Code то же самое делается кликом слева от номера строки и запуском отладки клавишей `F5`.

<Note>

Убирайте `console.log` и `debugger` перед коммитом. Лишние отладочные строки попадают в репозиторий чаще, чем кажется.

</Note>

## Типичные ошибки

Все сообщения ниже получены запуском в Node.js 22.

**1. Забыли закрыть скобку.**

<Wrong>

```js
const items = 3;
const price = 1200;
console.log("Итого:", items * price
console.log("Готово");
```

</Wrong>

```text
file:///home/anna/shop/cart.js:3
console.log("Итого:", items * price
                              ^^^^^

SyntaxError: missing ) after argument list
```

Фраза «missing ) after argument list» значит «не хватает закрывающей скобки после списка аргументов». Ошибка указана в строке 3, но скобку надо дописать в её конце. Если строка выглядит правильно, посмотрите на строку выше.

**2. Лишний знак.**

```text
$ node -e 'const price = ;'
SyntaxError: Unexpected token ';'
```

«Unexpected token» значит «неожиданный символ»: после знака `=` ждали значение, а встретили точку с запятой.

**3. Опечатка в имени.**

<Wrong>

```js
let total = 100;
console.log(totl);
```

</Wrong>

```text
ReferenceError: totl is not defined
```

«is not defined» значит «не определено». Сверьте написание с объявлением.

**4. Вызвали метод числа у строки.**

```text
TypeError: price.toFixed is not a function
```

Значение `price` не число, а строка. Вспомните урок про типы в модуле 1: данные из формы приходят строками.

**5. Читаем свойство у «ничего».**

```text
TypeError: Cannot read properties of undefined (reading 'name')
```

Слева от точки стоит `undefined`. В скобках названо свойство, которое пытались прочитать. Ищите, почему значение не появилось.

**6. Присвоили значение константе.**

```text
TypeError: Assignment to constant variable.
```

Значение, объявленное словом `const`, менять нельзя. Подробнее — в уроке про переменные.

**7. Объявили одно имя дважды.**

```text
SyntaxError: Identifier 'a' has already been declared
```

## Итог

Что вы теперь умеете:

- разобрать сообщение об ошибке на место, тип, текст и стектрейс;
- найти в стектрейсе первую строку из вашего кода и понять, где ошибка и где её причина;
- отличить `SyntaxError`, `ReferenceError` и `TypeError`;
- отладить код через `console.log`, а при необходимости остановить его точкой останова и пройти по шагам.

На этом модуль «Рабочее место» закончен. Вы умеете запускать код, ходить по папкам, хранить историю в Git и читать ошибки. Теперь можно учить сам язык.

Начните с урока «Значения, типы и преобразования типов»: [перейти к уроку 1.1](/m01-js-basics/l01-values-and-types). В нём вы узнаете, почему `"12" + 3` даёт `123` и откуда берётся `NaN` из отладочных логов.
