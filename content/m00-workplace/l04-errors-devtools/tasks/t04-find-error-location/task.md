## Контекст

Тикет DEVEX-9. Инструмент сбора ошибок должен по тексту стектрейса сразу показывать разработчику, куда открыть файл. Надо найти первую строку стектрейса из вашего кода (не из внутренностей Node.js) и вернуть файл, строку и столбец.

Реальные кадры стектрейса бывают трёх видов:

```text
    at Object.<anonymous> (/home/anna/shop/typo.js:1:9)
    at parseWeight (file:///home/anna/shop/src/delivery.js:2:22)
    at file:///home/anna/shop/src/index.js:4:26
```

Первый и второй — с именем функции и местом в скобках. Третий — без имени, место сразу после `at`. Внутренние кадры Node.js выглядят так:

```text
    at Module._compile (node:internal/modules/cjs/loader:1706:14)
```

В Windows путь содержит букву диска с двоеточием: `at calcTotal (C:\Users\anna\shop\src\cart.js:7:21)`.

## Цель

Допишите функцию `findErrorLocation(stackText)` в `index.js`. Она принимает многострочный текст сообщения об ошибке и возвращает объект `{ file, line, column }` для первого кадра с вашим кодом. Если такого кадра нет, возвращает `null`.

## Критерии приёмки

- `file` — путь к файлу без префикса `file://`, `line` и `column` — числа.
- Кадры, место которых начинается с `node:`, пропускаются.
- Кадры без номеров строки и столбца (например, `at new Promise (<anonymous>)`) пропускаются.
- Строки, которые не начинаются с `at ` (после пробелов), игнорируются: заголовок ошибки, код с указателем и пустые строки.
- Двоеточия внутри пути (`file:///`, буква диска Windows) не мешают.
- Если подходящего кадра нет, результат `null`.

## Ограничения

- Не используйте регулярные выражения.
- Менять только тело `findErrorLocation`.
