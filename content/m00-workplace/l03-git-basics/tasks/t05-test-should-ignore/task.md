## Контекст

В инструменте публикации есть функция `shouldIgnore(path, rules)`: она решает, надо ли игнорировать файл по простым правилам в стиле `.gitignore`. Тестов у неё нет, а на следующей неделе её будут переписывать. Если сломается правило, в репозиторий уйдёт файл с паролями или, наоборот, потеряется нужный файл.

Ваша задача — написать тесты, которые защитят функцию от поломки.

## Цель

Напишите тесты в `index.test.js` для функции `shouldIgnore` из файла `subject/index.js` (код показан под описанием). Функция работает так:

- `path` — путь к файлу с прямыми косыми чертами: `src/index.js`;
- `rules` — массив правил; файл игнорируется, если подошло хотя бы одно правило;
- правило, заканчивающееся на `/`, — папка: игнорируются файлы внутри папки с таким именем, лежащей на любом уровне вложенности;
- правило вида `*.log` — файлы, имя которых заканчивается на `.log` (точка обязательна);
- любое другое правило — файл с точно таким именем, на любом уровне вложенности.

## Критерии приёмки

- Все ваши тесты проходят на показанной реализации.
- Проверка находит каждую из трёх реализаций с ошибкой: тесты должны падать на каждой.
- Проверяется только результат для входных данных, а не устройство функции.
- Названия тестов описывают случай на русском языке.

## Ограничения

- Пишите тесты только в `index.test.js`. Код функции менять нельзя.
- Используйте `describe`, `it` и `expect` без импорта. Из `index.js` импортируйте только `shouldIgnore`.
- Подумайте о вложенных папках и о файлах с похожими именами.
