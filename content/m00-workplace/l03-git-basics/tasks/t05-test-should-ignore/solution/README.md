# Разбор

Хорошие тесты проверяют не только то, что правило срабатывает, но и то, что оно не срабатывает на похожем. Для `shouldIgnore` важны три места.

1. **Вложенность папок.** Правило `node_modules/` должно работать на любом уровне. Тест `packages/app/node_modules/lib.js` ловит реализацию, которая смотрит только на первую папку.
2. **Похожие имена.** Правило `.env` не должно задевать `.env.example`: этот файл как раз нужно хранить в репозитории. Правило `*.log` не должно задевать `changelog`. Без таких проверок ошибки «содержит» и «забыли точку» не видны.
3. **Отрицательные проверки.** Три теста с `false` не менее важны, чем с `true`: функция, которая игнорирует всё подряд, прошла бы все проверки «игнорируется».

Тесты проверяют результат и не лезут в устройство функции, поэтому переживут её переписывание.
