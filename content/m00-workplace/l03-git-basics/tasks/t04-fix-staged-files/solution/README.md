# Разбор

Код состояния в `git status --short` состоит из двух символов. Первый описывает индекс, второй — рабочую папку:

- `M ` — изменение в индексе, войдёт в коммит;
- ` M` — изменение только в рабочей папке, в коммит не войдёт;
- `MM` — изменения есть и там, и там; в коммит войдёт то, что в индексе.

Функция смотрела на `code[1]`, то есть на рабочую папку. Поэтому ` M src/order.js` (изменён, но не добавлен) попадал в список, а `M  src/cart.js` (добавлен) пропадал.

Исправление — проверять `code[0]`. Файл в индексе, если первый символ — не пробел и не `?` (вопросительный знак значит «Git за файлом не следит», в индексе его нет).

Этот баг типичен: два похожих символа в одной строке, а смотрят не на тот. Помогает простое правило: сначала выпишите на бумаге, что означает каждая позиция кода.
