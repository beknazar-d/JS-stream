# Разбор

Идея: в каждый момент живёт не больше одного «актуального» запроса. Это замыкание с одной переменной `current`.

1. **Один контроллер на вызов.** Отменённый сигнал вернуть в строй нельзя, поэтому каждый вызов `suggest` создаёт новый контроллер.
2. **Отмена предыдущего.** В начале вызова мы отменяем `current`. Если предыдущий запрос уже закончился, `abort()` ничего не меняет, а если ещё идёт, то получает сигнал остановиться.
3. **`throwIfAborted()` после `await`.** Хороший `load` сам завершится при отмене. Но `suggest` не может на это рассчитывать, поэтому после ответа проверяет сигнал. Метод бросает `signal.reason`, то есть `AbortError`.
4. **Завершённый вызов не страдает.** Его контроллер отменит следующий вызов, но проверка уже пройдена, результат отдан.

## Вопросы, которые стоило задать

1. Что показывать при ошибке последнего запроса?
2. Нужна ли пауза перед запросом (debounce)? Её добавляют отдельно, поверх `suggest`.
3. Нужен ли кэш? Кэш с временем жизни будет в проекте этого модуля.
4. Как отличить `AbortError` от настоящей ошибки в интерфейсе: по `error.name`.
