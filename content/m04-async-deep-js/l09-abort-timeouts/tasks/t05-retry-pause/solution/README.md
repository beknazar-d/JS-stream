# Разбор

Цикл `for` без условия выхода: выходим через `return` (успех) или `throw` (попытки закончились или отмена).

1. **Проверка отмены перед попыткой.** `signal?.throwIfAborted()` бросает `signal.reason`, если сигнал уже отменён. Первый вызов `task` для отменённого сигнала не происходит. Знак `?.` нужен, потому что сигнал необязателен.
2. **Ошибка `task`.** В `catch` два решения. Сигнал отменён: это не сбой службы, а решение клиента, выбрасываем причину отмены. Попытка последняя: выбрасываем последнюю ошибку и не ждём.
3. **Пауза через `sleep(pauseMs, signal)`.** Если сигнал отменят во время паузы, `sleep` отклонится сам, таймер очистится, и цикл прервётся. Следующий `task` не вызывается.
4. **`attempts` — общее число вызовов.** Цикл начинается с 1, условие `attempt >= attempts`.

Эта функция — основа для «клиента нестабильного API» в проекте P4: там добавятся экспоненциальная пауза и выбор ошибок, которые стоит повторять.

## Вопросы, которые стоило задать

1. Повторять ли любые ошибки? Ошибка 404 не исправится от повтора. В проекте P4 мы научимся это различать.
2. Нужна ли случайная добавка к паузе (jitter), чтобы тысячи клиентов не повторяли запрос в один момент?
