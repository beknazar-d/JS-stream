## Зачем это в работе

Пришёл тикет от продакт-менеджера «Домотеки». На странице оформления заказа поле «Адрес» подсказывает улицы. Человек печатает «Каз», потом «Казань». Запрос на «Каз» ушёл первым, но ответа на него пришлось ждать дольше. В итоге ответ на «Каз» приходит после ответа на «Казань» и затирает свежие подсказки. А ещё служба доставки иногда просто молчит: запрос висит, и страница ждёт вечно.

Три проблемы из одной семьи:

- запрос, который уже никому не нужен, продолжает работать;
- запрос, который завис, ждёт без предела;
- запрос, который упал по случайной причине, никто не повторил.

В прошлых уроках мы научились ждать промисы. Этот урок про то, как перестать ждать вовремя: отменить, ограничить, повторить.

```js
const controller = new AbortController();
controller.abort();
console.log(controller.signal.aborted);
```

```text
true
```

## Объяснение

У промиса нет кнопки «отменить». Промис — это обещание результата, и оно или выполнится, или нет. Поэтому отмену придумали отдельно, в виде двух объектов.

Представьте телевизор и пульт. Телевизор — это сигнал отмены (`AbortSignal`). Пульт — контроллер отмены (`AbortController`). Пульт у вас, телевизор вы отдаёте тому, кого можно выключить: запросу, паузе, циклу. Нажали кнопку на пульте, и все телевизоры, которые к нему привязаны, получили команду.

Как это выглядит в коде:

- `new AbortController()` создаёт пульт. У него есть свойство `signal` и метод `abort()`.
- `signal.aborted` — отменён ли сигнал (`true` или `false`).
- Событие `abort` на сигнале срабатывает в момент отмены. Оно приходит один раз.
- `signal.reason` — причина отмены. Если не указать свою, это `DOMException` с именем `AbortError`.
- `signal.throwIfAborted()` бросает причину, если сигнал отменён. Удобно, чтобы прервать работу в середине функции.

Сигнал сам ничего не останавливает. Он только сообщает. Останавливает тот, кто его получил: он должен слушать сигнал и вовремя прекратить работу. `fetch` в браузере так делает: ему передают `{ signal }`.

Заметьте: второй `abort()` с другой причиной ничего не изменил. Сигнал отменяется один раз и навсегда. Поэтому на каждую новую операцию нужен новый контроллер.

## Пример

Вот самая полезная заготовка урока: пауза, которую можно отменить. Она нужна и для таймаутов, и для повторов.

```js
function sleep(ms, signal) {
  return new Promise((resolve, reject) => {
    if (signal?.aborted) {
      reject(signal.reason);
      return;
    }
    const timer = setTimeout(resolve, ms);
    signal?.addEventListener('abort', () => {
      clearTimeout(timer);
      reject(signal.reason);
    }, { once: true });
  });
}
```

Три правила, которые тут видны:

1. Сначала проверяем `signal.aborted`. Если сигнал уже отменён, событие `abort` не придёт во второй раз, и пауза пошла бы целиком.
2. При отмене очищаем таймер. Иначе он останется в очереди.
3. Причину отмены отдаём как есть: `signal.reason`.

Теперь таймаут. Хотим ждать запрос не дольше `ms` и при этом сказать самому запросу «остановись».

<Wrong>

```js
function withTimeout(load, ms) {
  const timeout = new Promise((_, reject) => {
    setTimeout(() => reject(new Error('Таймаут')), ms);
  });
  return Promise.race([load(), timeout]);
}
```

</Wrong>

<Right>

```js
async function withTimeout(load, ms) {
  const controller = new AbortController();
  let timer;
  const timeout = new Promise((_, reject) => {
    timer = setTimeout(() => {
      const error = new Error(`Таймаут: ${ms} мс`);
      controller.abort(error);
      reject(error);
    }, ms);
  });
  try {
    return await Promise.race([load(controller.signal), timeout]);
  } finally {
    clearTimeout(timer);
  }
}
```

</Right>

Что исправлено. `Promise.race` лишь выбирает победителя, проигравшего он не останавливает. В неправильном варианте таймер живёт после ответа и запрос не знает про таймаут. В правильном таймер очищается в `finally`, а запрос получает сигнал.

<Note>

В браузерах и Node.js есть готовый `AbortSignal.timeout(ms)`: сигнал, который сам отменяется через `ms` миллисекунд с причиной `TimeoutError`. В обычном коде его можно и нужно использовать. В заданиях этого курса мы пишем таймаут через `setTimeout` и `controller.abort()`: так время в тестах управляется подменными часами, а встроенный сигнал работает на внутреннем таймере и подменные часы его не двигают.

</Note>

## Как это работает

Схема показывает ситуацию из тикета. Два запроса уходят подряд. Второй начинается через 100 мс. В этот момент мы отменяем первый.

<Figure src="stale-request.svg" alt="Ось времени слева направо. Верхняя полоса: запрос «Каз», начинается в нуле, на отметке 100 мс обрывается крестиком, дальше пунктир «ответ пришёл бы поздно и не нужен». Нижняя полоса: запрос «Казань», начинается на 100 мс и заканчивается на 300 мс отметкой «ответ получен». Пунктирная стрелка от места обрыва вниз к началу второго запроса подписана «controller.abort() для запроса 1»." caption="Новый запрос отменяет предыдущий. Ответ на устаревший запрос не придёт и не затрёт свежие подсказки." />

Из схемы следуют правила.

1. **Один запрос — один контроллер.** Сигнал, который уже отменили, живым не станет. Для каждого нового запроса создаём новый контроллер, а предыдущий отменяем.
2. **Отмена — это отказ промиса.** Запрос, получивший `abort`, отклоняется с `signal.reason`. Поэтому в `catch` отмену отличают от настоящей ошибки: по `error.name === 'AbortError'` или по самому сигналу (`signal.aborted`). Отмена не повод показывать пользователю красную ошибку.
3. **Проверяйте сигнал после `await`.** Не все функции слушают сигнал. После ожидания вызывайте `signal.throwIfAborted()`: так устаревший ответ не пройдёт дальше.
4. **Таймаут — это отмена по таймеру.** Таймер вызывает `controller.abort(...)`. Таймер, как и любой ресурс, нужно очистить, когда он больше не нужен.
5. **Повторы — цикл с паузой.** Между попытками ждём. Пауза отменяемая, иначе клиент уйдёт со страницы, а повторы продолжатся. Паузу после последней неудачи не делаем: ошибку надо отдать сразу.

Повторы стоит посчитать заранее. Запустите модель: сколько прождёт клиент, если служба доставки четыре раза подряд отвечает ошибкой.

## Типичные ошибки

Все сообщения получены запуском в Node.js 22.

**1. Отменяют сигнал, а не контроллер.**

<Wrong>

```js
const controller = new AbortController();
controller.signal.abort();
```

</Wrong>

```text
TypeError: controller.signal.abort is not a function
```

Метод `abort` есть у контроллера (пульта), а не у сигнала (телевизора). Сигнал только сообщает об отмене.

<Right>

```js
controller.abort();
```

</Right>

**2. Отмена не поймана, и страница сообщает об ошибке.**

```js
const controller = new AbortController();
const request = new Promise((resolve, reject) => {
  controller.signal.addEventListener('abort', () => reject(controller.signal.reason));
});
controller.abort();
```

```text
DOMException [AbortError]: This operation was aborted
```

Промис отклонён, а `catch` нет. В Node.js такой необработанный отказ останавливает программу, в браузере пишет красную ошибку в консоль. Отмена — штатная ситуация, её надо ловить и тихо игнорировать, если это именно `AbortError`.

**3. Бросили причину отмены и не поняли, что это.**

```js
const controller = new AbortController();
controller.abort();
controller.signal.throwIfAborted();
```

```text
AbortError: This operation was aborted
```

Это не поломка, а вежливый способ прервать функцию. Ловите такую ошибку там, где можно спокойно завершить работу.

**4. Ждут `AbortError`, а пришёл `TimeoutError`.** Сигнал `AbortSignal.timeout(ms)` отменяется с причиной другого вида.

```js
const signal = AbortSignal.timeout(10);
// через 30 мс:
console.log(signal.reason.name, '-', signal.reason.message);
```

```text
TimeoutError - The operation was aborted due to timeout
```

Если обработчик ловит только `AbortError`, таймаут пролетит мимо. Проверяйте оба имени или смотрите на `signal.aborted`.

**5. Тихая ошибка: таймер остался.** Сообщения нет. Если не очистить таймер таймаута, он сработает позже, после ответа, и отклонит промис, которого никто не ждёт. В браузере это шум в консоли, в Node.js ещё и процесс не завершается вовремя. Лекарство: `clearTimeout` в `finally`.

**6. Тихая ошибка: повтор после отмены.** Пауза между попытками сделана через голый `setTimeout`. Клиент закрыл страницу, сигнал отменён, а следующая попытка всё равно уходит. Лекарство: паузу тоже делают отменяемой, как `sleep(ms, signal)`.
