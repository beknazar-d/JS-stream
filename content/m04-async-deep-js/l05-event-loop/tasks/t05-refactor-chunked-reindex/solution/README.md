# Разбор

Идея: работа делится на части, а между частями поток свободен.

1. `runChunk` обрабатывает товары от `position` до `end`, но не больше `chunkSize` за раз. Позиция лежит внутри вызова `reindexCatalog`, поэтому две переиндексации не мешают друг другу.
2. Если товары остались, следующая часть ставится через `setTimeout(runChunk, 0)`. Это новая задача. Пока она ждёт, event loop может выполнить клики, другие таймеры и перерисовку.
3. Когда товары кончились, `resolve(position)` отдаёт количество. Для пустого каталога это `0`.
4. Ошибка обработчика ловится в `try/catch` внутри `runChunk` и уходит в `reject`. Мы выходим через `return`, и следующая часть не ставится.

Почему не микрозадача. `Promise.resolve().then(runChunk)` тоже «откладывает» вызов, но event loop опустошает микрозадачи целиком, не заглядывая в очередь задач. Страница заморожена так же, как в исходном цикле.

Размер части выбирают замером: достаточно маленький, чтобы одна часть занимала несколько миллисекунд, и достаточно большой, чтобы накладные расходы на таймеры не съели выигрыш.
