## Контекст

Тикет CAT-902. Админка «Домотеки» переиндексирует каталог для поиска. Функция `reindexCatalog` обходит все товары в одном цикле. Для 200 тысяч товаров вкладка администратора замирает на несколько секунд: кнопки не нажимаются, индикатор не крутится. Нужно разбить работу на части, не меняя результат.

## Цель

Перепишите `reindexCatalog(products, indexProduct, chunkSize = 100)` в `index.js`. Теперь она возвращает промис и обрабатывает не больше `chunkSize` товаров за одну задачу, а между частями отдаёт управление в event loop.

## Критерии приёмки

- Каждый товар передаётся в `indexProduct` ровно один раз, в исходном порядке.
- Промис выполняется числом обработанных товаров (как раньше возвращала функция).
- За одну задачу (без возврата в event loop) вызывается не больше `chunkSize` раз `indexProduct`.
- Между частями успевают сработать другие таймеры: таймер, поставленный до вызова, выполняется до завершения переиндексации.
- Пустой каталог: промис выполняется значением `0`.
- Если `indexProduct` бросил ошибку, промис отклоняется этой же ошибкой, а оставшиеся товары не обрабатываются.
- Две переиндексации, запущенные одновременно, не мешают друг другу.

## Ограничения

- Используйте `setTimeout`, а не `queueMicrotask` и не `then`: нужны именно задачи, а не микрозадачи.
- Состояние (позиция) должно жить внутри вызова.
- Сигнатуру менять нельзя, кроме нового необязательного параметра `chunkSize`.
