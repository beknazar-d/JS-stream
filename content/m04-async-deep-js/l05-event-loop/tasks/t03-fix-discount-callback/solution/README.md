# Разбор

Ошибка в порядке событий. `setTimeout` только ставит задачу в очередь, а строка `onReady(percent)` идёт следом и выполняется синхронно. К этому моменту таймер ещё не сработал, и `percent` равен `0`. Когда таймер потом присвоит скидку, читать её уже некому.

Правило: всё, что зависит от результата отложенной работы, выполняется внутри неё. Вызов `onReady` переехал в колбэк таймера, туда, где значение уже известно.

Важная деталь контракта: колбэк всегда вызывается асинхронно. Если бы он иногда приходил сразу (как в варианте `sync-call`), код вызывающей стороны вёл бы себя по-разному в зависимости от данных. А `?? 0` даёт запасное значение для неизвестных кодов, не трогая настоящий ноль.
