## Контекст

Тикет NOTIFY-310. Покупатель оформляет заказ из 20 позиций. Сервис резервирует товары по одному, и после каждой позиции вызывает `notify("Товар зарезервирован: ...")`. Покупателю приходит 20 push-уведомлений подряд. Продукт-менеджер просит слать одно сообщение со списком, но без заметной задержки: ждать секунду, чтобы «набрать пачку», нельзя.

Идея: уведомления, добавленные в одном проходе синхронного кода, собираются в одну пачку, а пачка уходит сразу, как только поток освободится.

## Цель

Реализуйте `createNotificationBatcher(sendBatch)` в `index.js`. Она возвращает функцию `add(notification)`. Все уведомления, добавленные до того, как event loop освободится, уходят одним вызовом `sendBatch(batch)`, где `batch` это массив в порядке добавления.

## Критерии приёмки

- Три вызова `add("a")`, `add("b")`, `add("c")` подряд дают один вызов `sendBatch(["a", "b", "c"])`.
- `sendBatch` не вызывается синхронно внутри `add`.
- Пачка уходит не позже ближайшей микрозадачи, раньше любого таймера, включая `setTimeout` с нулём.
- Уведомление, добавленное после отправки пачки, попадает в новую пачку, и `sendBatch` вызывается ещё раз.
- Уведомление, добавленное из самого `sendBatch`, не теряется: оно уходит следующей пачкой.
- `sendBatch` никогда не вызывается с пустым массивом и ровно один раз на пачку.
- Два независимых батчера (`createNotificationBatcher` вызвана дважды) не делят пачки.

## Неясности

В тикете нет ответов на вопросы: что делать, если `sendBatch` бросит ошибку; нужно ли убирать одинаковые уведомления; можно ли добавлять `undefined`; нужно ли ограничить размер пачки. Запишите вопросы и допущения в `assumptions.js` (комментариями) до кода. Тесты проверяют только однозначные случаи из критериев приёмки.

## Ограничения

- Только `queueMicrotask` (или промисы). Таймеры и ожидание «набрать пачку» не используются.
- Без внешних библиотек.
