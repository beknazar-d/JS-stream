## Зачем это в работе

Тикет от службы поддержки. Покупатель нажимает «Оформить заказ» и просит письмо с подтверждением. Разработчик пишет так: сохранить заказ, поставить отправку письма в `setTimeout`, показать «Спасибо». Письмо уходит, но иногда раньше, чем заказ записан. В другой раз страница после загрузки выгрузки из 200 тысяч строк замирает на три секунды: кнопки не нажимаются, таймер не тикает.

Обе беды из одного источника. Мы не знаем, в каком порядке JavaScript берёт работу. Этот урок про порядок. Он нужен каждый раз, когда в коде есть таймеры, промисы или события.

```js
console.log("сохраняем заказ");
setTimeout(() => console.log("отправляем письмо"), 0);
console.log("показываем «Спасибо»");
```

```text
сохраняем заказ
показываем «Спасибо»
отправляем письмо
```

Таймер стоит на 0 миллисекунд, а письмо всё равно ушло последним.

## Объяснение

JavaScript выполняет код в одном потоке (thread). Это значит: одновременно делается только одно дело. Место, где выполняется текущий код, называется стеком вызовов (call stack). Пока стек занят, больше ничего не происходит.

Представьте кухню с одним поваром. Стек вызовов — это блюдо, которое повар готовит прямо сейчас. Работу он не бросает. Остальное ждёт в двух местах:

- Очередь задач (task queue): заказы от зала. Сюда попадают сработавшие таймеры (`setTimeout`, `setInterval`) и события (клик, ввод). Повар берёт из неё один заказ за раз.
- Очередь микрозадач (microtask queue): срочные записки на столе. Сюда попадают продолжения промисов (`.then`, `.catch`, `.finally`), продолжение после `await` и функции, переданные в `queueMicrotask`. Закончив блюдо, повар читает все записки до единой и только потом берёт следующий заказ.

Механизм, который решает, что делать дальше, называется циклом событий (event loop). Его правила короткие:

1. Выполнить синхронный код до конца: стек должен опустеть.
2. Выполнить все микрозадачи. Если одна из них добавила новую микрозадачу, выполнить и её.
3. Взять одну задачу из очереди задач и выполнить её.
4. Вернуться к пункту 2.

`setTimeout(fn, 0)` значит не «выполни сейчас», а «поставь в очередь задач; выполнится, когда стек и микрозадачи освободятся». Реальная задержка может оказаться больше нуля.

<Note>

Промисы мы разберём в следующем уроке. Сейчас достаточно одного факта: `Promise.resolve().then(fn)` ставит `fn` в очередь микрозадач.

</Note>

Что произошло. Строки 1 и 2 — синхронный код, он идёт подряд. Когда стек опустел, event loop сначала опустошил микрозадачи (строка 3) и только потом взял задачу от таймера (строка 4). Таймер стоял в коде раньше `then`, но это ничего не меняет: микрозадачи всегда впереди задач.

Правило: порядок вывода определяет не порядок строк в файле, а очередь, в которую попала функция.

<Wrong>

```js
let total;
setTimeout(() => { total = 5; }, 0);
console.log(total); // undefined
```

</Wrong>

<Right>

```js
setTimeout(() => {
  const total = 5;
  console.log(total); // 5
}, 0);
```

</Right>

Всё, что зависит от результата таймера, должно выполняться внутри него (или после него), а не рядом.

## Как это работает

Посмотрите на схему: три блока и цикл.

<Figure src="event-loop.svg" alt="Три блока слева направо: стек вызовов с синхронным кодом, очередь микрозадач с then, await и queueMicrotask, очередь задач с setTimeout, setInterval и событиями. Внизу стрелка по кругу и подпись: сначала стек, потом все микрозадачи, потом одна задача, потом снова микрозадачи." caption="Микрозадачи выполняются все сразу, задачи берутся по одной." />

Теперь пример посложнее. Внутри таймера появляется микрозадача, а внутри микрозадачи — ещё одна.

<Playground example="nested" />

Разберём по правилам. Стек заканчивается строкой «синхронный код закончился». Микрозадачи выполняются все: сначала «микрозадача 1», а добавленная ею «микрозадача 2» тоже выполняется сразу, до любого таймера. Затем берётся одна задача: таймер A. Она добавила микрозадачу, и та выполняется до таймера B.

Отсюда два следствия.

Первое: микрозадачи могут задержать таймеры. Если микрозадача постоянно добавляет новую микрозадачу, очередь задач не получит слова никогда. Таймеры и события замрут, как при бесконечном цикле.

Второе: блокировка потока. Пока идёт длинный синхронный цикл, стек занят, и event loop ничего другого не делает. В браузере страница перестаёт реагировать на клики и не перерисовывается. Выход — разбить работу на части и между частями возвращать управление в event loop через `setTimeout`.

<Playground example="chunks" />

Здесь после первой части (заказы 1–4) обработчик ставит следующую в очередь задач. Между частями event loop успевает выполнить другие задачи, например сработавший таймер «страница успела откликнуться». Для передачи управления годится именно `setTimeout`, а не `queueMicrotask`: после микрозадачи event loop снова выполнит микрозадачи, а к задачам не дойдёт.

<Wrong>

```js
function processAll(orders) {
  for (const order of orders) heavyWork(order); // 200 000 заказов подряд
}
```

</Wrong>

<Right>

```js
function processPart(orders, from, size) {
  for (const order of orders.slice(from, from + size)) heavyWork(order);
  if (from + size < orders.length) {
    setTimeout(() => processPart(orders, from + size, size), 0);
  }
}
```

</Right>

## Типичные ошибки

Сообщения получены запуском в Node.js 22. В консоли браузера текст похожий: строка начинается с `Uncaught`.

**1. try/catch не ловит ошибку из таймера.**

<Wrong>

```js
try {
  setTimeout(() => { throw new Error("Не удалось сохранить заказ"); }, 0);
} catch (error) {
  console.log("поймали");
}
```

</Wrong>

```text
Error: Не удалось сохранить заказ
    at Timeout._onTimeout (/app/order.js:2:27)
```

К моменту срабатывания таймера `try` давно закончился: стек, в котором он стоял, уже пуст. Слово «поймали» не выведено. `try/catch` нужно ставить внутрь функции, которую вызовет таймер.

<Right>

```js
setTimeout(() => {
  try {
    throw new Error("Не удалось сохранить заказ");
  } catch (error) {
    console.log("поймали: " + error.message);
  }
}, 0);
```

</Right>

**2. В `setTimeout` вызвали функцию вместо того, чтобы её передать.**

<Wrong>

```js
function sendEmail() {}
setTimeout(sendEmail(), 0);
```

</Wrong>

```text
TypeError [ERR_INVALID_ARG_TYPE]: The "callback" argument must be of type function. Received undefined
```

Скобки вызвали `sendEmail` сразу, а в таймер ушёл её результат `undefined`. Node.js ругается сразу. В браузере такая ошибка может пройти молча, и письмо уйдёт не вовремя. Передавайте саму функцию: `setTimeout(sendEmail, 0)` или `setTimeout(() => sendEmail(order), 0)`.

**3. Результат таймера читают сразу.** Ошибки в консоли нет, значение просто `undefined` (пример в разделе «Пример»). Ищите чтение переменной раньше записи.

**4. Тяжёлый цикл.** Сообщения нет совсем: страница тормозит, таймеры опаздывают. Если интерфейс «залипает» на длинной операции, а ошибок нет, проверьте, не крутится ли синхронный цикл по большому массиву.
