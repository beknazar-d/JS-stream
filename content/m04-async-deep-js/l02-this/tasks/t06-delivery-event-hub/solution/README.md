# Разбор

Хаб — фабрика с одним состоянием: `Map` от имени события к списку записей. Методы объявлены обычными функциями внутри фабрики и берут `subscriptions` из замыкания, а не из `this`. Поэтому `const { on, emit } = createEventHub()` работает: никакой объект слева от точки не нужен.

Ключевые решения.

1. **Контекст — это `this` обработчика.** Для этого `emit` вызывает `handler.apply(context, args)`. Если контекст не передали, `apply` получает `undefined`, и в строгом режиме `this` внутри обработчика тоже `undefined`. Если бы хаб вызывал `handler(...args)`, методы объектов теряли бы `this`.
2. **Запись, а не функция.** Подписка хранится как объект `{ handler, context }`. `off` ищет в списке именно эту запись через `indexOf`. Если искать по функции, один `off` снимет сразу обе подписки одной и той же функции. Если запись уже убрана, `indexOf` вернёт `-1`, и повторный `off` ничего не сделает.
3. **Копия списка в `emit`.** `off`, вызванный внутри обработчика, вырезает запись из массива через `splice`. Если идти по живому массиву, следующий обработчик сдвинется на освободившееся место и будет пропущен. Копия `[...list]` фиксирует список на момент начала `emit`.

## Вопросы, которые стоило задать

- Что делать, если обработчик выбросил ошибку: остановить `emit` или продолжить с остальными?
- Получат ли событие обработчики, подписанные во время этого же `emit`?
- Получит ли событие обработчик, которого отписал другой обработчик раньше его очереди?
- Нужна ли подписка «один раз»?

## Допущения в эталоне

Ошибка обработчика не перехватывается и уходит вызывающему. Список обработчиков фиксируется в начале `emit`, поэтому новые подписки видят только следующие события, а отписанный до своей очереди обработчик в текущем `emit` всё равно вызывается. Подписки «один раз» нет. Тесты эти решения не проверяют.
