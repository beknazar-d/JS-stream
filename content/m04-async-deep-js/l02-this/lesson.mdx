## Зачем это в работе

Ревью кода в «Домотеке». Кто-то написал трекер отправлений: объект с методом `markShipped`. Вызов `tracker.markShipped(order)` работает. Но когда метод передали в `orders.forEach(tracker.markShipped)`, в консоли появилось:

```text
TypeError: Cannot read properties of undefined (reading 'shipped')
```

Код тот же. Метод тот же. Ошибка есть, когда его вызывают иначе.

Так выглядит самая частая путаница в JavaScript. Метод, который отлично работал, ломается, как только его передали в колбэк, обработчик события или `setTimeout`. Причина — `this`. Урок про то, чему он равен и как его вернуть.

## Объяснение

`this` — это особое значение внутри функции. Обычно это объект, у которого вызвали метод: «о ком речь».

Главное правило, которое нужно запомнить: **`this` определяется способом вызова, а не местом, где функция написана**. Одна и та же функция в одном вызове получит один `this`, а в другом — другой.

Аналогия — слово «я». Когда курьер говорит «я везу посылку», слово «я» значит курьера. Когда то же предложение произносит диспетчер, «я» значит диспетчера. Слово одно, смысл зависит от того, кто говорит. Так же `this` зависит от того, кто вызывает.

Правил пять.

1. **Метод.** Вызов `order.print()`: `this` равен `order`, объекту слева от точки.
2. **Простой вызов.** Вызов `print()` без объекта: `this` равен `undefined`. Так работает строгий режим (strict mode). Файлы-модули ES и тела классов всегда строгие. В старом, нестрогом режиме вместо `undefined` подставлялся глобальный объект, что приводило к ещё более странным ошибкам.
3. **Явное задание.** `print.call(x)`, `print.apply(x)` и `print.bind(x)` дают `this` равный `x`.
4. **Конструктор.** Вызов `new Parcel()`: `this` равен новому пустому объекту. Подробности в следующем уроке.
5. **Стрелка.** У стрелочной функции (arrow function) своего `this` нет. Она берёт его из окружающего кода.

Запомнить удобно так. Сначала смотрите на стрелку: если функция стрелочная, остальные правила не работают. Иначе смотрите на вызов: есть объект слева от точки?

`call` вызывает функцию сразу, аргументы идут по одному. `apply` делает то же, но аргументы собраны в массив. `bind` ничего не вызывает, он возвращает новую функцию с закреплённым `this` (и при желании с первыми аргументами). ## Как это работает

Все пять правил на одной схеме.

<Figure src="this-rules.svg" alt="Таблица из двух колонок и пяти строк. Вызов order.print() даёт this равный объекту слева от точки. Вызов print() даёт undefined в строгом режиме. Вызов через call, apply или bind даёт переданное значение. Вызов new Parcel() даёт новый пустой объект. Стрелка берёт this из внешнего кода." caption="Как вызвали, таким и будет this. Исключение одно: у стрелки своего this нет." />

Где `this` теряется чаще всего.

1. **Метод передали как колбэк**: `forEach(obj.method)`, `setTimeout(obj.method, 100)`, `button.addEventListener('click', obj.method)`. В момент вызова функция уже не связана с объектом: движок получил голую функцию.
2. **Метод сохранили в переменную**: `const { markShipped } = tracker`.
3. **Обычная функция внутри метода**: `this.items.map(function (item) { return this.rate; })`. Колбэк вызывается как простая функция.

Три способа лечения.

- **Стрелка-обёртка**: `(order) => tracker.markShipped(order)`. Вызов опять идёт через точку.
- **`bind`**: `tracker.markShipped.bind(tracker)`. Новая функция всегда помнит объект.
- **Стрелка вместо `function`** внутри метода: колбэк берёт `this` метода.

Как выбрать? Для разового колбэка проще стрелка-обёртка. Если функцию передают в несколько мест, удобнее `bind` один раз.

И предупреждение про стрелку как метод объекта.

<Wrong>

```js
const order = {
  id: "ORD-7",
  print: () => "Заказ " + this.id, // this не order!
};
```

</Wrong>

<Right>

```js
const order = {
  id: "ORD-7",
  print() {
    return "Заказ " + this.id;
  },
};
```

</Right>

Стрелка берёт `this` из кода вокруг объекта, а не из самого объекта. Скобки `{ ... }` литерала не создают область для `this`. Поэтому методы объектов пишите в сокращённой записи `name() {}`, а стрелки оставляйте для колбэков.

<Note>

Альтернатива всем этим хитростям — не использовать `this` вовсе. В уроке 4.1 мы делали корзину на замыканиях: методы не зависят от того, как их вызвали, и их можно спокойно передавать в колбэки. Но классы и методы встроенных объектов используют `this`, поэтому правила знать нужно.

</Note>

## Типичные ошибки

Сообщения получены запуском в Node.js 22 в строгом режиме.

**1. Метод вызван без объекта.**

<Wrong>

```js
const tracker = { shipped: [], mark(id) { this.shipped.push(id); } };
[1, 2].forEach(tracker.mark);
```

</Wrong>

```text
TypeError: Cannot read properties of undefined (reading 'shipped')
```

Читайте сообщение так: `this` равен `undefined`, а код хотел взять у него свойство `shipped`. Значит, метод вызвали без объекта. Ищите, где его передали или сохранили.

**2. Деструктуризация метода.**

<Wrong>

```js
const courier = { name: "Иван", greet() { return this.name; } };
const { greet } = courier;
greet();
```

</Wrong>

```text
TypeError: Cannot read properties of undefined (reading 'name')
```

Деструктуризация достаёт функцию, объект остаётся позади. Та же причина.

**3. Конструктор без `new`.**

<Wrong>

```js
function Parcel() {
  this.weight = 1;
}
Parcel();
```

</Wrong>

```text
TypeError: Cannot set properties of undefined (setting 'weight')
```

Без `new` `this` равен `undefined`. Сообщение о записи, а не о чтении: «setting» вместо «reading».

**4. Молчащие ошибки.** Сообщения нет, результат неверный:

```text
стрелка как метод объекта        → this не объект, свойство undefined
передали метод в setTimeout     → this не объект, свойства нет
bind на уже привязанной функции → this не меняется
```

В старом нестрогом режиме `this.name` в потерянном методе читался из глобального объекта и давал `undefined` или пустую строку без всякой ошибки. Строгий режим превращает такую тихую ошибку в громкую.
