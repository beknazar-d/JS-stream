## Контекст

Тикет WH-142. Письмо от начальника склада: «Менеджеры резервируют товар под заказ, и иногда одну коробку продают дважды. Нужен модуль, который выдаёт резервы и умеет их снимать, если заказ отменили. Остатки при этом не должны портиться от чужого кода».

Остатки приходят из учётной системы в виде объекта `{ kettle: 5, cup: 20 }`, где ключ — артикул, значение — количество штук.

## Цель

Реализуйте в `index.js` функцию `createWarehouse(initialStock)`. Она возвращает объект со складом:

- `available(sku)` — сколько штук доступно сейчас (не зарезервировано). Для неизвестного артикула — `0`.
- `reserve(sku, qty)` — резервирует `qty` штук. При успехе возвращает `{ ok: true, id }`, где `id` — строка, уникальная в пределах этого склада, и доступное количество уменьшается. При отказе возвращает `{ ok: false, reason }` и остатки не меняются. Причина `"unknown-sku"`, если артикула нет на складе, и `"not-enough"`, если товара меньше, чем запрошено.
- `release(id)` — снимает резерв и возвращает товар на склад. Возвращает `true`, если резерв был. Для неизвестного или уже снятого `id` возвращает `false`, остатки не меняются.
- `snapshot()` — объект с доступными остатками по всем артикулам, включая те, где остаток `0`.

## Критерии приёмки

- После `createWarehouse({ kettle: 5 })` вызов `reserve("kettle", 2)` оставляет `available("kettle")` равным `3`.
- Запрос на `6` штук при остатке `5` возвращает `{ ok: false, reason: "not-enough" }`; запрос на `5` проходит и оставляет `0`.
- Объект `initialStock`, переданный в `createWarehouse`, не меняется ни резервами, ни снятием резервов. Правка этого объекта снаружи после создания склада не влияет на склад.
- Изменение объекта из `snapshot()` не влияет на склад.
- Два склада независимы. Два резерва получают разные `id`.
- Повторный `release` того же `id` возвращает `false` и не увеличивает остаток.
- Количество `0`, отрицательное и дробное отклоняется: `ok` равно `false`.

Запишите вопросы и допущения в `assumptions.txt` до кода (строки в этом файле начинаются с `//`, пишите после них). Тесты проверяют только однозначные случаи из списка выше: формат `id` и причина отказа для нулевого количества не проверяются.

## Ограничения

- Состояние хранится в замыкании, без классов.
- Менять объект `initialStock` нельзя.
- Только встроенные возможности языка, без библиотек.
