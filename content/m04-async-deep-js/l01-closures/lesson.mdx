## Зачем это в работе

Тикет от службы доставки «Домотеки»: заказам нужны номера вида `ORD-0001`, `ORD-0002`. Возвратам нужны свои номера, `RET-0001`. Счётчики не должны мешать друг другу. И никто снаружи не должен случайно записать в счётчик число 5.

Хранить счётчик в глобальной переменной нельзя: её тронет любой код. Нужна функция, которая помнит своё число между вызовами и при этом прячет его.

Такие задачи в работе встречаются каждый день:

- номера заказов и накладных;
- скидка, настроенная один раз: «−10% по купону»;
- корзина, в которой список позиций нельзя испортить снаружи;
- кэш: стоимость доставки в зону считать долго, второй раз брать готовый ответ.

Во всех случаях работает одна идея. Она называется замыкание.

## Объяснение

Замыкание (closure) — это функция вместе с переменными из места, где она была создана.

Представьте рюкзак. Когда функция рождается внутри другой функции, она кладёт в рюкзак все переменные вокруг. Потом она уходит куда угодно: её возвращают, передают в другую функцию, вызывают через час. Рюкзак остаётся с ней. Внешняя функция давно завершилась, а переменные живы.

Переменные из рюкзака хранятся в лексическом окружении (lexical environment). Это просто «таблица имён и значений», которая создаётся при каждом вызове функции. Слово «лексическое» значит: окружение определяется тем, где функция написана в коде, а не тем, откуда её вызвали.

Функцию, которая создаёт и возвращает другую функцию, называют фабрикой функций. Каждый вызов фабрики даёт новое окружение. Поэтому два счётчика не мешают друг другу.

Из этого вытекают три приёма:

1. **Фабрика с настройкой.** Параметр фабрики остаётся в рюкзаке: `makeDiscount(10)`.
2. **Приватное состояние.** Переменная внутри фабрики видна только возвращённым функциям.
3. **Кэш.** Функция помнит результаты прошлых вызовов.

## Как это работает

Схема показывает два вызова фабрики.

<Figure src="closure-backpack.svg" alt="Две рамки рядом. В левой окружение первого вызова makeCounter с ORD: prefix равен ORD, last равен 3, ниже функция nextOrder со стрелкой к окружению. В правой окружение второго вызова с RET: prefix равен RET, last равен 1, ниже функция nextReturn со стрелкой к своему окружению. Окружения не связаны." caption="Каждый вызов фабрики создаёт своё окружение. Функция держит ссылку на него." />

Порядок событий:

1. Вызов `makeCounter("ORD")` создаёт окружение с `prefix` и `last`.
2. Внутри создаётся функция `next`. Она получает ссылку на это окружение.
3. `makeCounter` завершается и возвращает `next`. Обычно после завершения функции её переменные исчезают. Но на окружение всё ещё указывает `next`, поэтому оно остаётся в памяти.
4. Когда вы вызываете `next`, она ищет `last` сначала у себя, потом в своём рюкзаке. Находит и меняет.

Отсюда два правила, которые стоит запомнить.

**Правило общего окружения.** Функции, созданные в одном вызове фабрики, делят одни и те же переменные. Поэтому `add`, `total` и `count` из примера видят один список.

**Правило нового окружения.** Каждый новый вызов фабрики даёт новые переменные. Состояние одного счётчика не попадёт в другой.

Ещё одна деталь: рюкзак хранит ссылки, а не копии. Если в рюкзаке массив и вы вернули его наружу как есть, внешний код получит тот же самый массив и сможет его менять. Для приватных данных возвращайте копию.

<Note>

Замыкание держит переменные в памяти, пока жива функция. Для счётчиков это ничего не стоит. Но кэш без ограничения размера растёт вечно. В уроке 4.12 мы научим кэш забывать старое.

</Note>

## Типичные ошибки

Сообщения ниже получены запуском в Node.js 22.

**1. Чтение переменной замыкания снаружи.**

<Wrong>

```js
function makeCounter() {
  let last = 0;
  return () => ++last;
}
console.log(last);
```

</Wrong>

```text
ReferenceError: last is not defined
```

Переменная `last` существует только в рюкзаке функции. Снаружи имя `last` никому не известно. Это не баг, а смысл приватности.

**2. Вернули результат вместо функции.**

<Wrong>

```js
function makeCounter() {
  let last = 0;
  return last + 1; // забыли обернуть в функцию
}
const next = makeCounter();
next();
```

</Wrong>

```text
TypeError: next is not a function
```

Фабрика должна вернуть функцию, а не число. Проверьте, что после `return` стоит `function` или стрелка.

**3. Обращение к «приватному» полю как к свойству.**

<Wrong>

```js
function createCart() {
  const items = [];
  return { add(x) { items.push(x); } };
}
const cart = createCart();
cart.items.push(1);
```

</Wrong>

```text
TypeError: Cannot read properties of undefined (reading 'push')
```

Свойства `items` у объекта нет, есть только переменная в рюкзаке. Нужен метод, который с ней работает.

**4. Молчащие ошибки.** Сообщения нет, результат неверный:

```text
let внутри возвращаемой функции      → счётчик всегда 1
состояние в переменной модуля        → все фабрики делят одно значение
return items (внутренний массив)     → снаружи его можно испортить
if (cache.get(key)) вместо has       → результат 0 считается заново
```

Защита одна: писать тесты на два независимых экземпляра и на изменение результата снаружи.

Функции помнят переменные из места создания. Но есть второе, что функция «получает» при вызове: объект, у которого её вызвали. Оно называется `this`. И оно ведёт себя совсем иначе: определяется не местом написания, а способом вызова. В следующем уроке разберём, как `this` теряется, и как его вернуть.
