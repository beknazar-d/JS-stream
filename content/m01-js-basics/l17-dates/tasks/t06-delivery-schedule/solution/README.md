# Разбор

**Приведение к дням.** Сроки и «сегодня» сравниваются по календарным дням, а не по моментам. Поэтому обе даты сначала приводятся к полуночи UTC (`Date.UTC(год, месяц, день)` из частей `getUTC...`). Тогда разница кратна суткам, и `Math.round` убирает только ошибки округления, а не настоящее время суток. Именно тут ломается вариант «разница в миллисекундах до текущего момента»: в день доставки после полуночи он даёт минус одни сутки.

**Плохие заказы.** Проверка `typeof order.createdAt === 'string'` нужна, потому что `new Date(null)` — это 1 января 1970, а не ошибка. После неё `Number.isNaN(created.getTime())` ловит нечитаемые строки. Ошибки `addWorkingDays` ловятся `try/catch` вокруг одного вызова. Остальной код (включая баги) не прячется в `catch`.

**Форматтер.** `Intl.DateTimeFormat` с `timeZone: 'UTC'` форматирует дату по UTC, а не по поясу компьютера, поэтому подпись не зависит от места запуска. Объект создаётся один раз снаружи цикла: это дешевле, чем создавать его для каждого заказа.

**Сортировка.** Компаратор сравнивает строки `YYYY-MM-DD`: у такого формата алфавитный порядок совпадает с хронологическим. При равенстве срабатывает `a.id - b.id`.

**Чистота.** Функция не читает текущее время и не меняет входные данные: `today` приходит параметром, `addWorkingDays` копирует даты.
