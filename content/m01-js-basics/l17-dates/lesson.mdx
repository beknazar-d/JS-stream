## Зачем это в работе

Магазин пообещал доставку «до 14 марта». Разработчик посчитал срок на своём ноутбуке, и всё сходилось. На сервере в другом часовом поясе тот же код выдал 13 марта. Курьерская служба, сверившись со своим календарём, поставила дату 15 марта. Клиент получил три разных ответа на один вопрос.

Ошибки с датами редко бросают исключения. Чаще они молча сдвигают результат на день или на месяц. Запоминать нужно несколько правил, зато они работают всегда.

В этом уроке мы создаём даты так, чтобы результат не зависел от компьютера, сравниваем их, считаем сроки с учётом выходных и показываем покупателю по-русски.

```js
const d = new Date(2025, 2, 5);
console.log(d.getMonth());
```

```text
2
```

Март, а число два. Месяцы в `Date` нумеруются с нуля.

## Объяснение

`Date` — это встроенный объект JavaScript для момента времени. Внутри хранится одно число: сколько миллисекунд прошло с полуночи 1 января 1970 года по UTC. UTC (всемирное координированное время) — общая точка отсчёта без часовых поясов.

Представьте стеклянные песочные часы на складе. Песок всегда один и тот же, это и есть момент. Но на коробке в Нью-Йорке напишут «вчера, 19:00», а на такой же коробке в Токио «сегодня, 09:00». Момент один, записей много.

Отсюда главное правило: храните и считайте в UTC, а часовой пояс подключайте только при показе человеку.

Что нужно запомнить:

- Месяцы с нуля: январь `0`, декабрь `11`. Дни месяца с единицы. Дни недели: воскресенье `0`, суббота `6`.
- Методы с `UTC` в названии (`getUTCDate`, `setUTCDate`) работают по UTC. Методы без `UTC` (`getDate`, `getHours`) работают по часовому поясу компьютера и дают разные ответы на разных машинах.
- `Date.UTC(год, месяц, день)` создаёт момент по UTC. Конструктор `new Date(год, месяц, день)` использует местный пояс.
- `Date` изменяемый: `setUTCDate` правит объект на месте. Прежде чем менять, делайте копию.

## Как это работает

Почему методы без `UTC` опасны? Посмотрите на схему.

<Figure src="date-timeline.svg" alt="Вверху блок «один момент» с числом 1741132800000 миллисекунд. Из него три стрелки ведут вниз к трём блокам: Нью-Йорк 4 марта 19:00 и getDate даёт 4, UTC 5 марта 00:00 и getUTCDate даёт 5, Токио 5 марта 09:00 и getDate даёт 5." caption="Один момент времени, три записи. Метод без UTC выбирает запись по компьютеру." />

Вот что получается на практике. Строка `'2025-03-05'` без времени разбирается как полночь по UTC. А строка `'2025-03-05T00:00:00'` со временем, но без буквы `Z`, разбирается по местному поясу. Запуск на компьютере в Нью-Йорке:

```js
console.log(new Date('2025-03-05').getDate());
console.log(new Date('2025-03-05T00:00:00').getDate());
```

```text
4
5
```

Первая строка дала 4, потому что полночь по UTC в Нью-Йорке ещё предыдущий вечер. Поэтому правила такие:

1. Создавайте даты через `Date.UTC(...)` или строки с буквой `Z`: `'2025-03-05T10:00:00Z'`.
2. Читайте части через методы `getUTC...`.
3. Текущую дату не берите внутри функции (`new Date()` без аргументов). Передавайте её параметром. Тогда функцию можно проверить тестом с любой датой.

**Дни между датами.** Если вычесть время создания из времени доставки, получится дробное число суток: `2.979...`. Для календарных дней сначала отбрасывают время, то есть приводят обе даты к полуночи UTC, и только потом делят на `86400000`.

**Сроки с выходными.** Считают по одному дню: сдвинулись на сутки, проверили, рабочий ли это день (`getUTCDay()` не `0` и не `6`, дата не в списке праздников), и только тогда увеличили счётчик. Особых формул для недель не нужно.

**Показ покупателю.** Для красивого вывода служит `Intl.DateTimeFormat`. Первым аргументом идёт язык, вторым настройки. Параметр `timeZone: 'UTC'` фиксирует пояс, и результат не зависит от компьютера.

<Playground example="date-format" />

Обратите внимание: «5 марта 2025 г.» заканчивается точкой и буквой «г.». Если проверяете такую строку тестом, сравнивайте её целиком. Московское время в примере — это UTC плюс три часа: 14:30 стало 17:30.

<Note>

Для валют `Intl.NumberFormat('ru-RU', ...)` вставляет неразрывные пробелы, поэтому «1 234,50 ₽» выглядит как обычная строка, но обычному пробелу не равна. У дат в русской локали Node.js 22 использует обычные пробелы. Всё равно проверяйте вывод `Intl` запуском, а не по памяти: он зависит от версии данных локалей.

</Note>

## Типичные ошибки

Сообщения получены запуском в Node.js 22.

**1. Строка не дата.**

<Wrong>

```js
const date = new Date('вчера');
console.log(date.toISOString());
```

</Wrong>

```text
RangeError: Invalid time value
```

`new Date('вчера')` не падает, а создаёт особое значение Invalid Date. Падает только следующая операция. Проверяйте результат: `Number.isNaN(date.getTime())`.

**2. Метод даты у строки.**

<Wrong>

```js
const createdAt = '2025-03-05';
console.log(createdAt.getUTCDay());
```

</Wrong>

```text
TypeError: createdAt.getUTCDay is not a function
```

Из JSON и форм приходят строки, а не даты. Превращайте их через `new Date(...)`.

**3. Тихая ошибка: месяц на единицу меньше.**

<Wrong>

```js
const march = new Date(Date.UTC(2025, 3, 5)); // хотели март
console.log(march.toISOString());
```

</Wrong>

```text
2025-04-05T00:00:00.000Z
```

Исключения нет, дата просто другая. Март — это `2`. Заведите помощник `makeDate(year, month, day)`, который сам вычитает единицу.

**4. Тихая ошибка: перенос несуществующего дня.** `Date.UTC(2025, 1, 29)` даёт 1 марта, а не ошибку. Для дат из формы сравнивайте части результата с введёнными числами, как в задании про `parseFormDate`.

**5. Тихая ошибка: `===` для дат.** `a === b` почти всегда `false`. Сравнивайте `getTime()`.

**6. Тихая ошибка: изменение даты на месте.** `setUTCDate` правит объект. Если дата пришла в функцию снаружи, вызывающий код получит изменённую. Делайте копию: `new Date(date)`.
