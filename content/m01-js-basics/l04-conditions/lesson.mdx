## Зачем это в работе

Тикет от службы поддержки: «У товара остаток 0, а на карточке написано “Нет данных”. Покупатели думают, что сайт сломался. Должно быть “Нет в наличии”».

Разработчик посмотрел на код:

```js
const stock = 0;
if (stock) {
  console.log("В наличии: " + stock);
} else {
  console.log("Нет данных");
}
```

```text
Нет данных
```

Программа выбрала не ту ветку. Для неё ноль оказался «пустым» значением, и она решила, что остатка нет вовсе. Консоль молчала. Разберёмся, как работает такой выбор.

## Объяснение

Условие (condition) — это развилка в программе. Представьте контролёра на воротах склада. Он смотрит на пропуск. Если пропуск действителен, пускает. Иначе не пускает. Программа делает то же самое: проверяет вопрос с ответом «да» или «нет» и идёт по одной из дорог.

Основной инструмент — `if` («если»). Он проверяет значение в круглых скобках. После него в фигурных скобках `{ }` стоит код, который выполнится, если ответ «да». Вариант `else` («иначе») выполнится, если «нет». Между ними можно поставить сколько угодно проверок `else if` («иначе если»).

Условия проверяются сверху вниз. Как только одно сработало, остальные пропускаются. Поэтому порядок важен: сначала самый узкий случай, потом шире.

Три способа записать развилку:

- `if`, `else if`, `else`: основной способ, подходит для любых проверок, в том числе диапазонов («от 2000 до 5000»);
- тернарный оператор (ternary operator) `условие ? значение1 : значение2`: короткая запись выбора из двух значений. Он сам является выражением и возвращает значение;
- `switch`: сравнивает одно значение с несколькими готовыми вариантами (`case`). Хорош для статусов и кодов, неудобен для диапазонов.

В примерах дальше мы пишем код внутри функций. Слова `function` и `return` подробно разберём в уроке 1.7. Пока считайте так: функция получает значения и командой `return` отдаёт результат, а на этом `return` она сразу заканчивает работу.

Последняя часть про то, что значит «да» в скобках `if`. JavaScript превращает любое значение в `true` или `false`. Значения, которые становятся `false`, называют ложными (falsy). Их всего шесть:

- `false`;
- `0`;
- `""` (пустая строка);
- `null`;
- `undefined`;
- `NaN`.

Все остальные значения истинные (truthy). Включая строки `"0"` и `"false"`, строку из пробела `" "` и любое ненулевое число.

Посмотрите на `break`. Он обязателен: без него `switch` не остановится после нужного `case`, а «провалится» в следующий. Мы разберём это в типичных ошибках.

Наконец, ранний выход (early return). Если в функции много проверок, не вкладывайте их друг в друга. Проверяйте плохие случаи сначала и сразу заканчивайте функцию. Основной код тогда остаётся без лишних отступов.

<Wrong>

```js
function canShip(stock, isBlocked) {
  if (!isBlocked) {
    if (stock > 0) {
      return true;
    } else {
      return false;
    }
  } else {
    return false;
  }
}
```

</Wrong>

<Right>

```js
function canShip(stock, isBlocked) {
  if (isBlocked) {
    return false;
  }
  return stock > 0;
}
```

</Right>

Правый вариант короче, читается сверху вниз и не прячет главное условие в глубине вложенных блоков.

Про нулевой остаток из начала урока. Раз ноль ложный, проверять надо явно, а не через «если значение есть».

<Wrong>

```js
if (stock) {
  console.log("В наличии: " + stock);
}
```

</Wrong>

<Right>

```js
if (stock === undefined || stock === null) {
  console.log("Нет данных");
} else if (stock === 0) {
  console.log("Нет в наличии");
} else {
  console.log("В наличии: " + stock);
}
```

</Right>

## Как это работает

Схема показывает цепочку проверок из первого примера как маршрут. Вопрос задаётся сверху вниз. Как только ответ «да», маршрут уходит вправо и заканчивается. Остальные вопросы не задаются.

<Figure src="if-chain.svg" alt="Блок-схема в три строки. Первый вопрос: сумма заказа не меньше 5000. Если да, доставка 0 рублей. Если нет, переход ко второму вопросу: сумма не меньше 2000. Если да, доставка 150 рублей. Если нет, доставка 350 рублей, ветка else." caption="Цепочка if, else if, else: проверки идут сверху вниз и останавливаются на первой, где ответ «да»." />

Что полезно знать про части конструкций.

1. Ветка `else` не имеет условия. Она ловит всё, что не поймали проверки выше.
2. Тернарный оператор не заменяет `if` везде. Если вариантов больше двух, пишите `if`. Вложенные тернарные операторы читать невозможно.
3. `switch` сравнивает через `===`, без приведения типов. Строка `"1"` не совпадёт с `case 1`.
4. Если ни один `case` не подошёл, срабатывает `default`. Его пишут последним, он нужен всегда: даже для «невозможных» значений.
5. Если ни одно из условий в функции не сработало, а `return` в конце не написан, функция вернёт `undefined`.

<Playground example="truthy-values" />

Когда нужно проверить «значение пришло», выбирайте проверку под задачу:

- «это не `null` и не `undefined`»: `value !== null && value !== undefined`;
- «число не ноль»: `value !== 0`;
- «строка не пустая»: `value !== ""`.

Короткая запись `if (value)` годится, только когда ноль и пустая строка для вас то же самое, что «ничего».

## Типичные ошибки

Сообщения получены запуском в Node.js 22.

**1. Присваивание вместо сравнения.**

<Wrong>

```js
let stock = 5;
if (stock = 0) {
  console.log("Нет в наличии");
} else {
  console.log("В наличии: " + stock);
}
```

</Wrong>

```text
В наличии: 0
```

Одиночный знак `=` не сравнивает, а присваивает. Остаток стал нулём, а результат присваивания (ноль) оказался ложным. Ошибки нет, зато остаток испорчен. Для сравнения нужен `===`.

**2. Ноль принят за «нет значения».** Это ошибка из начала урока. Результат: `Нет данных` вместо `Нет в наличии`. Лечится явной проверкой: `stock === 0`.

**3. Забыт `break` в `switch`.**

<Wrong>

```js
function zoneDays(zone) {
  let days;
  switch (zone) {
    case "A":
      days = 1;
    case "B":
      days = 2;
      break;
    default:
      days = 9;
  }
  return days;
}
console.log(zoneDays("A"));
```

</Wrong>

```text
2
```

Ожидали `1`. После `days = 1` не было `break`, и выполнение провалилось в следующий `case`, где `days` стало `2`. Ставьте `break` после каждого `case`, если не делаете провал намеренно.

**4. Функция ничего не вернула.**

<Wrong>

```js
function fee(orderSum) {
  if (orderSum > 1000) {
    return 0;
  }
}
console.log(fee(500));
```

</Wrong>

```text
undefined
```

Путь, на котором нет `return`, возвращает `undefined`. Это то самое «значения нет» из урока 1.1, которое потом превращается в `NaN` или ошибку. Добавьте `return` на каждый путь.

**5. Лишняя `else` без `if`.**

<Wrong>

```js
if (stock > 0) console.log("есть"); console.log("ещё");
else console.log("нет");
```

</Wrong>

```text
SyntaxError: Unexpected token 'else'
```

Без фигурных скобок `if` управляет только одной строкой. Вторая команда на той же строке выбила `else` из пары. Пишите фигурные скобки всегда, даже для одной команды.

**6. Незакрытая фигурная скобка.**

<Wrong>

```js
if (stock > 0) {
  console.log("есть");
```

</Wrong>

```text
SyntaxError: Unexpected end of input
```

Программа закончилась, а блок не закрыт. Проверьте парность `{` и `}`. Редактор подсвечивает пары, если поставить курсор рядом со скобкой.

**7. Тернарный оператор без второй части.**

<Wrong>

```js
const label = isExpress ? "Экспресс";
```

</Wrong>

```text
SyntaxError: Unexpected token ';'
```

У тернарного оператора всегда три части: условие, значение «да», значение «нет». Если второго значения нет, нужен обычный `if`.

## Итог

Что вы теперь умеете:

- выбирать путь программы через `if`, `else if` и `else`;
- записывать выбор из двух значений тернарным оператором;
- перебирать готовые варианты через `switch` и не забывать `break`;
- выходить из функции раньше, а не складывать проверки в глубокую вложенность;
- помнить шесть ложных значений и не принимать ноль за «нет данных».

Пока код работал с одним значением за раз. Но склад обрабатывает сотни заказов. В следующем уроке разберём строки: как собирать текст из частей, искать в нём нужное и приводить артикулы и телефоны к единому виду.
