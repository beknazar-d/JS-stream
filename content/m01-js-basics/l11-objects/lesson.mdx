## Зачем это в работе

Два тикета за один день.

Первый. Оператор отменил заказ A-101 в окне предпросмотра, а в общем списке отменился и настоящий заказ. Кто-то решил, что сделал копию, а на самом деле держал тот же заказ под другим именем.

Второй. Страница оформления падает у части покупателей с ошибкой про `undefined`. Оказалось, что у заказов самовывоза нет адреса доставки, а код ждал, что адрес есть всегда.

Оба случая про объекты. Объект (object) хранит данные по именам: у заказа есть номер, статус, сумма и клиент. В этом уроке вы научитесь создавать объекты, читать вложенные данные без падений и понимать, когда два имени указывают на один и тот же объект.

```js
const order = { id: "A-101", status: "new" };
console.log(order.status);
```

```text
new
```

## Объяснение

Массив хранит значения по номеру. Объект хранит значения по имени. Имя называется ключом (key), а то, что под ним лежит, — значением (value). Пара «ключ и значение» называется свойством (property).

Аналогия: анкета клиента. В бланке есть графы «Имя», «Телефон», «Город». Чтобы найти телефон, не нужно знать, какой он по счёту. Достаточно знать название графы.

Объект создают фигурными скобками. Внутри пары `ключ: значение` через запятую:

```js
const order = { id: "A-101", status: "new", total: 4500 };
```

Как читать и менять свойства:

- `order.status` — чтение через точку. Это основной способ.
- `order["status"]` — то же самое через квадратные скобки. Нужен, когда имя лежит в переменной (`order[field]`) или содержит дефис (`order["pickup-point"]`).
- `order.status = "paid"` — запись. Если поля не было, оно появится.
- Если поля нет, чтение даёт `undefined`, а не ошибку.

Значением может быть что угодно, в том числе другой объект или массив. Так получаются вложенные данные: `order.customer.address.city`. Читать такую цепочку нужно осторожно. Если в середине цепочки лежит `undefined`, попытка читать дальше падает с ошибкой. Для этого есть оператор `?.`, безопасный доступ (optional chaining). Он останавливает цепочку и возвращает `undefined`, если слева пусто.

Оператор `?.` часто сочетают с `??` из урока про операторы: `order.giftCard?.code ?? "без подарочной карты"`.

## Пример

Три полезных действия с объектом целиком.

- `Object.keys(obj)` возвращает массив ключей.
- `Object.values(obj)` возвращает массив значений.
- `Object.entries(obj)` возвращает массив пар `[ключ, значение]`.

Все три удобно перебирать через `for...of` из прошлого урока. Остатки склада — классический пример: ключ это артикул, значение это количество.

<Playground example="keys-and-search" />

Как проверить, есть ли поле:

- `"SOCK-07" in stock` — оператор `in`, проверяет наличие ключа, в том числе унаследованного.
- `Object.hasOwn(stock, "SOCK-07")` — проверяет только собственные свойства объекта. В работе чаще берут его.
- `stock["SOCK-07"] === undefined` — ненадёжно: поле может существовать со значением `undefined`.

Обратите внимание на остаток `0`. Поле есть, значение ноль. Проверка вида `if (stock[sku])` примет ноль за «поля нет». Если нужно отличить «нет поля» от «ноль», используйте `Object.hasOwn`.

<Wrong>

```js
if (stock[sku]) {
  // ноль остатка выглядит как «товара нет в каталоге»
}
```

</Wrong>

<Right>

```js
if (Object.hasOwn(stock, sku)) {
  // товар в каталоге есть, остаток может быть нулём
}
```

</Right>

## Как это работает

Теперь самое важное в уроке. В переменной с объектом лежит не сам объект, а ссылка (reference) на него. Это как адрес склада: на бумажке написан адрес, а не сам склад.

Когда вы пишете `const preview = original`, копируется адрес. Объект остаётся один, а имён у него становится два. Меняете через одно имя, видите изменение через другое. Копируются же сами данные, только когда вы собираете новый объект.

<Figure src="shared-reference.svg" alt="Две схемы. Слева: переменные original и preview обе указывают на один объект со статусом cancelled, поэтому изменение через preview видно и в original. Справа: переменные source и copy указывают на два разных объекта, у source статус new, у copy статус cancelled." caption="Присваивание копирует ссылку, а не объект. Чтобы получить независимый объект, соберите новый." />

<Playground example="shared-reference" />

Из этого следуют три правила.

1. Присваивание объекта не копирует его. Копию нужно собрать самому: `{ id: source.id, status: source.status }`. В уроке про деструктуризацию и spread появится короткая запись для того же.
2. Оператор `===` для объектов сравнивает ссылки, а не содержимое. Два одинаковых по виду объекта `{ id: 1 }` не равны друг другу, потому что это два разных объекта.
3. `const` защищает только переменную от нового присваивания. Поля объекта под `const` менять можно.

Функция получает объект тоже по ссылке. Если внутри функции написать `order.status = "paid"`, изменится заказ снаружи. Поэтому функции, которые не должны менять вход, собирают и возвращают новый объект.

<Note>

Копия, собранная вручную, остаётся «мелкой»: вложенный объект, например `customer`, по-прежнему будет общим для оригинала и копии. Если нужно менять и вложенные данные, новый объект собирают и на этом уровне.

</Note>

Хранить объекты удобно в массиве: список заказов это `[{ id: "A-101", ... }, { id: "A-102", ... }]`. Перебираете его через `for...of`, а внутри читаете поля через точку.

## Типичные ошибки

Все сообщения ниже получены запуском в Node.js 22. Браузер на движке V8 (Chrome, Edge) пишет их так же.

**1. Вложенного объекта нет, а читаем из него.**

<Wrong>

```js
const order = { id: "A-101" };
console.log(order.customer.address.city);
```

</Wrong>

```text
TypeError: Cannot read properties of undefined (reading 'address')
```

Сообщение называет, что именно пошло не так: `order.customer` равно `undefined`, и читать у него `address` нельзя. Название поля в скобках — это то, что вы читали, а не то, чего нет.

<Right>

```js
console.log(order.customer?.address?.city ?? "город не указан");
```

</Right>

**2. Опечатка в названии поля.**

<Wrong>

```js
const order = { id: "A-101", total: 4500 };
console.log(order.totl.toFixed(2));
```

</Wrong>

```text
TypeError: Cannot read properties of undefined (reading 'toFixed')
```

Поле `totl` не существует, поэтому чтение дало `undefined`, а упала уже следующая операция. Если ошибка называет метод, а сам метод правильный, ищите опечатку в предыдущем имени.

**3. Поле вызвали как функцию.**

<Wrong>

```js
const order = { total: 4500 };
console.log(order.total());
```

</Wrong>

```text
TypeError: order.total is not a function
```

Поле `total` содержит число, а не функцию. Скобки после имени — это вызов.

**4. Объект пытаются обойти как массив.**

<Wrong>

```js
const stock = { "RUN-42": 7 };
for (const item of stock) {
  console.log(item);
}
```

</Wrong>

```text
TypeError: stock is not iterable
```

`for...of` работает с массивами, а объект не перебирается так напрямую. Возьмите `Object.keys(stock)`, `Object.values(stock)` или `Object.entries(stock)`.

**5. Тихая ошибка: общий объект.** Сообщения нет, поменялось не то.

<Wrong>

```js
const original = { id: "A-101", status: "new" };
const preview = original;
preview.status = "cancelled";
console.log(original.status);
```

</Wrong>

```text
cancelled
```

<Right>

```js
const preview = { id: original.id, status: "cancelled" };
console.log(original.status); // "new"
```

</Right>

## Итог

Что вы теперь умеете:

- создавать объекты и читать их поля через точку и через квадратные скобки;
- читать вложенные данные без падений через `?.` и подставлять запасное значение через `??`;
- перебирать объект через `Object.keys`, `Object.values` и `Object.entries`;
- проверять наличие поля через `Object.hasOwn` и отличать его от нуля и `undefined`;
- помнить, что присваивание объекта копирует ссылку, а `===` сравнивает ссылки.

Теперь у вас есть массивы и объекты. Самая частая форма данных в работе — массив объектов: список заказов, каталог товаров. Обходить такие списки циклом можно, но есть методы короче и надёжнее. В следующем уроке мы познакомимся с `map`, `filter`, `find`, `some` и `every`.
