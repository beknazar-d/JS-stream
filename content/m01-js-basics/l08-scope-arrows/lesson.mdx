## Зачем это в работе

Два тикета за одну неделю.

Первый: «После правки в чеке скидка считается как 25%, а должна 10%». Разработчик добавил в функцию новую переменную `discount`, не заметив, что такая уже есть снаружи. Внутри функции новая «закрыла» старую, и формула стала брать не то значение.

Второй: «Нужны номера заказов. У онлайн-магазина они начинаются с 1000, у кассы в офлайн-точке с 5000, и счётчики не должны мешать друг другу». Хранить два счётчика в двух глобальных переменных можно, но любой код в программе сможет их случайно изменить.

Оба тикета про одно: где живут переменные и кто их видит. Это называется областью видимости (scope). В этом уроке мы разберём её, а заодно выучим короткую запись функций: стрелочные функции (arrow functions).

## Объяснение

Представьте офис. Есть общий коридор и несколько кабинетов. Из кабинета можно выйти в коридор и увидеть всё, что там висит. Но из коридора в закрытый кабинет не заглянешь. А в кабинете внутри могут быть свои шкафы.

Переменные работают так же. У каждой есть область, в которой она видна.

- Блок (block) — это код в фигурных скобках: тело `if`, тело цикла, просто `{ ... }`. Переменная, объявленная через `let` или `const` внутри блока, видна только в нём и в блоках, вложенных в него.
- Функция тоже создаёт свою область: её параметры и переменные видны только внутри неё.
- Всё, что объявлено вне функций и блоков, видно во всём файле.

Главное правило: внутренняя область видит внешние, внешняя внутренние не видит. Когда JavaScript встречает имя, он ищет его сначала в текущей области, потом в окружающей, потом в ещё более внешней, пока не дойдёт до файла.

Если во внутренней области объявить переменную с тем же именем, она закроет внешнюю. Это называется затенением (shadowing). Внешняя переменная при этом не меняется, просто внутри её не видно.

Теперь стрелочные функции. Это более короткая запись, которой вы будете пользоваться постоянно:

```js
const vat = (price) => price * 1.2;
```

Читать это можно так: «`vat` — функция, которая принимает `price` и возвращает `price * 1.2`». Стрелка `=>` отделяет параметры от результата.

Если после стрелки идёт выражение без фигурных скобок, оно возвращается автоматически. Это неявный возврат (implicit return). Если вы ставите фигурные скобки, возврат надо писать самим:

```js
const vat = (price) => {
  return price * 1.2;
};
```

И последнее. Функция запоминает переменные из того места, где её создали, даже когда внешняя функция уже закончила работу. Это называется замыканием (closure). Пока мы знакомимся с ним на одном примере: счётчик номеров заказов.

## Пример

Сначала области видимости. В примере три ситуации: функция видит внешнюю переменную, блок прячет свою переменную, внутренняя переменная затеняет внешнюю. Запустите и прочитайте вывод.

<Playground example="scope" />

Что произошло. `makeLabel` увидела `shopName` из файла и свою `prefix`. Переменная `message` из блока `if` существует только внутри него. В `priceFor` новая `discount` равна 25 и закрыла внешнюю, равную 10. Скидка 25% от 1000 дала 750. А внешняя `discount` осталась 10: последняя строка это подтверждает.

<Wrong>

```js
const discount = 10;
function priceFor(amount) {
  const discount = 25; // случайно закрыли внешнюю
  return amount - (amount * discount) / 100;
}
```

</Wrong>

<Right>

```js
const discount = 10;
function priceFor(amount, percent) {
  return amount - (amount * percent) / 100;
}
priceFor(1000, discount);
```

</Right>

Лучший способ избежать неприятных затенений — передавать значения через параметры и давать переменным разные имена.

## Как это работает

Посмотрите на схему вложенных областей.

<Figure src="scope-boxes.svg" alt="Три вложенных прямоугольника. Внешний подписан «Файл» и содержит переменную shopName. Внутри него пунктирный прямоугольник «Функция makeLabel» с переменной prefix. Внутри функции ещё один прямоугольник «Блок if» с переменной message. Справа стрелка вверх: имя ищут изнутри наружу. Подпись внизу: снаружи внутренние имена не видны." caption="Имя ищут от самой внутренней области к самой внешней. Обратного пути нет." />

Из схемы следуют правила.

1. Из блока `if` видны `message`, `prefix` и `shopName`. Из функции `makeLabel` — только `prefix` и `shopName`. Из файла — только `shopName`.
2. Если имя найдено в ближайшей области, дальше JavaScript не ищет. Так работает затенение.
3. `let` и `const` ограничены блоком. Если значение нужно после блока, объявите переменную до него.
4. Параметры функции ведут себя как переменные внутри её области.

Теперь про замыкание. Посмотрите на счётчик заказов.

<Playground example="order-counter" />

Функция `createOrderCounter` создаёт переменную `current` и возвращает маленькую стрелочную функцию. Когда `createOrderCounter` закончила работу, её переменные могли бы исчезнуть. Но возвращённая функция продолжает на них ссылаться, поэтому они остаются живыми. Каждый вызов `createOrderCounter` создаёт новую `current`. Поэтому `nextWebOrder` и `nextShopOrder` считают независимо: после 1000, 1001 и 5000 следующий онлайн-заказ — 1002.

Это и есть замыкание: функция плюс переменные, которые она «унесла с собой». И главное, `current` недоступна снаружи. Её нельзя изменить случайно, можно только вызвать функцию и получить следующий номер.

<Note>

Стрелочные функции и обычные `function` похожи, но различаются в деталях, которые нужны позже (например, в работе с `this`). Пока выбирайте стрелки для коротких расчётов и вспомогательных функций, а `function` — для основных именованных функций.

</Note>

Что запомнить про стрелки:

- один параметр можно писать без скобок (`price => price * 1.2`), но мы всегда ставим скобки: так меньше путаницы;
- без параметров скобки обязательны: `() => 0`;
- выражение после стрелки возвращается само; если нужны фигурные скобки, пишите `return`.

## Типичные ошибки

Все сообщения ниже получены запуском в Node.js 22. Браузер на движке V8 пишет их так же.

**1. Переменную из блока используют снаружи.**

<Wrong>

```js
const stock = 5;
if (stock > 0) {
  const message = "Есть в наличии";
}
console.log(message);
```

</Wrong>

```text
ReferenceError: message is not defined
```

Снаружи блока имени `message` нет. Объявите переменную до блока и присвойте значение внутри.

<Right>

```js
const stock = 5;
let message = "Нет в наличии";
if (stock > 0) {
  message = "Есть в наличии";
}
console.log(message);
```

</Right>

**2. Затенение и обращение до объявления.**

<Wrong>

```js
const discount = 10;
function priceFor(amount) {
  console.log(discount);
  const discount = 25;
  return amount - (amount * discount) / 100;
}
priceFor(1000);
```

</Wrong>

```text
ReferenceError: Cannot access 'discount' before initialization
```

Новая `discount` объявлена в функции, поэтому она закрывает внешнюю во всей функции, в том числе выше строки с объявлением. До этой строки новая переменная ещё «не создана», читать её нельзя. Сообщение «before initialization» значит именно это. Разберём его подробнее в уроке 1.9.

**3. Стрелка с фигурными скобками забыла вернуть значение.** Сообщения нет.

<Wrong>

```js
const broken = (price) => {
  price * 1.2;
};
console.log(broken(500));
```

</Wrong>

```text
undefined
```

Как и в обычной функции: нет `return`, результат `undefined`. Либо уберите скобки (`(price) => price * 1.2`), либо добавьте `return`.

**4. Вызвали метод числа у строки в стрелке.**

<Wrong>

```js
const format = (value) => value.toFixed(1);
console.log(format("3"));
```

</Wrong>

```text
TypeError: value.toFixed is not a function
```

Это знакомая ошибка из урока 1.1: у строки нет метода числа. Стрелка тут не виновата, она просто принесла строку из формы. Превращайте значения в числа на входе.

## Итог

Что вы теперь умеете:

- определять, где видна переменная, и объяснять, почему внутри блока или функции её не видно снаружи;
- замечать затенение и избегать его;
- записывать функцию стрелкой, в том числе с неявным возвратом;
- помнить, что стрелка с фигурными скобками требует `return`;
- создавать счётчик, который прячет своё состояние, через замыкание.

Мы закончили самую трудную часть основ: типы, операторы, функции и области видимости. Прежде чем двигаться дальше, нужно закрепить ловушки. В следующем уроке мы разберём те из них, которые чаще всего ломают реальный код: `==` против `===`, плюс со строками, `NaN`, `??` против `||`, затенение и забытый `return`. После этого начнётся работа с массивами.
