## Контекст

Интерфейс оператора показывает заказ и историю изменений. Чтобы можно было нажать «Отменить», старая версия заказа должна остаться нетронутой. Сейчас оператор правит объект прямо на месте, и после отмены в истории видны уже новые значения. Нужны функции, которые возвращают новый заказ и не трогают старый.

Заказ выглядит так:

```js
{
  id: 1042,
  status: 'new',
  customer: { name: 'Анна Ким', address: { city: 'Казань', street: 'Баумана' } },
  lines: [{ sku: 'A-100', qty: 2 }],
}
```

## Цель

Реализуйте в `index.js` три функции. Каждая возвращает новый заказ.

- `setStatus(order, status)` меняет статус.
- `addLine(order, line)` добавляет позицию `{ sku, qty }`. Если позиция с таким `sku` уже есть, количество суммируется, а не появляется вторая строка.
- `changeCity(order, city)` меняет город в адресе клиента.

## Критерии приёмки

- Результат — новый объект, а не тот же самый.
- После вызова исходный заказ полностью совпадает с тем, каким был до вызова (включая вложенные объекты и массив `lines`).
- Остальные поля заказа в результате сохранены.
- `addLine` с уже существующим `sku` увеличивает количество и оставляет одну строку.

## Ограничения

- Не используйте `push`, присваивание свойств и `splice` на данных заказа.
- Работайте со spread: `...`.
