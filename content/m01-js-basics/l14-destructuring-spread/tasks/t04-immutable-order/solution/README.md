# Разбор

Главное правило: копировать нужно каждый уровень, который меняется.

`setStatus` меняет только верхний уровень. `{ ...order, status }` копирует все поля и перезаписывает `status`. Поле, записанное после spread, всегда выигрывает.

`changeCity` меняет третий уровень вложенности: `order.customer.address.city`. Поэтому копируются три объекта: заказ, клиент и адрес. Все остальные поля (например `name` или `street`) приезжают через spread. Остальные ветки заказа (например `lines`) остаются общими со старым заказом. Это нормально, пока их никто не меняет.

`addLine` разбирает два случая. Если `sku` уже есть, `map` собирает новый массив, в котором нужная позиция заменена копией с большим количеством. Остальные позиции переиспользуются как есть. Если `sku` нет, новая позиция дописывается через `[...order.lines, line]`. Ни `push`, ни `qty +=` здесь не нужны: старый массив и старые объекты остаются нетронутыми.
