# Разбор

У функции три обещания, и по тесту нужно на каждое.

1. **Слияние клиента.** Правка `{ customer: { city: 'Самара' } }` не должна стереть имя. Тест сравнивает весь объект клиента, а не только город. Так ловится мутант, который заменяет клиента целиком.
2. **Защита id.** Правка с `id: 999` не меняет номер. Заодно проверяем, что остальные поля той же правки применились: иначе тест пройдёт и на функции, которая игнорирует правку вообще.
3. **Исходные данные.** Заказ сравнивается с «чистой копией», созданной фабрикой `makeOrder()`. Такая проверка ловит и мутацию верхнего уровня, и вложенную. Отдельный тест проверяет, что результат — новый объект.

Хороший тест проверяет не только «что изменилось», но и «что осталось прежним». Фабрика заказа вместо общей константы нужна, чтобы тесты не влияли друг на друга.
