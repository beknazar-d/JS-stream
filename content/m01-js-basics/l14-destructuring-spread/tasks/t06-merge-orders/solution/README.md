# Разбор

Ключевая мысль: мы меняем `existing.qty`, поэтому `existing` обязан быть нашей собственной копией. Именно для этого первая строка функции делает `base.lines.map((line) => ({ ...line }))`. Тогда `existing.qty += line.qty` правит копию и не трогает основной заказ. Если скопировать только массив (`[...base.lines]`), объекты внутри останутся общими, и сумма «протечёт» в старый заказ.

Rest-параметр `...others` собирает все остальные заказы в массив. При вызове с одним аргументом это пустой массив: циклы просто не выполняются, а `mergedFrom` получает `[]`. Отдельная проверка на «нет дополнительных заказов» не нужна.

Из строк остальных заказов в результат попадают тоже копии (`{ ...line }`), поэтому будущая правка итогового заказа не заденет исходные.

Итоговый объект собран через spread: поля основного заказа сохранены, `lines` и `mergedFrom` записаны поверх.
