## Зачем это в работе

Оператор поддержки открывает заказ 1042 и меняет город доставки с Казани на Самару. Потом нажимает «Отменить». Город остаётся Самарой. История изменений показывает Самару и в старой версии, и в новой.

Разработчик скопировал заказ и поменял город в копии. Копия получилась, но вложенный адрес остался общим для обеих версий. Консоль молчала.

В этом уроке три инструмента для такой работы с данными: деструктуризация достаёт нужные поля, spread копирует, rest собирает остальное. Мы научимся копировать заказ так, чтобы старая версия не менялась.

```js
const order = { id: 1042, address: { city: 'Казань' } };
const copy = { ...order };
copy.address.city = 'Самара';
console.log(order.address.city);
```

```text
Самара
```

## Объяснение

Объект и массив похожи на коробку с отделениями. Иногда нужна вся коробка, а иногда два предмета из неё.

Деструктуризация (destructuring) достаёт значения из объекта или массива и сразу кладёт их в переменные. Вместо трёх строк `const id = order.id` получается одна запись.

Для объекта пишут фигурные скобки слева от знака равенства. Имена внутри скобок совпадают с именами свойств. Для массива пишут квадратные скобки, и значения берутся по порядку.

Три добавки делают запись гибкой:

- Значение по умолчанию (default value): `city = 'не указан'`. Оно используется, если свойства нет или оно равно `undefined`.
- Переименование: `id: orderId` читается как «свойство `id` положи в переменную `orderId`».
- Остаток (rest): `...others` собирает всё, что не забрали остальные имена. Для массива получается массив, для объекта получается объект.

Те же три точки в другой роли называются spread (распаковка). Они стоят справа от знака равенства или внутри вызова и «высыпают» содержимое объекта или массива на новое место. Так делают копии и объединяют данные.

Правило, как отличить rest от spread: слева, где мы забираем, это rest. Справа, где мы раскладываем, это spread.

## Как это работает

Главное, что нужно понять про копии: spread копирует только один уровень. Объект внутри объекта не копируется, а разделяется. В переменной лежит не сам вложенный объект, а ссылка (reference) на него. Копия верхнего уровня копирует ссылку.

<Playground example="shallow-copy" />

Правило: чтобы изменить поле на глубине, копируйте каждый объект на пути к нему. Для города в адресе клиента это три копии: заказ, клиент, адрес.

```js
const updated = {
  ...order,
  customer: {
    ...order.customer,
    address: { ...order.customer.address, city: 'Самара' },
  },
};
```

Остальные ветки заказа (например массив `lines`) остаются общими со старым заказом. Это нормально, пока их никто не меняет. Подход, при котором данные не меняют на месте, а создают новую версию, называется иммутабельным (immutable): старая версия остаётся целой, и «Отменить» работает.

Ещё три детали:

1. Значение по умолчанию срабатывает только на `undefined`. Значения `null`, `0` и пустая строка остаются как есть.
2. Для массива скобки квадратные и важен порядок: `const [first, second] = items` берёт первый и второй элементы. Пропустить элемент можно запятой: `const [, second] = items`.
3. Rest всегда последний: после него нельзя поставить другие имена.

<Note>

Полная копия «до самого дна» называется глубокой (deep copy). Для заказов обычно хватает копирования тех уровней, которые вы меняете. Это быстрее и яснее, чем копировать всё подряд.

</Note>

## Типичные ошибки

Все сообщения получены запуском в Node.js 22. Браузеры на V8 пишут их так же.

**1. Распаковка того, чего нет.**

<Wrong>

```js
const order = undefined;
const { id } = order;
```

</Wrong>

```text
TypeError: Cannot destructure property 'id' of 'order' as it is undefined.
```

Сообщение называет и свойство (`id`), и переменную (`order`). Ищите, почему заказ не пришёл. Если пропуск допустим, проверьте заказ заранее. Значение по умолчанию для параметра функции спасает от `undefined`, но не от `null`.

**2. Вложенного объекта нет.**

<Wrong>

```js
const order = { id: 1042 };
const { customer: { name } } = order;
```

</Wrong>

```text
TypeError: Cannot read properties of undefined (reading 'name')
```

Распаковка пытается прочитать `name` у отсутствующего `customer`. Для необязательной ветки задайте значение по умолчанию: `const { customer: { name } = {} } = order`.

**3. Квадратные скобки для объекта.**

<Wrong>

```js
const order = { id: 1042 };
const [first] = order;
```

</Wrong>

```text
TypeError: order is not iterable
```

Квадратные скобки работают с массивами и другими перебираемыми значениями. Объекту нужны фигурные.

**4. Rest не на последнем месте.**

<Wrong>

```js
function sum(...prices, tax) {}
```

</Wrong>

```text
SyntaxError: Rest parameter must be last formal parameter
```

**5. Тихая ошибка: копия, которая не копия.** Сообщения нет вообще. Заказ в истории меняется вместе с копией, как в начале урока. Лечение одно: копировать вложенный объект, который меняете, как показано выше.

**6. Тихая ошибка: промокод `null` не заменился.**

<Wrong>

```js
const { coupon = 'нет' } = { coupon: null };
console.log(coupon); // null
```

</Wrong>

Значение по умолчанию заменяет только `undefined`. Если из формы приходит `null`, проверяйте его отдельно.

## Итог

Что вы теперь умеете:

- достать нужные поля из объекта и массива одной записью, с умолчаниями и переименованием;
- собирать остаток через rest и раскладывать через spread;
- объяснить, что spread копирует один уровень, и скопировать все уровни, которые меняете;
- обновлять заказ, не портя старую версию.

Пока наши функции ожидали правильные данные. Но заказы приходят с ошибками: нет адреса, количество отрицательное, товара не существует. В следующем уроке мы научимся сообщать об ошибке понятно и ловить её там, где с ней можно что-то сделать: `throw` и `try/catch`.
