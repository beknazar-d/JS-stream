## Зачем это в работе

Тикет от маркетинга: «Снизить НДС в расчётах с 20 до 18 процентов». Разработчик нашёл число `20` в коде и заменил. Нашёл не везде. В корзине цена пересчитывалась по 18, а на странице оплаты по-прежнему по 20. Покупатель видел две разные суммы и писал в поддержку.

Число `20` было вставлено в код семь раз. Шесть исправили, седьмое забыли.

Решение простое: записать число один раз и дать ему имя. Тогда менять его придётся в одном месте.

```js
const vatPercent = 20;
console.log(1000 * vatPercent / 100);
```

```text
200
```

Имя `vatPercent` (НДС в процентах) и есть переменная. В этом уроке разберём, как её создавать, менять и называть.

## Объяснение

Переменная (variable) — это имя, под которым хранится значение. Представьте полку на складе с ярлыком «Остаток кроссовок». Ярлык — это имя. Число на полке — значение. Вы приходите к полке по ярлыку и берёте или меняете то, что на ней лежит.

Создание переменной называется объявлением (declaration). Первое значение, которое вы кладёте на полку, — это инициализация. Позже значение можно заменить новым. Это присваивание (assignment).

В современном JavaScript есть два ключевых слова для объявления:

- `const` (от constant, «постоянная»): имя навсегда привязано к одному значению. Присвоить другое значение нельзя.
- `let` («пусть»): имя можно привязать к новому значению сколько угодно раз.

Правило, которому следуют почти все команды: по умолчанию пишите `const`. Берите `let` только тогда, когда значение действительно должно меняться. Так читатель кода сразу видит, что именно меняется по ходу программы.

Правила имён такие:

- имя состоит из букв, цифр, знака подчёркивания `_` и знака доллара `$`;
- имя не может начинаться с цифры: `1st` нельзя, `first` можно;
- пробелов и дефисов в имени нет: `my-var` JavaScript прочтёт как «my минус var»;
- регистр важен: `stock` и `Stock` — две разные переменные;
- слова, которые заняты языком, брать нельзя: `let`, `const`, `class`, `return`.

Договорённость, которой пользуется весь мир JavaScript, называется camelCase («верблюжий регистр»). Имя из нескольких слов пишут слитно, а каждое слово после первого начинают с заглавной буквы: `maxItemsPerOrder`, `freeShippingFrom`. Имена пишут латиницей. Имя должно говорить, что лежит внутри: `stock` лучше, чем `s`, а `shippingFee` лучше, чем `x2`.

Есть старый способ объявления: `var`. Он появился раньше `let` и `const`. У него неудобные правила: он позволяет объявить одно имя дважды и ведёт себя странно внутри блоков кода. В новом коде его не пишут. Но в чужих и старых проектах он встречается, поэтому узнавать его надо.

## Пример

Запустите пример. Потом замените `let` на `const` в строке с `stock` и посмотрите на ошибку.

Что произошло. Строка `let stock = 40;` объявила переменную и положила в неё `40`. Строка `stock = stock - reserved;` взяла старое значение, вычла резерв и записала результат обратно. Слово `let` второй раз не пишется: переменная уже есть, мы только меняем её значение.

Копия не следит за оригиналом. Когда мы написали `let backup = stock;`, число скопировалось. Дальше `stock` изменился, а `backup` остался прежним.

<Playground example="copy-stays" />

Важная оговорка про `const`. Она запрещает присваивать имени другое значение. Она не делает значение «неприкосновенным» вообще. С числами и строками разницы нет: они не меняются сами по себе. Но позже, когда мы дойдём до массивов и объектов, окажется, что их содержимое менять можно и у `const`. Сейчас запомните только одно: `const` защищает имя от повторного присваивания.

<Wrong>

```js
const stock = 40;
stock = 35; // TypeError
```

</Wrong>

<Right>

```js
let stock = 40;
stock = 35; // ok
```

</Right>

## Как это работает

Схема показывает два вида «полок».

<Figure src="let-vs-const.svg" alt="Две полки с ярлыками. Слева ярлык stock, объявленный через let: на полке лежало 40, потом его заменили на 35, стрелка показывает замену. Справа ярлык vatPercent, объявленный через const: на полке лежит 20, а замок и подпись говорят, что присвоить другое значение нельзя." caption="let: на полку можно положить новое значение. const: ярлык запечатан, значение 20 навсегда привязано к имени." />

Теперь про порядок строк. Движок JavaScript читает код в два приёма. Сначала он находит все объявления `let` и `const` и «вешает ярлыки». Потом выполняет строки по порядку. Пока выполнение не дошло до строки с объявлением, ярлык уже висит, но полка закрыта. Эту область между началом блока и строкой объявления называют временной мёртвой зоной (temporal dead zone, TDZ). Обратиться к переменной в этой зоне нельзя.

```js
console.log(price); // ReferenceError
const price = 500;
```

Сообщения разных ошибок отличаются, и это помогает искать причину:

- `Cannot access 'price' before initialization` — переменная объявлена ниже, а вы читаете её выше. Поднимите объявление вверх.
- `prce is not defined` — такого имени нет вообще. Скорее всего, опечатка.
- `Assignment to constant variable.` — вы присваиваете новое значение имени, объявленному через `const`.

Если переменную объявили через `let` и ничего не положили, в ней лежит `undefined`. Это тот самый случай «коробки нет» из прошлого урока.

Напоследок про `typeof`. Он единственный не падает на несуществующем имени: `typeof missingName` даёт строку `"undefined"`, а не ошибку.

## Типичные ошибки

Сообщения получены запуском в Node.js 22. Браузеры на V8 пишут их так же.

**1. Присвоили новое значение `const`.**

<Wrong>

```js
const stock = 40;
stock = 35;
```

</Wrong>

```text
TypeError: Assignment to constant variable.
```

Если значение должно меняться, объявите переменную через `let`. Если не должно, значит, где-то в коде лишнее присваивание.

**2. Прочитали переменную до объявления.**

<Wrong>

```js
console.log(price);
const price = 500;
```

</Wrong>

```text
ReferenceError: Cannot access 'price' before initialization
```

Поменяйте строки местами: сначала объявление, потом использование.

<Right>

```js
const price = 500;
console.log(price);
```

</Right>

**3. Опечатка в имени.**

<Wrong>

```js
const price = 500;
console.log(prce);
```

</Wrong>

```text
ReferenceError: prce is not defined
```

Это уже не «до инициализации», а «такого имени нет». Сверьте написание буква в букву.

**4. Объявили одно имя дважды.**

<Wrong>

```js
let stock = 40;
let stock = 35;
```

</Wrong>

```text
SyntaxError: Identifier 'stock' has already been declared
```

Во второй строке слово `let` не нужно: достаточно `stock = 35;`.

**5. `const` без значения.**

<Wrong>

```js
const vatPercent;
```

</Wrong>

```text
SyntaxError: Missing initializer in const declaration
```

Раз значение нельзя присвоить позже, `const` требует его сразу.

**6. Дефис в имени.**

<Wrong>

```js
let my-var = 5;
```

</Wrong>

```text
SyntaxError: Unexpected token '-'
```

Для имён из нескольких слов используйте camelCase: `myVar`.
