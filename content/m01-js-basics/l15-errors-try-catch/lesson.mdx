## Зачем это в работе

Покупатель в мобильном приложении ввёл в поле количества «пять» и нажал «Оформить». Приложение отправило `NaN`. Склад списал `NaN` штук, остаток стал `NaN`, и каждый следующий заказ этого товара тоже считался как `NaN`. Через час товар исчез с сайта.

Ни одна строка кода не «упала». Именно это и было проблемой. Если бы функция списания сразу остановилась и сказала «количество должно быть целым числом больше нуля», ошибку нашли бы через минуту.

В этом уроке мы научимся делать две вещи. Первая: останавливать работу с понятным сообщением, когда данные никуда не годятся. Вторая: ловить такую остановку в месте, где известно, что с ней делать.

```js
function reserve(stock, qty) {
  return stock - qty;
}
console.log(reserve(10, Number('пять')));
```

```text
NaN
```

## Объяснение

Ошибка (error) в JavaScript — это объект. У него есть имя (`name`), текст (`message`) и путь по вызовам функций (`stack`), по которому разработчик находит строку.

Остановить работу можно командой `throw` (выбросить). Выполнение функции прекращается прямо на этой строке, а ошибка «всплывает» вверх: к тому, кто вызвал функцию, потом к тому, кто вызвал его, и так до самого верха. Если никто не поймал, программа останавливается и печатает ошибку в консоль.

Представьте цех. Рабочий видит бракованную деталь и нажимает красную кнопку. Конвейер встаёт. Дальше есть выбор: либо дежурный на участке знает, что делать с такой деталью (убрать и запустить конвейер), либо сигнал идёт выше к начальнику смены. Но заглушить кнопку и делать вид, что всё хорошо, нельзя.

Дежурный в коде называется `try/catch`:

- в блок `try` кладут код, который может выбросить ошибку;
- в блок `catch` попадает пойманная ошибка, и там решают, что делать;
- блок `finally` выполняется в любом случае: он нужен для уборки.

Кроме встроенных видов ошибок (`Error`, `TypeError`, `RangeError`) можно сделать свой. Для этого пишут `class ... extends Error`. Класс (class) — это шаблон для создания объектов. Нам он нужен минимально: чтобы дать ошибке своё имя и отличать «заказ плохой» от «в коде баг».

## Как это работает

Схема показывает два пути через `try/catch/finally`.

<Figure src="try-catch-flow.svg" alt="Схема из пяти блоков. Сверху блок try. Из него идут две стрелки: влево «ошибки не было, try выполнен целиком», вправо «выброшен throw, остаток try пропущен, работает catch». Обе стрелки сходятся в блоке finally, из которого стрелка ведёт к блоку «дальше по программе»." caption="Какой бы путь ни выбрала программа, finally выполнится." />

Правила, которые из неё следуют.

1. После `throw` остаток блока `try` не выполняется.
2. Если ошибки не было, `catch` пропускается.
3. `finally` выполняется всегда, даже если в `try` или `catch` стоит `return`.
4. Если `catch` нет или он выбросил ошибку заново, ошибка идёт выше.

Пример с `finally`. Обратите внимание, в каком порядке идут строки:

<Playground example="finally-order" />

Строка `освободили блокировку` печатается раньше, чем результат `7`. Функция сначала дошла до `return`, потом выполнила `finally`, и только после этого вернула значение.

Теперь главный вопрос урока: когда ловить, а когда нет.

- **Ловите**, если знаете, что делать: показать сообщение покупателю, взять запасное значение, записать плохую строку в отчёт и перейти к следующей.
- **Не ловите**, если не знаете: пусть ошибка идёт к тому, кто знает. Если поймали только чтобы записать в журнал, после записи выбросьте её заново: `throw error`.
- **Не глотайте молча.** Пустой `catch` превращает поломку в тихую порчу данных.
- **Различайте свои и чужие ошибки.** `ValidationError` означает «данные плохие», и это нормально. `TypeError` из-за `null` означает «в коде баг», и его нельзя прятать в отчёте.

Полезная привычка: проверяйте вход функции в самом начале и выбрасывайте ошибку сразу. Тогда плохие данные не успевают дойти до расчётов.

<Note>

Выбрасывать можно любое значение, даже строку: `throw 'Нет товара'`. Но у строки нет ни `message`, ни `stack`, поэтому не делайте так. Всегда выбрасывайте объект `Error` или его потомка.

</Note>

## Типичные ошибки

Сообщения получены запуском в Node.js 22. Неуловленная ошибка в консоли выглядит так: сначала файл и строка, потом сообщение, потом путь по вызовам. Ниже показана первая значимая строка.

**1. Неуловленная ошибка.**

<Wrong>

```js
function checkSku(sku) {
  if (sku.trim() === '') {
    throw new Error('Не указан артикул');
  }
}
checkSku('   ');
```

</Wrong>

```text
Error: Не указан артикул
    at checkSku (/projects/shop/index.js:3:11)
```

Это не сбой самой функции. Это значит, что никто выше не поймал ошибку. Решите, кто в вашей программе знает, что делать с таким случаем.

**2. Ошибка создана, но не выброшена.**

<Wrong>

```js
function checkQuantity(quantity) {
  if (quantity <= 0) {
    new Error('Количество должно быть больше нуля');
  }
  return quantity;
}
console.log(checkQuantity(-1));
```

</Wrong>

```text
-1
```

Консоль молчит. Объект ошибки создали и тут же выбросили из памяти: без слова `throw` ничего не происходит.

**3. Выброшена строка, а не Error.**

<Wrong>

```js
try {
  throw 'Нет товара';
} catch (error) {
  console.log(error.message);
}
```

</Wrong>

```text
undefined
```

У строки нет свойства `message`. Выбрасывайте `new Error('Нет товара')`.

**4. Забыли про super.**

<Wrong>

```js
class ValidationError extends Error {
  constructor(message) {
    this.name = 'ValidationError';
    super(message);
  }
}
new ValidationError('плохо');
```

</Wrong>

```text
ReferenceError: Must call super constructor in derived class before accessing 'this' or returning from derived constructor
```

В классе-наследнике нельзя трогать `this`, пока не вызван `super`.

**5. Блок try без catch и finally.**

<Wrong>

```js
try {
  reserve(10, 3);
}
```

</Wrong>

```text
SyntaxError: Missing catch or finally after try
```

**6. Тихая ошибка: пойманное и забытое.** Сообщения нет вообще. Пустой `catch` или `catch` с одним `console.log` превращает ошибку в `undefined` дальше по программе, как в задании про резерв товара. Решение: либо обработайте ошибку по-настоящему, либо не ловите.

## Итог

Что вы теперь умеете:

- останавливать работу командой `throw new Error(...)` с понятным сообщением;
- ловить ошибку через `try/catch` и пользоваться `finally` для уборки;
- сделать свой вид ошибки через `extends Error` и отличать его через `instanceof`;
- отличать плохие данные от багов и не глотать ошибки молча;
- проверять ошибки в тестах через `toThrow`.

До сих пор весь код жил в одном файле. Проект растёт, и скоро в одном файле станет тесно: деньги, склад, проверки. В следующем уроке мы разобьём код на файлы через `import` и `export`, а заодно научимся превращать данные в текст и обратно через JSON, потому что данные между программами ходят именно так.
