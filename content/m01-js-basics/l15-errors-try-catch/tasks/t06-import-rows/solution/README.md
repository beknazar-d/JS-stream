# Разбор

**Две функции с разными ролями.** `parseRow` знает правила одной строки и выбрасывает `ValidationError`. Она не решает, что делать с ошибкой. `importRows` знает, что с плохой строкой нужно сделать: записать причину и идти дальше.

**Количество.** `Number('3')` и `Number(' 3 ')` дают `3`. Пустая строка даёт `0`, `'abc'` даёт `NaN`, `'2.5'` даёт `2.5`. Одно условие `!Number.isInteger(qty) || qty <= 0` отсекает всё это: `0` отсеивается проверкой `<= 0`, остальное проверкой на целое.

**Порядок проверок.** Артикул проверяется до справочника: нет смысла искать товар по пустому артикулу. Количество проверяется до справочника: дешёвая проверка идёт раньше дорогой.

**Что ловить.** `catch (error)` получает любую ошибку. Проверка `instanceof ValidationError` отделяет «строка плохая» (записываем в отчёт) от «система сломалась» (пробрасываем через `throw error`). Если ловить всё подряд, недоступный справочник превратится в сотню одинаковых «ошибок строк», а настоящая причина потеряется. Строка `null` вызовет `TypeError` на `row.sku`: это баг вызывающего кода, и он тоже должен всплыть.

Цикл `forEach` с индексом даёт номер строки: `index + 1`.
