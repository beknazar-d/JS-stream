## Контекст

Заказы приходят из мобильного приложения, с сайта и из партнёрского импорта. Данные бывают испорчены: нет позиций, количество `0`, цена `NaN`. Сейчас такой заказ доходит до склада и ломается там, а оператор видит в логах «Cannot read properties of undefined». Нужна проверка на входе с понятными сообщениями и отдельным видом ошибки: «заказ плохой», а не «в коде баг».

## Цель

В `index.js` напишите:

- класс `ValidationError` — свой вид ошибки. Он наследует от `Error`, а его `name` равен `'ValidationError'`;
- функцию `validateOrder(order)`: если заказ в порядке, возвращает этот же заказ; иначе выбрасывает `ValidationError` с сообщением из списка (проверки идут по порядку, выбрасывается первая найденная).

Заказ: `{ id, lines: [{ sku, qty, price }] }`.

| Проблема | Сообщение |
| --- | --- |
| заказа нет (`undefined` или `null`) | `Заказ не передан` |
| `lines` не массив или он пуст | `В заказе нет позиций` |
| `qty` не целое число больше нуля | `Позиция A-100: количество должно быть целым числом больше нуля` |
| `price` не конечное число или меньше нуля | `Позиция A-100: цена должна быть неотрицательным числом` |

Вместо `A-100` подставляется `sku` проверяемой позиции. В каждой позиции сначала проверяется `qty`, потом `price`. Цена `0` допустима (подарок).

## Критерии приёмки

- Корректный заказ возвращается без изменений (тот же объект).
- Каждая проблема из таблицы даёт `ValidationError` с точным сообщением.
- `error.name` равен `'ValidationError'`, `error instanceof Error` истинно.
- Количество `1.5`, `'2'` (строка) и `NaN` считается неверным.

## Ограничения

- Только `index.js`. Не изменяйте заказ.
- Свой класс ошибки пишите минимально: достаточно конструктора, который задаёт `name`.
