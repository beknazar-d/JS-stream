## Зачем это в работе

Тикет: «Стоимость доставки считается в трёх местах — на карточке товара, в корзине и в письме с заказом. Сегодня в корзине поправили формулу, а в письме забыли. Покупатель видит две разные цены».

Причина проста: один и тот же расчёт скопирован в три места. Когда его меняют, нужно помнить обо всех копиях. Кто-то забудет.

Решение — функция (function). Это кусок кода с именем. Вы пишете расчёт один раз, а в нужных местах просто вызываете его по имени. Поправили формулу в одном месте, и она исправлена везде.

С этого урока заготовки в заданиях могут быть пустыми: вы сами объявляете функцию и экспортируете её. Слово `export` перед `function` нужно, чтобы тесты могли её вызвать.

## Объяснение

Представьте кофейный автомат. Вы бросаете монеты и нажимаете кнопку. Внутри что-то происходит, и вы получаете стакан. Как именно, вам знать не нужно: вы знаете только, что бросить и что получить.

Функция устроена так же. На вход она получает значения, внутри считает, на выходе отдаёт результат.

Вот объявление (declaration) функции:

```js
function shippingCost(weightKg, distanceKm) {
  return 200 + weightKg * 40;
}
```

Разберём по частям.

- `function` — слово, которое говорит: «здесь объявляется функция».
- `shippingCost` — имя функции. Оно описывает, что функция делает. Хорошее имя — глагол или существительное с действием: `shippingCost`, `applyDiscount`.
- `weightKg, distanceKm` — параметры (parameters). Это имена, под которыми значения доступны внутри функции.
- `return` — ключевое слово: «отдать результат и закончить работу функции».

Когда вы вызываете функцию, в скобках передаёте аргументы (arguments). Это конкретные значения для параметров: `shippingCost(2, 50)`. Первый аргумент попадает в первый параметр, второй — во второй.

Запомнить разницу проще так: параметры — это пустые ячейки в объявлении, аргументы — то, что вы кладёте в ячейки при вызове.

Что вернёт функция, если в ней нет `return`? Значение `undefined`. Функция что-то посчитает, но результат потеряется.

Ещё одна возможность: значение по умолчанию (default value). Если аргумент не передали, параметр получит запасное значение, которое вы записали в объявлении:

```js
function priceWithVat(price, rate = 0.2) {
  return price * (1 + rate);
}
```

Вызов `priceWithVat(500)` использует `rate`, равный `0.2`. Вызов `priceWithVat(500, 0)` использует `0`: значение по умолчанию подставляется только когда аргумента нет, то есть он `undefined`.

И последнее. Функция — это такое же значение, как число или строка. Её можно положить в другую переменную (`const calculate = shippingCost`) и вызвать через новое имя. Позже мы будем передавать функции в другие функции. Пока достаточно знать, что без скобок `shippingCost` — это сама функция, а со скобками `shippingCost(2, 50)` — её вызов и результат.

## Как это работает

Посмотрите на путь значений при вызове.

<Figure src="function-machine.svg" alt="Схема функции как автомата. Слева пунктирная рамка с аргументами «2, 50» со стрелкой в прямоугольник функции shippingCost, внутри которого параметры weightKg равно 2 и distanceKm равно 50. Справа от функции стрелка return к пунктирной рамке с результатом 280. Ниже второй прямоугольник «без return» со стрелкой к рамке undefined." caption="Аргументы входят в функцию и становятся параметрами. Через return выходит результат. Без return выходит undefined." />

Из схемы следуют четыре правила.

1. Порядок аргументов важен. `shippingCost(2, 50)` и `shippingCost(50, 2)` — разные вызовы: параметры заполняются по порядку.
2. `return` завершает функцию. Всё, что написано после него, не выполнится.
3. Если аргументов меньше, чем параметров, лишние параметры равны `undefined`. Если аргументов больше, лишние никуда не попадают.
4. Параметры и переменные, объявленные внутри функции, живут только внутри неё. Снаружи их не видно.

Теперь важная мысль про качество функций. Посмотрите на две функции в примере `pure`.

<Playground example="pure" />

Первая, `discounted`, зависит только от своих аргументов. Одни и те же `2000` и `10` всегда дают `1800`, и больше ничего в программе не меняется. Такая функция называется чистой (pure function). Её легко проверить тестом и легко использовать в любом месте.

Вторая, `registerOrder`, меняет переменную `ordersToday` снаружи. Это побочный эффект (side effect): функция делает что-то за пределами своего результата. Два вызова с одинаковым (пустым) списком аргументов дали 1 и 2. Результат зависит не от аргументов, а от того, сколько раз её вызывали раньше. Такие функции труднее тестировать: сначала надо привести внешнюю переменную в известное состояние.

К побочным эффектам относится и `console.log`: он пишет в консоль, а не возвращает значение. Побочные эффекты не запрещены, но их стоит держать отдельно от расчётов. Правило для работы: расчёты делайте чистыми функциями, а вывод и изменения внешнего состояния оставляйте на границе программы.

<Note>

Хорошая функция делает одно дело. Если описывая её приходится говорить «и… и…», например «считает стоимость и пишет в консоль и обновляет склад», разбейте её на несколько.

</Note>

## Типичные ошибки

Все сообщения ниже получены запуском в Node.js 22. Браузер на движке V8 пишет их так же.

**1. Опечатка в имени функции.**

<Wrong>

```js
function shippingCost(weightKg) {
  return 200 + weightKg * 40;
}
console.log(shipingCost(3));
```

</Wrong>

```text
ReferenceError: shipingCost is not defined
```

Язык не нашёл такого имени. Сравните написание в объявлении и в вызове буква за буквой.

**2. Вызов того, что не является функцией.**

<Wrong>

```js
const total = 500;
console.log(total(2));
```

</Wrong>

```text
TypeError: total is not a function
```

Круглые скобки после имени означают «вызвать». Но `total` — число, вызывать его нельзя. Чаще всего так бывает, когда имя переменной совпало с именем функции.

**3. Забытый `return`.**

<Wrong>

```js
function priceWithVat(price) {
  price * 1.2;
}
console.log(priceWithVat(100));
console.log(priceWithVat(100).toFixed(2));
```

</Wrong>

```text
undefined
TypeError: Cannot read properties of undefined (reading 'toFixed')
```

Первая строка вывела `undefined` вместо цены. Вторая упала, потому что у `undefined` нет методов. Эта ошибка знакома по уроку 1.1. Но теперь вы знаете причину: функция ничего не вернула. Если в консоли `undefined` там, где ждали число, первым делом ищите пропущенный `return`.

**4. Пропущенный аргумент.** Сообщения нет вообще.

<Wrong>

```js
function shippingCost(weightKg, distanceKm) {
  return 200 + weightKg * 40 + (distanceKm > 100 ? 300 : 0);
}
console.log(shippingCost(3));
```

</Wrong>

```text
320
```

Второй параметр остался `undefined`, а `undefined > 100` даёт `false`. Расчёт не упал и дал правдоподобное число. Здесь нужен либо значение по умолчанию, либо проверка. Если вместо `weightKg` забыли первый аргумент, результат будет `NaN`: `undefined * 40` это `NaN`.

## Итог

Что вы теперь умеете:

- объявлять функцию, различать параметры и аргументы;
- возвращать результат через `return` и объяснять, почему без него получается `undefined`;
- задавать значения по умолчанию и знать, что `0` не заменяется;
- отличать чистую функцию от функции с побочным эффектом и писать расчёты чистыми;
- читать сообщения `is not defined` и `is not a function`.

В примерах функции видели переменные снаружи, а переменные внутри функции снаружи не видны. Почему так, где проходит эта граница и что будет, если имена совпадут, разберём в следующем уроке. Там же появится короткая запись функций: стрелочные функции.
