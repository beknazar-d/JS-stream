## Зачем это в работе

Три тикета подряд.

Первый. В корзине вместо суммы написано `[object Object]300`. Разработчик сложил цены через `reduce` и забыл про один аргумент.

Второй. В отчёте «Топ заказов по сумме» после 1200 идёт 250, потом 4500. Заказы отсортированы, но не по числам, а как строки.

Третий. Руководитель просит свести заказы по статусам: сколько в каждом и на какую сумму.

Все три задачи про одно: превратить список в итог, в порядок или в группы. Для этого нужны `reduce`, `sort` и приём группировки. В этом уроке мы разберём их и заодно предупредим главные ловушки.

```js
const prices = [1200, 300, 4500];
console.log(prices.reduce((sum, price) => sum + price, 0));
```

```text
6000
```

## Объяснение

Метод `reduce` («свернуть») проходит по массиву и собирает из него одно значение. Это может быть число (сумма), объект (счётчики) или другой массив.

Аналогия: кассир у ленты. Он идёт вдоль товаров и держит в руке промежуточный итог. На каждом товаре он прибавляет цену к тому, что уже в руке. Когда лента закончилась, итог в руке и есть результат.

Колбэк у `reduce` принимает два значения:

- `acc` (от accumulator, «накопитель») — промежуточный итог;
- `item` — очередной элемент массива.

Колбэк возвращает новый `acc`. Это значение попадёт в следующий шаг. Вторым аргументом `reduce` передают начальное значение `acc`. Для суммы это `0`, для счётчиков `{}`, для списков `[]`.

<Playground example="reduce-total" />

Начальное значение всегда нужно писать. Если его пропустить, `reduce` возьмёт в качестве `acc` первый элемент массива и начнёт со второго. Для массива чисел это сработает, для массива объектов нет: к объекту прибавится число, и получится строка. А на пустом массиве без начального значения `reduce` вообще упадёт с ошибкой.

## Пример

Теперь сортировка. Метод `sort` упорядочивает массив. У него две особенности, и обе опасны.

Первая: **`sort` по умолчанию сравнивает элементы как строки.** Число `10` превращается в `"10"`, и строка `"10"` стоит раньше `"9"`, потому что `"1"` меньше `"9"`. Поэтому `[10, 9, 1].sort()` даёт `[1, 10, 9]`.

Вторая: **`sort` меняет исходный массив**, как `splice` из урока про массивы. Он ещё и возвращает его же, из-за чего кажется, что получена копия.

Чтобы сортировать числа правильно, нужен компаратор (comparator) — функция сравнения двух элементов `(a, b)`. Её результат говорит, кто идёт раньше:

- отрицательное число: `a` идёт раньше `b`;
- положительное число: `b` идёт раньше `a`;
- ноль: порядок не важен.

Для чисел подходит `(a, b) => a - b` (по возрастанию) и `(a, b) => b - a` (по убыванию). Для строк берут `a.name.localeCompare(b.name, "ru")`: он учитывает русский алфавит.

<Playground example="sort-basics" />

Чтобы не портить оригинал, используйте `toSorted`. Он делает то же, что `sort`, но возвращает новый массив. Метод появился недавно, он есть в Node.js 20 и новее и в современных браузерах. В коде для старых окружений вместо него пишут `items.slice().sort(...)`: сначала копия, потом сортировка копии.

<Wrong>

```js
const ranked = orders.sort((a, b) => b.total - a.total);
// orders тоже переставлен!
```

</Wrong>

<Right>

```js
const ranked = orders.toSorted((a, b) => b.total - a.total);
// orders остался прежним
```

</Right>

## Как это работает

Посмотрите, как `reduce` проходит по массиву. На каждом шаге есть два участника: накопленный `acc` и очередной элемент.

<Figure src="reduce-steps.svg" alt="Схема из четырёх блоков слева направо. Начало: acc равен 0. Шаг 1: прибавляем 1200, acc равен 1200. Шаг 2: прибавляем 300, acc равен 1500. Шаг 3: прибавляем 4500, acc равен 6000. Итог последнего шага является результатом reduce." caption="Колбэк возвращает новый acc, а reduce передаёт его на следующий шаг. Результат последнего шага и есть итог." />

Из схемы следуют правила.

1. Колбэк `reduce` обязан вернуть `acc`. Если открыли фигурные скобки и забыли `return`, следующий шаг получит `undefined`.
2. Начальное значение определяет тип итога. Сумма начинается с `0`, строка с `""`, список с `[]`, счётчики с `{}`.
3. Если `acc` объект, его обновляют внутри колбэка и возвращают. Это единственное место, где мутация `acc` нормальна: объект создан внутри `reduce` и ещё никому не отдан.

**Группировка** — это тот же `reduce` с объектом. Ключ — признак, по которому группируем (статус), значение — массив заказов. Если ключа ещё нет, создаём пустой массив, потом кладём в него заказ. Запустите пример: заказы разложены по статусам, а следом посчитаны суммы по статусам.

<Playground example="group-orders" />

<Note>

Для группировки в JavaScript появилась готовая функция `Object.groupBy(orders, (order) => order.status)`. Она новая: в Node.js её нет до версии 21, в браузерах до 2023–2024 года. В Node.js 22 она работает, но не во всех старых окружениях. Результат у неё необычный: объект без прототипа, то есть без служебных методов вроде `toString`. Поэтому в курсе мы пока пишем группировку через `reduce` или цикл. Так она работает везде и понятно показывает, что происходит.

</Note>

## Типичные ошибки

Все сообщения ниже получены запуском в Node.js 22. Браузер на движке V8 (Chrome, Edge) пишет их так же.

**1. `reduce` по пустому массиву без начального значения.**

<Wrong>

```js
const cart = [];
const total = cart.reduce((sum, item) => sum + item.price);
```

</Wrong>

```text
TypeError: Reduce of empty array with no initial value
```

Пустая корзина — обычное дело, поэтому падать на ней нельзя. Добавьте начальное значение: `cart.reduce((sum, item) => sum + item.price, 0)`.

**2. Тихая ошибка: массив объектов без начального значения.**

<Wrong>

```js
const cart = [{ price: 100 }, { price: 50 }];
console.log(cart.reduce((sum, item) => sum + item.price));
```

</Wrong>

```text
[object Object]50
```

Первый `acc` — сам объект `{ price: 100 }`. Плюс видит объект и строку, превращает объект в `"[object Object]"` и склеивает. Опять правило из первого урока: плюс склеивает, если рядом не число.

<Right>

```js
console.log(cart.reduce((sum, item) => sum + item.price, 0)); // 150
```

</Right>

**3. Тихая ошибка: в колбэке `reduce` нет `return`.**

<Wrong>

```js
const total = [1, 2, 3].reduce((sum, n) => {
  sum + n;
}, 0);
console.log(total);
```

</Wrong>

```text
undefined
```

Колбэк ничего не вернул, и итог превратился в `undefined`. Добавьте `return sum + n;`.

**4. Тихая ошибка: числа отсортированы как строки.**

<Wrong>

```js
console.log([10, 9, 1].sort());
```

</Wrong>

```text
[1, 10, 9]
```

<Right>

```js
console.log([10, 9, 1].sort((a, b) => a - b)); // [1, 9, 10]
```

</Right>

**5. Тихая ошибка: компаратор вернул не число.**

<Wrong>

```js
console.log([3, 1, 2].sort((a, b) => a > b));
```

</Wrong>

```text
[3, 1, 2]
```

Результат сравнения `a > b` — это `true` или `false`, а компаратору нужно число: отрицательное, ноль или положительное. Массив остался как был, хотя ошибки нет. Пишите `a - b`.

**6. Тихая ошибка: после сортировки пропал порядок в корзине.** Если вы сделали `cart.sort(...)` для показа в отчёте, то порядок товаров в самой корзине тоже изменился. Для отчётов сортируйте копию через `toSorted`.

## Итог

Что вы теперь умеете:

- сворачивать список в одно значение через `reduce` и всегда писать начальное значение;
- считать суммы и счётчики и собирать объекты внутри `reduce`;
- сортировать числа компаратором `(a, b) => a - b`, а не как строки;
- сортировать копию через `toSorted` или `slice().sort()` и помнить, что `sort` меняет оригинал;
- группировать заказы по признаку через `reduce` и знать про новый `Object.groupBy`.

Теперь у вас есть почти все инструменты для работы со списками. Но код выглядит громоздко: мы много раз писали `order.customer.address.city`, `acc[status]`, копировали поля вручную.
