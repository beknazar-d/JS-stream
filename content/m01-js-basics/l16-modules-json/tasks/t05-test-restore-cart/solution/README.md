# Разбор

Входы функции делятся на три группы, и тестам нужна каждая.

1. **Нормальная корзина.** Проверяем результат целиком через `toEqual`: так видно, что лишние поля пропали, а `qty` стало числом. Отдельный тест на пустую корзину нужен, чтобы функция не отказывала на корректных, но пустых данных.
2. **Текст не JSON.** Обрезанная строка, пустая строка, слово и `undefined`. Внутри функции их ловит `try/catch` вокруг `JSON.parse`, а снаружи должно быть одно понятное сообщение.
3. **JSON, но не корзина.** Число, `null`, массив, `items` не массив, `items` нет. `JSON.parse` с такими строками справляется, поэтому нужна отдельная проверка структуры.

Сообщение проверяем с текстом: `toThrow('Корзина повреждена')`. Без текста `toThrow()` довольствуется любой ошибкой, в том числе английским `SyntaxError`, который показали бы покупателю, и поломка осталась бы незамеченной.
