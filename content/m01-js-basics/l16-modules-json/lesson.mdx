## Зачем это в работе

В проекте магазина один файл вырос до тысячи строк. Чтобы поправить округление цены, разработчик ищет нужное место двадцать минут. Рядом лежит расчёт скидок, проверка склада и текст писем. Любая правка рискует задеть соседний код.

Другая история. Покупатель закрыл вкладку, не оформив заказ. Корзину хотелось бы сохранить до следующего визита, но в хранилище браузера можно положить только текст, а не объект.

Эти две задачи решаются двумя инструментами. Модули (modules) делят код на файлы. JSON превращает данные в текст и обратно.

```js
const cart = { items: [{ sku: 'A-100', qty: 2 }] };
console.log(String(cart));
```

```text
[object Object]
```

Так объект не сохранить: из него получилась бесполезная строка. Нужен формат, который можно записать в файл и прочитать обратно.

## Объяснение

**Модули.** Модуль (module) — это файл с кодом, у которого есть своя область видимости. То, что в нём объявлено, снаружи не видно, пока файл сам не отдаст это наружу. Отдают командой `export` (экспортировать). Берут командой `import` (импортировать).

Представьте склад с отдельными помещениями. В каждом помещении свои стеллажи. Чтобы взять что-то из соседнего, нужно, чтобы помещение выставило это в окно выдачи (`export`), а вы пришли и забрали (`import`).

Экспорт бывает двух видов:

- Именованный (named export): у значения есть имя, их в файле может быть сколько угодно. Подключают в фигурных скобках под тем же именем.
- По умолчанию (default export): главное значение файла, в файле оно одно. Подключают без скобок, и имя выбираете вы.

**JSON.** JSON (JavaScript Object Notation) — текстовый формат для данных. Он похож на объекты JavaScript, но строже: ключи и строки только в двойных кавычках, нет функций, комментариев и запятой после последнего элемента. Функция `JSON.stringify` превращает значение в строку (сериализация), функция `JSON.parse` превращает строку обратно (разбор).

Бытовая аналогия: посылка. Чтобы отправить мебель, её разбирают и упаковывают в коробку. Получатель собирает по инструкции. Но шурупы иногда теряются, и не всякая вещь переезжает целой. С данными то же самое.

## Пример

Два файла в одной папке. Файл `money.js` отдаёт две функции: одну по имени, одну по умолчанию.

```js
// money.js
export function formatPrice(rub) {
  return `${rub.toFixed(2)} ₽`;
}

export default function calcTax(amount) {
  return Math.round(amount * 20) / 100;
}
```

Файл `index.js` подключает их.

```js
// index.js
import calcTax, { formatPrice } from './money.js';

const sum = 2400;
console.log(formatPrice(sum), calcTax(sum));
```

```text
2400.00 ₽ 480
```

Что здесь важно. `./money.js` — путь к соседнему файлу: точка с косой чертой и расширение обязательны. Скобки нужны только для именованного экспорта. Подключить значение под другим именем можно через `as`: `import { formatPrice as fp } from './money.js'`.

<Wrong>

```js
import { calcTax } from './money.js';   // calcTax отдан по умолчанию
import formatPrice from './money.js';   // formatPrice отдан по имени
```

</Wrong>

<Right>

```js
import calcTax, { formatPrice } from './money.js';
```

</Right>

Теперь JSON. Запустите пример и посмотрите, что получилось на каждом шаге.

После `JSON.parse` мы получили новый объект. Не только верхний уровень, а все вложенные объекты тоже новые. Поэтому иногда пишут `JSON.parse(JSON.stringify(x))` для копии. Но у такой копии есть цена, и о ней дальше.

## Как это работает

JSON знает только строки, числа, `true`, `false`, `null`, массивы и объекты. Всё остальное по дороге теряется или превращается во что-то другое.

<Figure src="json-roundtrip.svg" alt="Три блока слева направо: объект в памяти, строка JSON, новый объект. Стрелки между ними подписаны stringify и parse. Под блоками рамка со списком потерь: undefined и функции пропадают, NaN и Infinity становятся null, дата становится строкой." caption="Круг через JSON возвращает копию, но не всегда ту же самую по содержанию." />

Посмотрите, что происходит с типичным заказом:

<Playground example="json-lost" />

Из этого следуют правила.

1. Свойства со значением `undefined` и функции пропадают. `undefined` внутри массива превращается в `null`.
2. `NaN` и `Infinity` превращаются в `null`. Деньги, потерянные как `null`, потом ломают расчёты.
3. Дата становится строкой в формате ISO. После `JSON.parse` это просто строка, а дату нужно создавать заново: `new Date(text)`. Подробнее про даты в следующем уроке.
4. Числа и строки сохраняют тип. `"3"` останется строкой, и `"3" + 1` по-прежнему даст `"31"`.
5. Текст из файла или хранилища может быть чем угодно. `JSON.parse` на плохом тексте бросает `SyntaxError`, поэтому его оборачивают в `try/catch` и бросают понятную ошибку, как в прошлом уроке.

<Playground example="json-errors" />

Правила модулей, которые тоже нужно знать.

1. Один файл — одна ответственность: деньги, склад, скидки отдельно.
2. Файл исполняется один раз, при первом импорте. Все остальные импорты получают то же самое.
3. Для запуска в Node.js рядом с файлами кладут `package.json` с полем `"type": "module"`. Без него Node.js 22 тоже понимает `import`, но печатает предупреждение. В браузере для этого служит `script type="module"`.

<Note>

Сообщения о разборе JSON зависят от движка. Те, что показаны выше, получены в Node.js 22 (V8, как в Chrome). В Firefox и Safari тексты другие. Поэтому в тестах и логике ориентируйтесь на тип ошибки (`SyntaxError`), а не на её текст.

</Note>

## Типичные ошибки

Все сообщения получены запуском в Node.js 22.

**1. Имя в import не совпало с экспортом.**

<Wrong>

```js
import { formatMoney } from './money.js';
```

</Wrong>

```text
SyntaxError: The requested module './money.js' does not provide an export named 'formatMoney'
```

Откройте файл и посмотрите, как называется экспорт на самом деле. Опечатки в регистре тоже считаются.

**2. Импорт по умолчанию там, где его нет.**

<Wrong>

```js
import money from './money.js';
```

</Wrong>

```text
SyntaxError: The requested module './money.js' does not provide an export named 'default'
```

В файле только именованные экспорты. Возьмите нужное в фигурных скобках.

**3. Забыли расширение.**

<Wrong>

```js
import { formatPrice } from './money';
```

</Wrong>

```text
Error [ERR_MODULE_NOT_FOUND]: Cannot find module '/projects/shop/money' imported from /projects/shop/index.js
Did you mean to import "./money.js"?
```

Node.js сам предлагает правильную запись. В ES-модулях расширение нужно писать всегда.

**4. Файл не считается модулем.**

```text
SyntaxError: Cannot use import statement outside a module
```

Это значит, что среда запустила файл как обычный скрипт: в браузере нет `type="module"`, в Node.js файл с расширением `.cjs` или пакет без поддержки модулей. Добавьте `"type": "module"` в `package.json` или тег `script type="module"`.

**5. Старый способ подключения.**

<Wrong>

```js
const money = require('./money.js');
```

</Wrong>

```text
ReferenceError: require is not defined in ES module scope, you can use import instead
```

`require` относится к другой, старой системе модулей. В файлах-модулях используйте `import`.

**6. Плохой JSON.** Самая частая ошибка, которую делают вручную: одинарные кавычки, запятая в конце, пустая строка. Сообщения смотрите в примере выше. Хороший шаблон:

<Right>

```js
try {
  return JSON.parse(text);
} catch (error) {
  throw new Error('Файл повреждён: это не JSON');
}
```

</Right>

## Итог

Что вы теперь умеете:

- делить код на файлы и подключать их через `export` и `import`, различая именованный экспорт и экспорт по умолчанию;
- превращать данные в текст через `JSON.stringify` и обратно через `JSON.parse`;
- помнить, что теряется при этом превращении: `undefined`, функции, `NaN` и тип даты;
- оборачивать разбор чужого текста в `try/catch` и сообщать понятную причину.

В примерах с JSON дважды встретилась дата: она превращалась в строку и не возвращалась обратно. С датами в JavaScript много странного: месяцы с нуля, часовые пояса, неожиданные сдвиги. В следующем уроке мы разберёмся с `Date`, научимся считать сроки доставки и форматировать дату для покупателя.
