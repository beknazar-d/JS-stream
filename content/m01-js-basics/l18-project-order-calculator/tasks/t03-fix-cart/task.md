## Контекст

Этап 3 проекта P1. Модуль корзины написан быстро и ведёт себя странно. Из отчёта тестировщика:

1. «Добавил кофе в корзину, потом добавил ещё раз. В истории корзины (которую хранит интерфейс) задним числом поменялись все прошлые версии».
2. «Сумма корзины из трёх позиций по 199,99 ₽ уходит в кассу дробным числом 599.97, а касса ждёт целые копейки (59997)».
3. «Можно добавить товар с количеством 0 и с количеством минус три».

## Цель

Исправьте `cart.js`. Деньги и ошибки уже готовы в `money.js` и `errors.js`.

- `addItem(cart, item)` возвращает новую корзину и не меняет переданную. Позиция — `{ sku, name, price, qty }`, цена в копейках. Если позиция с таким `sku` уже есть, количество суммируется в новой строке (старый объект строки не меняется). Новая позиция добавляется в конец.
- Если `qty` не целое число больше нуля, выбрасывается `ValidationError` с текстом `Количество должно быть целым числом больше нуля`. Если `price` не целое число не меньше нуля, текст `Цена должна быть целым числом копеек`.
- `subtotal(cart)` возвращает сумму в целых копейках: цена на количество по всем позициям. Пустая корзина даёт `0`.

## Критерии приёмки

- Три позиции `price: 19999, qty: 1` дают `subtotal` ровно `59997`.
- Исходная корзина и её строки после `addItem` не меняются, в том числе при повторном добавлении того же `sku`.
- `addItem(cart, { qty: 0, ... })`, `qty: -3`, `qty: 1.5`, `price: 199.99` выбрасывают `ValidationError`.

## Ограничения

- Менять нужно только `cart.js`.
- Не используйте `push` и присваивание полей у данных корзины.
