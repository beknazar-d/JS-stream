# Разбор

**Порядок вычислений** важнее кода. Он записан в письме заказчика: сумма, скидка за количество, сумма после неё, промокод от этой суммы, итог. Код повторяет его строка в строку, поэтому читается как ТЗ.

**Регрессия.** Когда в корзине нет позиций от 10 штук, `volumeDiscount` возвращает `0`, `afterVolume` равно прежней сумме, и всё остальное идёт как раньше: `promo` и `total` не меняются. Поэтому старые тесты продолжают проходить без правок. Проверка этого условия — главное в задачах «добавить правило».

**Новое поле, а не замена.** Старые поля `subtotal`, `promo`, `total` остались, добавлено только `volume`. Код, который читал старый результат, продолжает работать.

**Округление по позициям.** Скидка за количество округляется для каждой позиции отдельно, потом суммируется. Это определённое правило, которое нужно держать неизменным: если округлять сумму один раз, копейки разойдутся с бухгалтерией.

**Порог промокода.** `applyPromo(afterVolume, code)` сама проверяет порог MINUS500 по переданной сумме. Менять её не пришлось, достаточно передать ей правильную сумму.

**Корзина не меняется.** Расчёт использует чтение и новые числа. Менять цены в позициях нельзя: корзина — исходные данные, а скидки — результат.
