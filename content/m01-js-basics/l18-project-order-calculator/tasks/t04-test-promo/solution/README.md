# Разбор

Каждое правило ТЗ превращается в один-два теста. Под каждую ошибку нужен тест, который именно на ней падает.

1. **«Половина вверх».** Подходит сумма, на которой десять процентов дают дробь ровно `.5`: `105` копеек. Круглые суммы вроде `10000` округления не требуют и ошибку `Math.floor` не ловят. Это мутант `rounds-down`.
2. **«От 2 000 рублей».** Для порога всегда проверяют две точки: ровно порог (скидка действует) и на копейку ниже (ошибка). Тест на `100` копеек тоже нужен, он ловит `no-threshold`.
3. **«В любом регистре, с пробелами».** Строчные буквы и пробелы по краям. Если в тестах только `'SALE10'`, мутант `case-sensitive` не виден.
4. **Пустой код.** Три варианта: пустая строка, пробелы, не передан.

Тесты читаются как ТЗ: названия записаны правилами, а не названиями функций. Если правило поменяется, будет ясно, какой тест исправлять.
