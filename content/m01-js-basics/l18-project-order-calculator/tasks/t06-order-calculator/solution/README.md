# Разбор

**Порядок.** Все числа зависят друг от друга по цепочке, и порядок вычислений записан в ТЗ: товары, скидка за количество, промокод, сумма товаров `goods`, доставка по `goods`, итог, НДС от итога. Код повторяет эту цепочку сверху вниз.

**Что от чего зависит.** Доставка зависит от `goods`, то есть после скидок. Если проверить порог по `subtotal`, промокод вернёт заказ ниже порога, а доставка останется бесплатной. НДС зависит от итога вместе с доставкой, потому что цена доставки тоже включает налог.

**Порог включительно.** В `deliveryCost` условие `goods >= FREE_DELIVERY_FROM`. Знак `>` сделал бы заказ ровно на 3 000 ₽ платным.

**Деньги.** Всё считается в целых копейках, и только НДС округляется (`Math.round`): `119999 * 20 / 120` равно `19999.83...`, округление даёт `20000`. Все остальные суммы целые по построению.

**Ошибки.** Пустую корзину проверяем в самом начале. Ошибки промокода выбрасывает `applyPromo` внутри `discountSummary`, и они проходят через `calculateOrder` как есть: ловить их здесь нечем, а пользователю нужен именно их текст.

**Чистота.** Результат собирается из новых объектов (`{ ...line, total }`), корзина не меняется. Модули разделены по смыслу: деньги, корзина, скидки, доставка, НДС, сборка. Каждый можно проверить отдельно, что и делают тесты.
