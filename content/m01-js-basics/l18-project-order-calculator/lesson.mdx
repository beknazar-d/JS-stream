## Зачем это в работе

Приходит заказчик. Он владеет небольшим интернет-магазином кофе и пишет: «Мне нужен калькулятор заказа. Корзина, промокоды, скидки, НДС, бесплатная доставка от трёх тысяч. И чтобы копейки сходились с бухгалтерией».

В рабочем проекте такое письмо превращается в техническое задание (ТЗ, specification), потом в этапы, потом в код и тесты. Заказчик не говорит «покройте границы тестами» и не знает про `NaN`. Это ваша часть работы: задать уточняющие вопросы, записать правила и проверить, что код их соблюдает.

Этот урок — мини-проект, который собирает всё, что вы выучили в модуле: функции, массивы и объекты, `reduce`, копии без мутаций, ошибки, модули и числа с копейками. Проект можно положить в портфолио.

```js
const goods = 250000;
const delivery = goods >= 300000 ? 0 : 29900;
console.log(goods + delivery);
```

```text
279900
```

Одна строка математики. Весь проект про то, чтобы правильно собрать таких строк пятьдесят и не потерять ни одной копейки.

## Объяснение

Проект отличается от задания тем, что нет готовой формулировки. Есть пожелания, и из них нужно сделать правила. Поэтому порядок работы такой:

1. **Прочитать ТЗ и выписать правила.** Каждое предложение заказчика — потенциальный тест. «Доставка бесплатна от трёх тысяч» — это тест на ровно 3 000, на копейку ниже и на копейку выше.
2. **Разбить на файлы по смыслу.** Деньги отдельно, корзина отдельно, скидки отдельно, доставка, налог, сборка. Файл должен делать одно дело.
3. **Двигаться этапами.** Сначала самое основание (деньги), потом то, что на него опирается. На каждом этапе тесты зелёные.
4. **Сначала тесты, потом код** хотя бы для сложных правил: если правило не получается записать тестом, значит, оно не понято.
5. **Встречать изменения спокойно.** Заказчик обязательно что-то добавит в середине. Хорошая структура и старые тесты помогут не сломать уже принятое.

Аналогия: ремонт квартиры. Сначала смета и чертёж (ТЗ), потом разметка (файлы), потом работа по комнатам (этапы), и после каждой комнаты приёмка. А если жильцы решили добавить розетку, вы проверяете, что она не перерезала старую проводку.

Округление каждой позиции отдельно дало 2 копейки, одно округление по сумме дало 1. Обе схемы разумны, но результаты расходятся. Поэтому правило округления записывают в ТЗ, и тесты проверяют именно его.

<Wrong>

```js
const vat = total * 0.2;
```

</Wrong>

<Right>

```js
const vat = Math.round((total * 20) / 120);
```

</Right>

Налог уже входит в цену, поэтому он равен 20/120 суммы, а не 20/100, и результат нужно округлить до целой копейки.

## Как это работает

Схема показывает файлы проекта и то, кто на кого опирается.

<Figure src="project-modules.svg" alt="Схема из шести блоков. Вверху блок index.js. Под ним в среднем ряду три блока: discounts.js (скидки), delivery.js (доставка по сумме после скидок) и vat.js (НДС по итогу). Внизу пунктиром три блока основания: cart.js (корзина), money.js (копейки и формат) и errors.js (ValidationError). Правила проекта.

1. Зависимости идут в одну сторону: сверху вниз. `money.js` не импортирует `discounts.js`. Иначе файлы начнут зависеть друг от друга по кругу, и разобраться станет трудно.
2. Все суммы между модулями передаются в копейках. Рубли с запятой появляются только в `formatMoney`, то есть при показе.
3. Все ошибки входа — `ValidationError` с понятным текстом. Ловят их там, где можно показать человеку сообщение. Остальные ошибки (баги) не прячут.
4. Функции расчёта не меняют входные данные и не читают текущее время. Результат зависит только от аргументов.
5. Новое правило добавляют так, чтобы старые поля результата остались. Тогда прежние тесты продолжают проходить.

Шесть этапов проекта сделаны как задания ниже. Каждый следующий опирается на предыдущий: в заготовке уже лежит код прошлых этапов. На пятом этапе заказчик присылает письмо с новым правилом: вам нужно добавить его, не сломав принятое.

## Типичные ошибки

Все сообщения получены запуском в Node.js 22 на файлах проекта.

**1. Ошибка входа не поймана.** Это ожидаемое поведение для пустой корзины: ошибка `ValidationError` поднялась до самого верха.

```text
ValidationError: Корзина пуста
    at calculateOrder (file:///projects/shop/index.js:8:11)
    at file:///projects/shop/run.js:3:1
```

Первая строка — главное: вид ошибки и ваше сообщение. Дальше путь по вызовам: снизу вверх видно, кто кого вызвал. Если пользователь должен увидеть красивый текст, ловите такую ошибку там, где показываете результат.

**2. Имя в import не совпало с экспортом.**

<Wrong>

```js
import { vatIncluded } from './vat.js';
```

</Wrong>

```text
SyntaxError: The requested module './vat.js' does not provide an export named 'vatIncluded'
```

Откройте `vat.js` и сверьте имена. Частая причина в проекте: функцию написали, но забыли слово `export`.

**3. Корзина не пришла.**

<Wrong>

```js
function countLines(cart) {
  return cart.length;
}
countLines(undefined);
```

</Wrong>

```text
TypeError: Cannot read properties of undefined (reading 'length')
```

Проверяйте вход на границе функции и выбрасывайте свою ошибку с понятным текстом, как в `calculateOrder`.

**4. Тихая ошибка: дробные рубли.** `4.35 * 100` даёт `434.99999999999994`. Исключения нет, но сумма не сойдётся с бухгалтерией. Лечение: копейки целыми числами и `Math.round` в одном месте.

**5. Тихая ошибка: граница порога.** Знак `>` вместо `>=` не вызывает ни одной ошибки в консоли. Находится только тестом на ровно 3 000 рублей.

**6. Тихая ошибка: мутация корзины.** Если расчёт правит цены в корзине, первый расчёт верный, а второй применит скидку повторно. Расчёт должен только читать.

## Итог

Что вы теперь умеете:

- превращать ТЗ в список правил и в приёмочные тесты;
- делить проект на модули по смыслу и держать зависимости в одну сторону;
- считать деньги целыми копейками и фиксировать правило округления;
- добавлять новое правило посреди работы, не ломая принятое;
- собирать и защищать расчёт: понятные ошибки, граничные случаи, никаких мутаций.

Первый модуль закончен. Вы знаете основы JavaScript и умеете собирать из них работающие небольшие программы. Но программа без интерфейса пока видна только в консоли. В модуле 2 «HTML и CSS» (готовится) мы займёмся тем, что видит покупатель: разметкой страниц, стилями и вёрсткой, а потом вернёмся к JavaScript в браузере.
