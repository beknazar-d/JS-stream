## Зачем это в работе

Тикет от команды витрины. Нужно показать в каталоге только товары в наличии, дешевле 2000 рублей, и подписать каждый ценой. Ещё нужно найти заказ по номеру и узнать, есть ли среди заказов отменённые.

Разработчик написал пять циклов `for` с пятью пустыми массивами и пятью `push`. В одном месте забыли `push`, в другом перепутали переменные. Код вырос втрое, а ошибки искали полдня.

Для таких задач в массивах есть готовые методы. Они делают то же самое, что цикл, но название метода сразу говорит, что происходит: «преобразовать», «отобрать», «найти». В этом уроке пять самых частых: `map`, `filter`, `find`, `some` и `every`.

```js
const prices = [1200, 300, 4500];
console.log(prices.filter((price) => price > 1000));
```

```text
[1200, 4500]
```

## Объяснение

Все пять методов работают одинаково: вы передаёте им функцию, а метод сам вызывает её для каждого элемента. Функцию, которую передают в другую функцию, называют колбэком (callback, «функция обратного вызова»). Вы уже умеете писать стрелочные функции, так что здесь ничего нового: просто стрелочная функция становится аргументом.

Аналогия: конвейер на складе. Коробки едут по ленте, а рядом стоит работник с одной инструкцией. Инструкция одна, а применяют её к каждой коробке по очереди. Вы пишете инструкцию. Лента едет сама.

Что делает каждый метод:

- `map(колбэк)` превращает каждый элемент в новое значение и возвращает массив из таких значений. Длина результата та же, что у исходного массива.
- `filter(колбэк)` оставляет только те элементы, для которых колбэк вернул истину. Возвращает новый массив, он может быть короче, а может быть пустым.
- `find(колбэк)` возвращает первый подходящий элемент. Если ни один не подошёл, возвращает `undefined`.
- `findIndex(колбэк)` делает то же, но возвращает индекс, а если ничего нет, то `-1`.
- `some(колбэк)` отвечает `true`, если подошёл хотя бы один элемент.
- `every(колбэк)` отвечает `true`, если подошли все элементы.

Главное свойство первых двух: они не меняют исходный массив, а создают новый. В уроке про массивы вы видели, как опасны методы, меняющие массив на месте. Здесь опасности нет.

Колбэк получает элемент первым аргументом. Вторым приходит индекс, но он нужен редко. Для `filter` колбэк возвращает условие, для `map` — новое значение.

## Пример

Теперь методы, которые возвращают не массив, а один ответ.

<Playground example="find-some-every" />

Обратите внимание на три вещи.

1. `find` возвращает сам заказ, а не массив из одного заказа. Если заказа нет, придёт `undefined`, и обращаться к его полям нельзя.
2. На пустом массиве `some` даёт `false` (подходящих нет), а `every` даёт `true` (нарушителей нет). Это логично, но неожиданно.
3. Для проверки «есть ли такой заказ» используйте `some`, а не `filter`. Результат `filter` — массив, а любой массив, даже пустой, считается истинным.

<Wrong>

```js
if (orders.filter((order) => order.status === "cancelled")) {
  // всегда выполняется: пустой массив тоже истина
}
```

</Wrong>

<Right>

```js
if (orders.some((order) => order.status === "cancelled")) {
  // выполняется, только если отменённый заказ есть
}
```

</Right>

## Как это работает

Методы можно соединять в цепочку (chain). Результат одного метода передаётся следующему, потому что `map` и `filter` возвращают массив, а у массива снова есть эти методы.

<Figure src="pipeline.svg" alt="Схема из трёх рядов. Верхний ряд: исходный массив цен 1200, 300, 4500, 800. Средний ряд: после filter с условием цена больше 1000 остались 1200 и 4500. Нижний ряд: после map с умножением на 0,9 получились 1080 и 4050. Стрелки идут сверху вниз, исходный массив не меняется." caption="Каждый шаг цепочки получает новый массив от предыдущего шага. Исходный массив остаётся прежним." />

Запустите цепочку и посмотрите, как товары отбираются, а потом превращаются в подписи.

<Playground example="chain" />

Порядок в цепочке важен. Сначала `filter`, потом `map`: так `map` не тратит время на то, что всё равно отбросят. И сначала нужно отобрать, а потом превращать в строки, иначе в `filter` придётся разбирать подписи.

Правила для колбэков:

1. В `map` колбэк обязан вернуть значение. Для стрелочной функции без фигурных скобок `return` пишется сам. Если открыли скобки `{ }`, `return` нужен явно.
2. В `filter` и `find` колбэк возвращает условие. Результат приводится к истине или лжи.
3. Колбэк не должен менять исходные данные. Он только смотрит на элемент и возвращает ответ.

<Note>

Метод `find` ищет первый подходящий и сразу останавливается. Метод `filter` проходит весь массив. Если нужен один заказ по номеру, берите `find`: он быстрее и возвращает сам заказ, а не массив из одного заказа.

</Note>

## Типичные ошибки

Все сообщения ниже получены запуском в Node.js 22. Браузер на движке V8 (Chrome, Edge) пишет их так же.

**1. Вместо массива пришёл объект.**

<Wrong>

```js
const orders = { id: "A-101" };
orders.filter((order) => order.id);
```

</Wrong>

```text
TypeError: orders.filter is not a function
```

У объекта нет метода `filter`. Так бывает, когда сервер вернул не список, а объект, или когда переменная содержит одиночный заказ. Проверьте, что лежит в переменной.

**2. Забыли передать колбэк.**

<Wrong>

```js
const prices = [1200, 300];
prices.map();
```

</Wrong>

```text
TypeError: undefined is not a function
```

Метод хотел вызвать колбэк, а колбэка нет. Если вы передали не функцию, а строку, сообщение будет похожим: `TypeError: string "abc" is not a function`.

**3. `find` ничего не нашёл, а результат используют.**

<Wrong>

```js
const orders = [{ id: "A-101", status: "paid" }];
const order = orders.find((item) => item.id === "A-999");
console.log(order.status);
```

</Wrong>

```text
TypeError: Cannot read properties of undefined (reading 'status')
```

Результат поиска нужно проверить до использования: `if (order === undefined)` или `order?.status`.

**4. Тихая ошибка: забыли `return` в `map`.** Сообщения нет, в результате пустота.

<Wrong>

```js
const upper = ["кепка", "шарф"].map((name) => {
  name.toUpperCase();
});
console.log(upper);
```

</Wrong>

```text
[undefined, undefined]
```

Фигурные скобки превратили колбэк в обычную функцию, а `return` в ней нет. Функция без `return` возвращает `undefined`.

<Right>

```js
const upper = ["кепка", "шарф"].map((name) => name.toUpperCase());
// ["КЕПКА", "ШАРФ"]
```

</Right>

**5. Тихая ошибка: массив как условие.** Условие `if (orders.filter(...))` истинно всегда, даже для пустого результата. В примере выше мы сравнили его с `some`. Когда нужно «есть ли хоть один», берите `some`.

## Итог

Что вы теперь умеете:

- превращать каждый элемент через `map` и отбирать элементы через `filter`;
- искать один элемент через `find` и `findIndex` и помнить про `undefined` и `-1`;
- отвечать на вопросы «есть ли хотя бы один» и «подходят ли все» через `some` и `every`;
- соединять методы в цепочку и не менять исходный массив;
- писать колбэк с `return`, если вы открыли фигурные скобки.

Методы из этого урока возвращают массивы или один элемент. А как получить итог по всему списку — сумму корзины, количество заказов по статусам? Для этого нужен метод `reduce`. В следующем уроке мы разберём его, а заодно научимся сортировать списки и группировать заказы.
