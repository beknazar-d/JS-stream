## Зачем это в работе

Пришёл тикет от интернет-магазина. Покупатель положил в корзину 12 штук и нажал «добавить ещё 3». Ожидали 15. На экране показалось `123`.

Другой покупатель стёр число из поля и нажал «пересчитать». На экране показалось `NaN`.

Код не падал. Консоль молчала. Просто количество пришло из формы строкой, и JavaScript обработал строку не так, как ждал разработчик.

Этот урок про то, что такое значения и типы, как язык сам превращает одни в другие и как делать это осознанно. Функции мы подробно разберём позже в этом модуле. Пока достаточно знать: функция получает значение и возвращает результат.

```js
const quantityFromForm = "12";
console.log(quantityFromForm + 3);
```

```text
123
```

## Объяснение

Значение (value) — это любые данные в программе: число, слово, ответ «да» или «нет». У каждого значения есть тип (type). Тип говорит языку, что можно делать с этим значением.

Представьте склад. На каждой коробке висит ярлык. Внутри один и тот же товар, но ярлык решает, как с коробкой обращаться. Число `42` и строка `"42"` выглядят похоже, но ярлыки у них разные. Поэтому и ведут себя они по-разному.

Пять типов, которые нужны сейчас:

- Число (number): `42`, `3.14`, `-7`. Целые и дробные числа — один тип.
- Строка (string): текст в кавычках, например `"42"` или `"Москва"`.
- Логическое значение (boolean): только `true` (истина) или `false` (ложь).
- `undefined`: значения нет, его никто не положил. Так выглядит переменная, которой ничего не присвоили. На складе: коробки нет.
- `null`: пусто, и это сделано намеренно. На складе: коробка есть, а внутри ничего.

Есть ещё особое число `NaN` (Not a Number, «не число»). Оно появляется, когда превратить значение в число не получилось. По типу `NaN` всё равно число.

Чтобы узнать тип, используют оператор `typeof`. Он возвращает название типа строкой.

<Playground example="typeof-table" />

Заметьте две странности. `typeof null` даёт `"object"`: это историческая особенность языка, `null` не объект. И `typeof NaN` даёт `"number"`.

Превращение значения из одного типа в другой называется преобразованием типов (type conversion). Оно бывает двух видов:

- неявное (implicit): язык делает его сам, вы об этом не просили;
- явное (explicit): вы сами вызываете `Number()` или `String()`.

Баги в корзине рождаются из неявных преобразований. Дальше мы посмотрим, как они работают.

## Пример

Вот тикет из начала урока в виде кода. Запустите его, потом поменяйте `"12"` на `"abc"` и посмотрите, что изменилось.

<Playground example="cart-bug" />

Что произошло. Оператор `+` умеет два дела: складывать числа и склеивать строки. Если хотя бы одна сторона — строка, он склеивает. Число `3` превратилось в `"3"`, и получилось `"12" + "3"`, то есть `"123"`.

Правило: данные из формы всегда строки. Сначала превращаем их в числа через `Number()`, потом считаем.

<Wrong>

```js
const total = quantityFromForm + added; // "123"
```

</Wrong>

<Right>

```js
const total = Number(quantityFromForm) + added; // 15
```

</Right>

## Как это работает

У `+` особое правило, у остальных арифметических операторов другое. Посмотрите на схему.

<Figure src="plus-vs-star.svg" alt="Две колонки. Слева: выражение «2» + 1, число 1 становится строкой «1», результат — строка «21». Справа: выражение «2» * 3, строка «2» становится числом 2, результат — число 6." caption="Плюс склеивает, если рядом есть строка. Умножение, вычитание и деление всегда считают числа." />

Из схемы следуют четыре правила.

1. Оператор `+`: если есть строка, значения склеиваются в строку. Иначе складываются числа. Поэтому `1 + 2 + "3"` даёт `"33"`: сначала `1 + 2` равно 3, потом `3 + "3"` склеивается. А `"1" + 2 + 3` даёт `"123"`.
2. Операторы `-`, `*`, `/`: всегда числа. Строка `"5"` в выражении `"5" - 2` превращается в число 5.
3. `Number(текст)` превращает строку в число. Пробелы по краям отбрасываются. Пустая строка и строка из пробелов дают `0`. Если в строке есть что-то кроме числа, например `"12 шт"` или `"1,5"` с запятой, результат — `NaN`.
4. `NaN` заразен: любая арифметика с ним снова даёт `NaN`. Он единственное значение, не равное самому себе: `NaN === NaN` даёт `false`. Поэтому проверять его нужно так: `Number.isNaN(value)`.

Теперь про сравнение. Оператор `==` перед сравнением приводит типы, и результаты бывают неожиданными. Оператор `===` типы не приводит: значения равны, только если совпадают и значение, и тип. В работе используйте `===`.

<Playground example="conversions" />

<Note>

Не путайте `Number.isNaN` с глобальной функцией `isNaN`. Глобальная сначала превращает значение в число: `isNaN("abc")` даёт `true`, хотя `"abc"` — строка. А `Number.isNaN("abc")` даёт `false`: строка не есть `NaN`. Для проверки результата `Number()` годятся оба варианта, но `Number.isNaN` не делает лишнего.

</Note>

Ещё несколько превращений, которые полезно помнить: `Number(true)` даёт 1, `Number(null)` даёт 0, `Number(undefined)` даёт `NaN`. `Number(null)` и `Number(undefined)` дают разное, и это частая ловушка: «пусто» становится нулём, а «значения нет» становится `NaN`.

## Типичные ошибки

Все сообщения ниже получены запуском в Node.js 22. Браузер на движке V8 (Chrome, Edge) пишет их так же.

**1. Метод числа вызвали у строки.**

<Wrong>

```js
const quantity = "3";
console.log(quantity.toFixed(2));
```

</Wrong>

```text
TypeError: quantity.toFixed is not a function
```

Метод `toFixed` есть у чисел, а у строк нет. Сообщение говорит: «`quantity.toFixed` — не функция». Первым делом проверьте `typeof quantity`.

<Right>

```js
const quantity = "3";
console.log(Number(quantity).toFixed(2)); // "3.00"
```

</Right>

**2. Значения нет вообще.**

<Wrong>

```js
let quantity;
console.log(quantity.toFixed(2));
```

</Wrong>

```text
TypeError: Cannot read properties of undefined (reading 'toFixed')
```

Переменная ничего не хранит, поэтому у неё нет методов. Сообщение называет и значение (`undefined`), и то, что вы пытались прочитать (`'toFixed'`). Ищите, почему переменная осталась пустой.

**3. Значение пусто намеренно, но к нему обратились.**

<Wrong>

```js
const note = null;
console.log(note.trim());
```

</Wrong>

```text
TypeError: Cannot read properties of null (reading 'trim')
```

То же самое, только вместо `undefined` здесь `null`. Перед вызовом метода проверьте, что значение не пусто.

**4. Тихий NaN.** Самая опасная ошибка: сообщения нет вообще.

<Wrong>

```js
console.log("Итого:", Number("12 шт") * 5);
```

</Wrong>

```text
Итого: NaN
```

Консоль не ругается, `NaN` спокойно доезжает до экрана покупателя. Защита одна: сразу после `Number()` проверить результат через `Number.isNaN` и решить, что делать с некорректным вводом.

<Right>

```js
const quantity = Number("12 шт");
if (Number.isNaN(quantity)) {
  console.log("Введите количество числом");
}
```

</Right>
