# Разбор

Задача делится на два шага: сначала проверить вход, потом считать. Пока вход не проверен, считать нельзя: любая арифметика с `NaN` даёт `NaN`.

**Проверка входа.**

- `price`: `Number(form.price)`. Пустая строка и строка из пробелов дают `0`, и их отсеивает условие `price <= 0`. Текст и запись с запятой дают `NaN`, `Number.isFinite` отсеивает `NaN` и бесконечность одним условием.
- `quantity`: `Number.isInteger` отсекает `NaN` и дроби, а `quantity < 1` отсекает ноль и минус. Пустое поле даёт `0` и тоже отсеивается.
- `discountPercent`: пустое значение нужно обработать до `Number()`, иначе неясно, `0` пришёл от пользователя или от пустого поля. Поэтому поле сначала превращается в строку, обрезается, и пустой результат означает «скидки нет». Затем проверяется диапазон от 0 до 100.

**Расчёт.** Деньги считаем в копейках. `19.99 * 100` даёт `1998.9999999999998`, поэтому цену переводим в копейки через `Math.round(price * 100)`. После этого все числа целые: цена в копейках, количество и `100 - discount`. Итог делим на 100 и округляем один раз в конце. Округление только в конце не накапливает ошибку.

Результат — целое число или `null`. `NaN` наружу не выходит, потому что все ветки с `NaN` закрыты проверками до расчёта.
