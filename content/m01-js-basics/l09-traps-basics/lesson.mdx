## Зачем это в работе

Пятница, ревью кода. За неделю в магазине нашли пять багов. В консоли у всех чисто, ошибок нет, тесты зелёные. Но:

- купон «0%» почему-то даёт скидку 5%;
- цена в корзине выглядит как «1002» вместо 12;
- сумма строки заказа показывает `undefined`;
- сравнение количества на складе считает, что «10» меньше «9»;
- кто-то проверяет `NaN` через `===`, и проверка никогда не срабатывает.

Это не редкие случаи. Это короткий список мест, где JavaScript делает не то, что подсказывает глаз. Вы уже встречали их в уроках 1.1–1.8. Этот урок — разбор: мы соберём ловушки вместе, научимся замечать их при чтении кода и лечить.

В уроке мало нового. Он про внимание. Почти все задания здесь — «предскажи результат» и «найди ошибку». Это главные навыки на ревью.

## Объяснение

Ловушка (trap) — это место, где код выглядит правильным, запускается без ошибки, но даёт неожиданный результат. Самые неприятные ловушки молчат: нет ни сообщения, ни красного текста.

Представьте дороги в незнакомом городе. Большинство перекрёстков простые. Но есть несколько опасных, где все ошибаются. Если вы знаете их заранее, то проезжаете спокойно. Урок — это карта таких перекрёстков.

Восемь ловушек делятся на три группы.

Типы и сравнения:

1. `==` приводит типы, поэтому `0 == ""` даёт `true`. Лекарство — всегда `===`.
2. `+` со строкой склеивает, а не складывает: `"5" + 3` даёт `"53"`. Лекарство — `Number()` до вычислений.
3. `NaN` не равен даже самому себе, поэтому `x === NaN` всегда `false`. Лекарство — `Number.isNaN(x)`.
4. Оператор `||` заменяет любое ложное значение: `0`, `""`, `NaN`. Оператор `??` заменяет только `null` и `undefined`. Для данных формы, где `0` — настоящее значение, нужен `??`.

Области видимости:

5. Затенение: переменная с тем же именем во внутренней области закрывает внешнюю.
6. Временная мёртвая зона (TDZ, temporal dead zone): переменную `let` или `const` нельзя читать до строки с объявлением, даже если снаружи есть другая с таким именем.

Возврат значения:

7. `return` с переносом строки: язык сам ставит точку с запятой, функция возвращает `undefined`.
8. Стрелка с фигурными скобками без `return`: результат потерян.

Седьмая ловушка связана с тем, как JavaScript читает код. Если строка может закончиться, он иногда считает, что она закончилась. Эту автоматическую вставку точки с запятой называют ASI (automatic semicolon insertion). Нам важно знать одно правило: после слова `return` значение пишут на той же строке.

## Как это работает

Все восемь ловушек на одной картинке.

<Figure src="traps-map.svg" alt="Таблица из восьми строк и трёх колонок: выражение, что получим, чем заменить. Строка плюс число даёт склейку, заменить на Number. Ноль и пустая строка при двойном равно дают true, заменить на тройное равно. NaN не равен NaN, заменить на Number.isNaN. Оператор или теряет ноль, заменить на двойной вопросительный знак. Строки «10» и «9» сравниваются как текст. Return с переносом и стрелка с фигурными скобками дают undefined. Внутренняя переменная закрывает внешнюю." caption="Карта ловушек. Слева выражение, посередине то, что получится, справа лекарство." />

Теперь объясним то, чего нет в примерах: TDZ и ASI.

**TDZ.** Переменные `let` и `const` существуют во всей своей области с самого начала, но пока выполнение не дошло до строки с объявлением, читать их нельзя. Этот промежуток называют временной мёртвой зоной. Если читаете раньше, получите `ReferenceError`. А если снаружи есть переменная с таким же именем, она не поможет: внутренняя уже закрыла внешнюю на всю область, включая строки выше своего объявления.

**ASI.** Когда после `return` стоит перенос строки, JavaScript считает, что `return` закончен, и сам вставляет `;`. Код на следующей строке превращается в отдельное выражение, которое никогда не выполнится.

Для чтения кода на ревью полезен такой порядок вопросов.

1. Это сравнение: что с типами? Тройное равно или двойное?
2. Это плюс: есть ли рядом строка?
3. Это число из формы: может ли оно быть `NaN`, `0` или пустой строкой?
4. Это запасное значение: должен ли ноль считаться «пустым»? Если нет, нужен `??`.
5. Это переменная: откуда она? Нет ли такой же снаружи?
6. Это функция: где её `return`, и стоит ли значение на той же строке?

<Note>

Эти вопросы не заменяют тестов. Но они помогают заметить ловушку до запуска, а не после жалобы покупателя.

</Note>

## Типичные ошибки

Все сообщения ниже получены запуском в Node.js 22. Браузер на движке V8 пишет их так же. Первые четыре ошибки шумные: язык сам сообщает о проблеме. Ловушки из карты выше в основном молчат.

**1. Чтение до объявления (TDZ).**

<Wrong>

```js
console.log(price);
let price = 10;
```

</Wrong>

```text
ReferenceError: Cannot access 'price' before initialization
```

Читайте сообщение буквально: к `price` обратились раньше, чем она была создана. Перенесите объявление выше.

**2. Стрелка вызвана раньше, чем объявлена.**

<Wrong>

```js
console.log(vat(100));
const vat = (price) => price * 1.2;
```

</Wrong>

```text
ReferenceError: Cannot access 'vat' before initialization
```

Та же причина. Заметьте различие: обычную функцию через `function` можно вызвать выше по файлу, и она сработает. Функция, записанная как `const` со стрелкой, до своей строки недоступна.

**3. Переменная объявлена дважды.**

<Wrong>

```js
let total = 1;
let total = 2;
```

</Wrong>

```text
SyntaxError: Identifier 'total' has already been declared
```

В одной области имя можно объявить один раз. Второй раз присваивайте без `let`.

**4. Изменение константы.**

<Wrong>

```js
const rate = 0.2;
rate = 0.3;
```

</Wrong>

```text
TypeError: Assignment to constant variable.
```

Если значение должно меняться, объявите его через `let`.

**5. Молчащие ловушки.** Сообщения нет вовсе. Результат неверный, а консоль чистая:

```text
"5" + 3        → "53"
0 == ""        → true
NaN === NaN    → false
0 || 10        → 10
"10" < "9"     → true
return + перенос → undefined
```

Единственная защита — привычка проверять эти места при чтении кода и писать тесты на границы: ноль, пустая строка, `NaN`.

## Итог

Что вы теперь умеете:

- выбирать `===` вместо `==` и объяснять почему;
- не склеивать числа из формы со строками и проверять `NaN` через `Number.isNaN`;
- выбирать `??`, когда ноль и пустая строка — настоящие значения;
- замечать затенение и TDZ;
- видеть `return` с переносом и стрелку без `return`.

Мы закончили основы: значения, операторы, условия, циклы, функции и области видимости. До сих пор данных было мало: одно число, одна строка. Но в корзине десятки товаров, в складе сотни позиций. Хранить каждую в отдельной переменной нельзя. В следующем уроке мы познакомимся с массивами: списками значений, по которым можно ходить циклом, добавлять и удалять элементы.
