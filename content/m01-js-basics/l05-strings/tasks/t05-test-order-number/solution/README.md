# Разбор

Тесты должны ловить типичные ошибки работы со строками:

1. **Нули слева.** Тест на короткий номер `formatOrderNumber(7, 2024)` ловит потерянный `padStart`. Тест на четырёхзначный номер этого не замечает: нули ему не нужны.
2. **Длинные номера.** `padStart` не обрезает, но кто-то может «для порядка» подрезать результат. Только номер длиннее четырёх цифр (`12345`) выявляет такую ошибку.
3. **Тип результата.** `parseOrderNumber` должна возвращать число. Сравнение `toBe(42)` строгое, поэтому строка `"0042"` его не пройдёт. Если сравнивать с `"0042"`, ошибки не заметить.

Тесты проверяют результат, а не устройство, поэтому переживут переписывание функций.
