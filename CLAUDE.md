# CLAUDE.md — открытая платформа обучения JS, TS, Node.js, CSS, React

Этот файл читается в начале каждой сессии. Полное ТЗ: документ «ТЗ: открытая платформа обучения JS, TS, Node.js и CSS (до уровня Middle)». Если что-то здесь противоречит ТЗ, спроси, а не угадывай.

## Цель проекта

Бесплатный открытый сайт на русском языке. Человек знает основы HTML и немного кода. За курс он доходит до уровня Middle в JavaScript, TypeScript, Node.js и CSS, затем изучает React, Redux Toolkit и MobX. Каждая тема закрепляется заданиями, похожими на реальную работу.

Результат курса — «Middle-ready»: знания и портфолио уровня Middle, но не рабочий стаж. Это честно сказано на главной странице.

## Жёсткие ограничения

- Всё бесплатно: курс, хостинг (бесплатный тариф статического хостинга), домен (бесплатный поддомен), CI. Не добавлять платные сервисы и зависимости.
- Без регистрации и аккаунтов. Весь контент открыт сразу, без закрытых уровней.
- Без бэкенда: сайт статический, всё исполняется в браузере пользователя.
- Язык контента: русский. Английские термины даются в скобках при первом употреблении.
- Прогресс хранится в IndexedDB и переносится экспортом и импортом файла.
- Нет аналитики с cookies и персональных данных.

## Стек

- Сайт: React, TypeScript, Vite.
- Контент: MDX в репозитории. У каждого задания своя папка.
- Редактор: Monaco Editor.
- JS и TS задания: компилятор TypeScript и раннер тестов в Web Worker, API тестов в стиле Vitest/Jest.
- HTML и CSS задания: iframe с `sandbox`, DOM-тесты, сравнение скриншотов с допуском.
- Node.js задания: WebContainer API (бесплатен для некоммерческого и open source использования). Обязателен резервный локальный режим: шаблон проекта и `npm test` с теми же тестами.
- Хостинг: статический хостинг с возможностью задавать HTTP-заголовки (нужны для изоляции источника, `SharedArrayBuffer`). Примеры: Cloudflare Pages, Netlify.
- Версии Node.js, TypeScript, React, Redux Toolkit, MobX закреплены (`.nvmrc`, `package.json` без `^`). Любое обновление версии делается отдельным коммитом с прогоном всех эталонов.

```
  ...

```

## Формат урока (всегда один и тот же)

1. Зачем это в работе (короткая рабочая ситуация).
2. Объяснение простыми словами, одна аналогия.
3. Минимальный живой пример.
4. Как это работает внутри (схема, анимация, пошаговый визуализатор).
5. Типичные ошибки с реальными сообщениями консоли.
6. Шпаргалка синтаксиса (попадает в карточки повторения).
7. Задания: не меньше шести (3 разминки, 2 основных, 1 реальная).
8. Итог и мостик к следующему уроку.

Правила подачи: один урок — одна идея; термин объясняется до использования; сначала пример, потом правило; неправильный вариант показывается рядом с правильным; предложения короткие.

Медиа: анимации до 10 секунд, без звука, предпочтительно WebM или MP4; схемы в SVG со своим текстом; у каждой картинки описание; у каждой анимации пауза. Чужие изображения не использовать, схемы рисуются самостоятельно.

## Правила составления заданий

- Реальный контекст: заказы, склад, доставка, бронирование, поддержка, финансы, расписания. Никаких `foo` и `bar`.
- Формулировка как тикет, критерии приёмки измеримы.
- Тесты проверяют поведение, а не реализацию. Сообщения об ошибках объясняют, что ожидалось и что получено.
- Для каждого задания: три подсказки (направление, шаг, почти решение), эталон с разбором, три неверных решения, сложность 1–5, время, теги.
- Начиная с модуля 3 часть заданий содержит неясности: человек пишет вопросы и допущения до кода.
- Старые темы возвращаются в новых заданиях.
- Практика не меньше 70% времени учащегося.

Типы заданий: набрать по памяти, предсказать результат, исправить баг, реализовать по тикету, рефакторинг, вёрстка по макету, интеграция с API, типизация, код-ревью, отладка по логам, скрипт или CLI на Node, REST API по спецификации, написать тесты, мини-проект и проект.

## Контент пишется и проверяется так

Весь контент пишет Claude, команды авторов нет. Поэтому проверка автоматическая и обязательна:

1. Эталон каждого задания проходит все тесты.
2. Каждое из трёх неверных решений проваливает хотя бы один тест.
3. Примеры кода из уроков запускаются в CI.
4. Факты об API сверяются с официальной документацией (MDN, Node.js, TypeScript, React, Redux Toolkit, MobX). Если не уверен, проверь поиском, а не пиши по памяти.
5. Урок или задание, не прошедшие проверку, не публикуются.

Источники: идеи из roadmap.sh, MDN, The Odin Project, Exercism, type-challenges, Node.js Best Practices, публичных тестовых заданий. Правила:
- Берём формат и идеи, тексты и задания пишем с нуля со своими данными.
- Прямые заимствования только из источников с совместимой лицензией и с указанием автора (MDN: CC-BY-SA, атрибуция «Mozilla Contributors»).
- Каждый использованный источник записывается в `/docs/sources.md` с лицензией.

## Программа курса (кратко)

Основная часть: 0 Рабочее место, 1 Основы JS, 2 HTML и CSS, 3 JS в браузере, 4 Асинхронность и глубокий JS, 5 TypeScript, 6 Основы Node.js, 7 Backend на Node и TS, 8 Тестирование, 9 Продакшен, 10 Профессиональные навыки, 11 Выпускной проект.
Фреймворки: 12 React, 13 Redux Toolkit, 14 MobX.
Целевой срок около 75 недель при 10–12 часах в неделю (уточняется после запуска).

## Порядок работы (этапы)

1. Фундамент: каркас сайта, движок урока на MDX, редактор, раннер JS/TS в Worker, формат задания, прогресс в IndexedDB, карточки повторения. Критерий: один урок с пятью типами заданий проходится от начала до конца.
2. Пилотный модуль: модули 0–1 целиком.
3. CSS и браузер: модули 2–3.
4. Асинхронность и TypeScript: модули 4–5.
5. Node и backend: модули 6–8.
6. Продакшен и выпуск: модули 9–11.
7. Фреймворки: модули 12–14.

MVP для запуска: этапы 1–3.

Контент пишется на один модуль впереди функций платформы, которые ему нужны.

## Как работать в этом репозитории

- Перед крупной задачей составь короткий план и дождись подтверждения.
 - Если разработчик (владелец проекта) дал добро на всё, делаем, как он сказал: работаем без запросов подтверждения, сами принимаем решения по неясным местам, записываем допущения в `/docs` и сообщаем о них в итоговом отчёте. Это правило важнее правил выше о том, чтобы спрашивать и ждать подтверждения.
- Делай маленькими шагами: задача → изменение → проверка → коммит. Один коммит — одна мысль, сообщение по-русски или по-английски, но единообразно.
- Не считай задачу выполненной, пока не запущены тесты и линтер. Пиши, что именно запускал и что получил.
- Не добавляй зависимости без причины. Новая зависимость: бесплатная, поддерживаемая, совместимая с лицензиями проекта; опиши в коммите зачем.
- Не копируй чужие тексты и задания. Не вставляй чужие картинки.
- Не придумывай факты. Если не уверен в поведении API или версии, проверь документацию.
- Код пользователя исполняется только в изоляции (Worker, iframe `sandbox`, WebContainer) с лимитом времени. Никакого доступа к данным платформы.
- Доступность: клавиатура, контраст, подписи к изображениям, WCAG 2.1 AA.
- Если требования неясны или противоречат ТЗ, задай один конкретный вопрос.
